# Process Note: 写作 agent 思考强度对照评估——保持默认

Status: implemented

## Problem

#278：写作 agent 统一沿用 deepseek-flash 默认思考强度（high）。简单确认、元数据操作与复杂创作共用同一设置，可能有不必要的推理开销，但此前没有对照证据。issue 要求先在 #273–#275 的工具与上下文优化之后做有界评估，无收益或质量下降时记录结论并保留原设置。

## Decision

- 增加实验开关 `AGENT_REASONING_EFFORT`（config/agent_runtime.py）：默认不设，行为与之前完全一致；只接受模型支持的档位，拼错的值忽略（不让一个错字把请求变成 422）。设置后经 ModelSettings.reasoning 以 `reasoning_effort` 发给模型。**生产不设置。**
- 不新增按任务的自动降档：评估显示简单任务没有收益，复杂任务的收益伴随质量风险（见下）。

评估：同一合成项目（3 章），fast 模式（只走 writer，无审稿干扰），生产 DeepSeek 密钥，5 个任务 × 3 档 × 2 次 = 30 次，每次用程序核对结果（只读不改文件 / 改名后正文逐字不变 / 只替换第一处 / 续写只追加且字数在范围内 / 三处修改全部生效且其他章不动）。平均输出 token 与成本（高峰价）：

| 任务 | 默认(high) | medium | low | 程序核对 |
| --- | --- | --- | --- | --- |
| 只读问答 | 162 / 0.019 | 152 / 0.019 | 162 / 0.025 | 全部通过 |
| 改名 | 144 / 0.019 | 149 / 0.019 | 210 / 0.019 | 全部通过 |
| 小改一处 | 382 / 0.022 | 420 / 0.023 | 350 / 0.022 | 全部通过 |
| 续写约400字 | 2252 / 0.039 | 2514 / 0.041 | 972 / 0.029 | 全部通过 |
| 三处修改 | 4091 / 0.055 | 2189 / 0.037 | 1612 / 0.033 | medium 1/2 失败 |

- 简单任务输出本来就只有一两百 token，成本主要是输入；降档没有可测收益。
- 续写：low 输出约少 57%，但人工比对正文：low 两次中一次自行加入了作者没要的新情节（门内有人开口说话、光从门里渗出），默认与 medium 更克制、细节与前文一致。程序核对只能证明篇幅和范围，不能证明这类质量。
- 三处修改：medium 有一次没有全部完成；low 两次都完成，但样本太少，且省下的主要是默认档改完后的复核读取。

## Alternatives considered

- **按任务类型自动降档（例如元数据操作用 low）。** 最强理由是确定性操作不需要深度推理。未采用：实测这些任务的推理开销已经很小，降档省不下钱；还需要可靠的任务分类，额外的模型分类会抵消收益。
- **全局降到 medium 或 low。** 最强理由是复杂任务输出明显减少。未采用：观察到 medium 改漏、low 擅自加情节；按 issue 的停止条件，质量下降时不能以成本换取。
- **不留开关，只记结论。** 未采用：保留一个默认关闭、经过校验的开关，便于以后用同一套用例复评，而不必再改代码。

## Consequences

- 生产行为不变；成本优化依靠 #273–#277 的工具与上下文改动（它们在同样的实测里分别减少了重新输出和重复读取）。
- 30 次样本只能说明方向；以后若要复评，复用同一任务集并加入人工正文评审，不能只看程序核对通过率。
