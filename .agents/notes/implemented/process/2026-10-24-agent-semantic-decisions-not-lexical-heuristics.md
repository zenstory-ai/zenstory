# Agent Note: 禁止以自然语言字符串规则替代 Agent 语义判断

Status: implemented

关联：[权限、确认和交付不从展示文字推导](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md)、[路由技术故障保留任务](../bug-fix/2026-10-18-router-invalid-decision-safe-stop.md)。

## Problem

「继续」恢复路径仍用固定短句白名单跳过 router；用户明确拒绝用字符串匹配判断 Agent 意图。既有架构记录已区分自由文本与权限/交付事实，但根目录和 Agent 子目录的开发规范没有直接约束新增的语义启发式。

## Decision

- 在根目录 `AGENTS.md` 写入共享规则，并在 `CLAUDE.md` 及 Agent 子目录对应两个文件中明确引用：不得用关键词、子串/整句、正则、长度或标点规则判断自然语言中的意图、确认、澄清、续接、角色、读写范围和完成。
- 复用现有 router/model 的结构化决策合同；程序仍需验证当前请求范围、应用权限、可信状态与真实执行/产物证据。模型自报授权或完成不能替代这些核验。
- 明确有边界的语法解析不在禁令之内：JSON、固定枚举、协议标记、路径/标识符、编辑锚点、版本并发与展示处理仍可使用字符串操作，但不能借此推断自然语言意思或扩大权限。
- 本批只修改规范并静态审计，不删除现有控制分支，不改变运行逻辑，不混入现有运行时修复 PR。现有不符规则的地方仍需单独、有回归的迁移，规范落地不代表它们已修复。

## Alternatives considered

- **继续扩充「继续」、只读、改稿等词表**：实现成本低，也能快速覆盖已知说法。但不能证明自然语言覆盖，且把范围和权限依赖于措辞；用户明确不接受，不再采用。
- **禁止任何字符串操作，直接删除现有分支**：表面上最彻底，但会破坏协议解析、精确编辑与并发安全，也可能失去只读和计费保护。禁令针对语义判断，不以破坏既有保护为代价。
- **增加独立语义分类服务或每条消息额外调用一次模型**：可集中语义判断，但已有 router，默认新增会增加成本、等待与失败面。优先复用现有合同，只有具体缺口才另行评估。

## Consequences

新代码有明确禁区，后续修复不能继续用词表补丁，也不能把模型判断直接当权限事实。现存字符串分支仍是技术债；替换时需同时验证既有成功路径、读写范围、剩余阶段、真实用量与终态。仅凭本次静态审计不能推断线上误判次数或失败率。
