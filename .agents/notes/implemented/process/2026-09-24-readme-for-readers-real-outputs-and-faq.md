# Agent Note: README 面向读者、用真实产出说话，并回答读者问过的问题

Status: implemented

## Problem

同组织的 oh-story-claudecode、drama-skills、novel-to-game、video-recap-skills、oh-story-dsh 在 2026-09-16 到 09-20 之间都完成了三步 README 升级：面向读者而不是答案引擎（#432 等）、统一 masthead（本仓库 #62 已做）、用真实产出替换说明文字并回答读者问过的问题（#434、#173、#60、#92、#48）。本仓库只做了 masthead，正文仍是 2026 年上半年的产品介绍稿：「8 大能力」「商业级运营能力」「全新创作范式」一类措辞，外加一张已交付功能的路线图。

2026-09-24 用 8 个 agent 把 README 的每一条说法对照源码核对，多处与代码不符：

- 「Diff 审阅模式——AI 的修改先以差异对比呈现，确认后再应用」：Agent 在对话里的修改直接保存（`agent/tools/file_ops/edit.py`），`stream_adapter.py` 发给前端的 `file_edit_end` 从不带新旧内容，前端因此从不进入审阅；差异审阅只出现在编辑器「去AI味」和保存冲突两处。
- 「长对话自动压缩上下文」：压缩子系统已在 `ef71c02` 删除，现在只按约 6000 token 带最近的对话。
- 「8 类结构化元素」：人物关系默认关闭，时间线从不生成；「混合检索素材库」「AI 写作时自动引用素材」：混合检索只覆盖项目文件，素材库条目要手动附加或导入。
- 13 个技能的名字有 8 个写错（继续写作、开头创作、悬念设计、沉浸增强、文本润色、角色创建、大纲生成、世界观构建），分类表与 `scripts/migrate_skills.py` 不一致；「Tiptap 富文本编辑器」实为纯文本 textarea；「深色模式自动跟随系统」实为手动切换；「多格式导出」实为只有 TXT；灵感库「上下文感知、素材联动」都不存在，配图是项目工作区而不是灵感库。
- 自部署一节写「一个 Key、一条命令」，但 web 镜像构建失败、数据库不在卷里、默认要邀请码而新实例没有任何人有邀请码（这些由同日的修复 PR 处理，见 `.agents/notes/implemented/bug-fix/2026-09-24-docker-quick-start-runs.md`）。

Issues 里读者问过的三个问题——自部署怎么取消邀请码（#1）、在线版去哪拿邀请码（#63）、能不能换模型或发布到平台（#13）——README 没有一处回答。

## Decision

两份 README 按姊妹仓库的骨架重写，masthead 保留 #62 的结构，只把一句话改成读者能直接理解的描述、导航第二、三项改为「开始使用 · 看看它的输出」：

1. **这是什么**：一段话加五条加粗要点，每条都来自核对过的源码行为（对话里直接改文件、路由加四个专职 Agent 与 500 字自动送审、改动留版本、每轮上下文的内容和预算、Agent API）。
2. **工作台里有什么**：多 Agent 流程图按 `agent/graph/router.py` 的五条路径重画，附「什么时候走」表（出自路由提示词的选择规则）；13 个技能按真实名称与 `migrate_skills.py` 的分类重列，并写清三种使用方式；版本、快照与导出，素材库与灵感库，其他功能各用几条说明写清边界。截图只保留四张，按图中实际内容写说明；删掉配错的灵感库图、写着 Tiptap 的编辑器图，以及包含仓库外短剧技能的技能页图。
3. **开始使用**：在线版（邀请码从哪来、免费额度、第一条请求沿用文档里的原创示例）与自己部署（修复后的四步，可选功能的配置表和本地开发折叠进 `<details>`）。
4. **看看它的输出**：写作 Agent 收到的去 AI 味规则原文，以及一次真实运行的两节节选——从干净检出按「自己部署」的步骤起服务，用 API 建项目与文件，取文件树顺序与导出的 TXT，以及 Agent API 的接入过程。章节正文是直接写入的测试文字，这次运行不调用模型。版本比较接口的输出没有放进 README：它返回的 `unified_diff` 头部三行没有换行分隔，原样引用会误导读者。
5. **常见问题**十一条，覆盖 #1、#63、#13，以及核对中发现 README 原来说错、读者最容易误解的几点（AI 改稿不先问、长对话不压缩、素材库要手动附加、快速与高质量模式）。
6. **延伸阅读**只链接存在的页面：`zenstory.ai/docs` 的叶子页（英文版链接到同页 `#en`）与两篇站点指南；删除路线图；项目结构与技术栈按实际目录更正后折叠进「参与贡献」；末尾补上与姊妹仓库一致的「ZenStory AI 项目」表。
7. README_EN 逐段同步，顶部加 `Last synced` 注释；技能名在英文版保留中文原名并附文件 id，界面词用英文界面的实际文案。

## Alternatives considered

- **保留原来的八大能力结构，只改错的句子**。最强理由：改动小，原有章节锚点和对外链接不变。被否：错误集中在最显眼的卖点（差异审阅、上下文压缩、素材自动引用），逐句改完后章节标题本身就不成立；姊妹仓库都已换成「这是什么 → 开始使用 → 看看它的输出 → 常见问题」的顺序，读者在组织内切换仓库时找得到同样的位置。
- **重新截一套带新 logo 的截图**。最强理由：现有 20 张截图都来自 2026-04-29，界面左上角还是旧的羽毛笔 logo。被否：截图里的界面文案与当前 i18n 仍然一致，只有 logo 过时；要截出有内容的工作区需要登录在线版或调用模型，超出这次文档改动。
- **在「看看它的输出」里放一次真实的 AI 写作对话**。最强理由：这是读者最想看的产出。被否：需要一次付费的模型调用，dsh #48 在同样情况下也没有做；这次只放不调用模型就能真实复现的产出，并原样引用写作 Agent 的规则原文。

## Consequences

- 收益：README 里每一条功能说法都能在源码里找到对应；读者问过的邀请码、换模型、导出问题有了答案；自部署一节从干净检出照做即可登录。
- 代价：README 不再罗列「订阅体系、积分、写作连续、管理后台」等运营功能的细节，这些只在免费额度与自部署配置里出现；中文 README 行数与原来相近，但删掉了路线图。
- 未做：截图没有重拍（旧 logo 仍在）；`apps/web/docs/reference/faq.md` 等已发布文档里的过时说法（自助重置密码、回收站 30 天、AES-256 加密、@ 引用文件）没有在这次修改；`apps/server/agent/CLAUDE.md` 仍列着已删除的 `compaction.py`。

## Verification

- 起草前 8 个 agent 分领域核对原 README 的每条说法（agent、素材与灵感、技能、编辑器与文件、账户与商业、Agent API、自部署、读者入口），结论逐条带文件与行号。
- 「看看它的输出」的两节运行节选来自同日对修复后 compose 栈的实际请求，输出原样粘贴，省略处以「……」标出；「先建序章会排在最前」另在一个新项目里实测。
- 起草后用 7 个独立 agent 做对抗核对（功能事实、上手与 FAQ 事实、节选逐字、中英对照、链接与渲染、读者视角、内部一致性），报出 2 个 blocker、35 个 should_fix（各视角有重复）和 31 个 nit，全部处理。两个 blocker：初稿说每轮上下文带「上级大纲」，但文件只能挂在文件夹下，`assembler.py` 按父级取大纲的分支永远不命中；中文句末的全角句号紧贴 `http://localhost:8000/docs`，被 GitHub 当成链接的一部分，改用尖括号链接。其余主要是把提示词要求写成了保证（快速模式仍可能审稿、AI 自己更新「AI 记忆」、AI 自己挑技能）、追加指令的生效时机、英文界面的真实文件夹名（Drafts / Outlines / Concept）、邀请链接参数是 `?code=`、Docker 下可选变量要写进 `environment:` 而不是根目录 `.env`，以及管理员同样受免费额度限制。修完后第二轮 3 个 agent 复核改动，又指出本轮新写的几处：用 `create_admin.py` 给别人建账号时没说明建出来的都是管理员；项目快照「回滚前先存当前状态」说得过满（快照只记每个文件的最新版本引用，不另存正文）；单文件版本历史与顶栏项目快照的入口混在一起；「AI 记忆」其实也在约 6000 token 的资料预算里、太长会被截短。均已改正。
- 两份 README 的本地链接、页内锚点和外部链接逐个检查；经 GitHub `/markdown` 接口渲染预览。
