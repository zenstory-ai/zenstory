# 素材侧栏按需读取导航字段

## Problem

素材侧栏展开分类时只使用实体 ID、名称、标题或世界观短预览，但现有列表会读取长描述、JSON、章节映射和剧情计数。详情页仍需要这些完整字段，不能修改默认响应来节省读取。

## Decision

- 六个现有实体读取接口增加显式 `navigation=true`，默认完整行为保留。导航分支只 SELECT 侧栏使用的列，并继续执行原有素材库权益、小说归属、软删除检查和剧情旧数据归属条件。
- 角色保持首次出场排序；导航使用单独的双字段响应模型，与完整列表组成明确的响应 union，不修改原模型的必填可空字段。其他分类仅返回导航列。世界观保留原始 world_structure 单列，由前端继续按相同 JavaScript 规则截取和使用原翻译兜底。
- 前端一个类型明确的方法将六类导航响应映射为 ID/名称列表；只替换侧栏读取，保持详情、预览、导入、添加到聊天、搜索及懒加载行为。旧服务忽略新增查询参数时仍能映射完整响应。
- 先增加真实 SQL 列投影、默认详情兼容、权限及六类 UI 行为回归，再实现。合并门禁包括相关测试、静态检查、隔离浏览器验证、独立审查和 CI；共享 main 部署后的 hosted staging 验收另行记录。

## Alternatives considered

- **直接裁剪默认列表。** 接口和客户端代码最少，但详情页及外部调用依赖完整字段，无法保持兼容。
- **新增统一导航接口。** 可声明单一新响应模型，但前后端滚动版本会出现旧服务 404，需要额外能力探测或回退请求。现有读取接口的可选参数可以自然兼容旧服务，不增加请求。
- **仅在 Python 序列化前丢弃长字段。** 改动较少，但仍会从数据库加载长文本和 ORM 对象，无法减少该读取路径的内存。

## Consequences

- 减少侧栏无用数据库读取、JSON 解析和响应正文；不改变存储内容、模型、收费或用户可见布局。
- 每个列表保留一条显式导航分支；世界观当前使用字段仍原样读取，避免改变 Unicode 截取和空白显示语义。收益需要按实际负载另行测量。

## Verification

- 后端导航回归在实现前 7 失败、36 通过，覆盖响应投影及参数校验；权限、试拆和默认详情原有行为保持。
- 新增角色双响应模型的 OpenAPI 回归；数据库列检查覆盖六类 SELECT，确认不会从实体表读取其他长字段。
- 前端验证六类名称映射、旧服务完整响应、世界观 Unicode/空白/空记录、侧栏懒加载和原有预览/附加/导入身份。
