# 服务状态弱入口与精简展示

## Problem

用户审阅 PR #361 后指出，服务状态不应占用主导航，页面也需要更简洁。初版重复呈现整体状态、错误提示、服务介绍、近期时间和历史日期。全量 CI 还发现未使用的固定 `daysAgo` 翻译违反项目的相对时间数字插值约定。

关联：[初版服务状态](../feature/2026-11-07-public-agent-status.md)。

## Decision

服务范围与接口结构随后收敛为[仅展示 Agent](../simplification/2026-11-07-status-agent-only.md)；以下保留当时的设计背景。

1. 撤掉桌面和手机 PublicHeader 的服务状态入口，仅保留首页页脚的低强调文字链接。直接访问 `/status`、匿名访问与域名路由不变。
2. 首屏只显示一个总体状态/更新/刷新区域，以及两行服务当前状态和调用成功率。错误提示合并到总体状态区域；删除服务介绍与重复的最近记录时间。
3. 近 30 天记录放进默认收起的原生 details。展开后保留每项服务的历史图和可访问的选日操作，去掉重复日期范围与套层卡片。
4. 删除不使用的翻译键，包括导致 CI 失败的 `daysAgo`，不放宽原来的全局测试。后端数据、超时、过期、未知处理保持。

## Alternatives considered

- 保留主导航能增加发现率，但这是遇到异常时偶尔查看的辅助页面，不应与写作、文档、订阅竞争入口。
- 完全删除历史能进一步缩短页面，但会失去判断问题是否持续的有用信息；使用原生折叠保留按需查看。

## Verification

已先复现相对时间翻译测试失败及主导航/历史折叠回归失败，再实施修改。相关前端测试 42 项、全量 315 个测试文件（4,990 项通过、1 项跳过）及覆盖率运行通过。lint（仅两条既有警告）、tokens、i18n keys、类型检查、生产构建及 Vercel finalizer 通过。构建产物的 19 个浏览器场景通过，包括中英/深浅色/390 与 1280px、历史折叠、键盘与触摸选日、单一错误重试、过期/超时与已登录访问、首页页脚进入且主导航无入口；无 serious/critical axe 问题。截图随 PR 更新。

Argon 单独只读复核方案，主 Codex 实现和验证。采纳单一错误/重试、低强调入口、删除重复说明与默认折叠历史；暂不改为共享日期控件，保留已经可用的服务独立选日操作。API 与后端未变。仅更新 PR，不合并或部署。
