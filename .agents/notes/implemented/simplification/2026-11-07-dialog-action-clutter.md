# 精简记忆与历史版本面板的重复控件

## Problem

AI 记忆底部的「取消」与右上角关闭执行同一个操作，手机上却多占一行。历史版本的「共 X 个版本」单独占据横条，让短列表出现多余分隔。

## Decision

按作者反馈，仅删除记忆页脚的取消按钮；保留原有关闭、保存、焦点返回与冲突处理。历史版本删除总数展示，未选择版本时不渲染操作栏，选中版本后继续显示选择数量和原有对比入口。沿用 [历史面板设计](../bug-fix/2026-11-07-history-and-context-labels.md) 与 [写作约定编辑](2026-10-26-memory-current-turn-agreements.md)，本次修订其取消入口安排。

实施顺序：先运行现有记忆生命周期与版本历史测试作为基线，再删重复控件并调整依赖旧入口的测试，最后用现有浏览器用例验证关闭不保存、保存与冲突恢复、版本选择和预览返回。更新 DESIGN.md，不改变 API 或引入组件。

## Alternatives considered

把取消改成图标或把总数移入标题可以压缩布局，但仍增加重复入口或低价值信息。保留右上角关闭和按需出现的选择操作更符合这次明确的精简要求。

## Consequences

手机记忆页脚减少一行；历史列表默认直接接在标题下面。用户通过右上角关闭或 Escape 放弃本次编辑，保存和版本对比规则不变。原来点击取消的生命周期用例需改走共享关闭按钮。

## Verification

改动前后既有 89 条记忆生命周期与版本历史测试通过；依赖取消按钮的用例改走共享关闭按钮。Chromium 与 WebKit 各 10 个浏览器场景已通过，覆盖关闭不保存、键盘焦点返回、Escape、保存与冲突恢复，以及版本选择/取消、预览返回、中英、明暗和手机/桌面。焦点用例明确从键盘打开，避免把 WebKit 鼠标点击按钮不获取焦点的原生行为误判为关闭回归。TypeScript、改动文件 ESLint、CSS token、i18n 检查与 Vite build 通过。独立只读复核没有阻塞问题。所有浏览器 API 为合成数据，未调用模型或修改生产。
