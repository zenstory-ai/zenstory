# Simplification Note: 移除「下载当前文件（TXT）」入口

Status: implemented

调整 [区分「下载当前文件」与「导出整本正文」](../feature/2026-10-19-current-file-download-and-export-scope.md) 与 [导出只保留整本正文，历史面板用标准宽度](2026-11-07-export-full-text-only.md) 中关于单文件下载入口的决策。

## Problem

项目顶栏的 `⋯` 更多功能菜单和移动端菜单仍保留了「下载当前文件（TXT）」，导致页面同时存在两个下载入口（顶栏「导出整本正文（TXT）」与菜单里的「下载当前文件（TXT）」）。产品决定进一步精简 `⋯` 更多功能菜单，只保留与全站辅助相关的入口（帮助文档、问题反馈），下载统一归口到整本正文/剧本导出。

## Decision

- 移除前端「下载当前文件（TXT）」菜单项（桌面端 `⋯` 菜单和移动端菜单）及相关处理逻辑，删除 `apps/web/src/lib/currentFileDownload.ts` 及其单测。
- 移除不再使用的 `editor.json` 中英文文案键（`header.downloadFile`、`header.downloadFileSuccess`、`header.downloadFileUnsaved`）。
- 保留顶栏「导出整本正文（TXT）」/「导出整部剧本（TXT）」入口及其行为不变。
- 更新中英文用户文档与后端 Agent 共享执行协议（`apps/server/agent/prompts/base.py`）：明确整本导出合并全部已保存的 `draft` / `script` 章节，单份大纲、角色、设定或单章正文在编辑器中打开直接复制即可，不再指引作者点击已移除的菜单项。

## Alternatives considered

- **仅在 UI 隐藏菜单项，保留 `currentFileDownload.ts` 和文案键。** 最强理由：未来若恢复单文件下载，不用重写文件名清理和保存前刷新逻辑。未采用：保留无调用方的工具文件、测试和 i18n 键会持续制造维护噪音并触碰未使用 key 检查，需要时可直接从 Git 历史恢复。
- **保留单文件下载但将其移入文件树右键或编辑器底部栏。** 最强理由：让需要单份导出大纲或单章的作者仍有一键下载。未采用：当前目标是精简界面入口而非迁移入口；作者在编辑器中即可全选复制单份纯文本，不必再多维护一套下载状态与未保存提示。

## Consequences

- 收益：`⋯` 更多功能菜单更聚焦（仅帮助文档与问题反馈），导出入口唯一，减少前端状态、测试与多语言/文档/提示词维护面。
- 代价：需要单独留存某一份大纲、角色设定或单章正文到本地的作者，需在编辑器中打开文档手动复制，或导出整本正文后在本地截取所需章节。
