# Simplification: 写作约定只按本轮请求追加，统一面板编辑

## Problem

生产 a8131941 的独立合成账号复现：明确记住→人工删除 notes→同会话普通写作时模型重放旧 notes，工具再次追加成功。卡片撤销基于逐行文本而没有持久条目身份，历史回执可能删除后来同文重记内容。原决定见 [remove-memory-proposals](../../implemented/feature/2026-10-25-remove-memory-proposals.md)。

## Decision

- 展示名「写作约定 / Writing Conventions」，覆盖人物事实、出场安排、禁忌和长期要求，内部 notes 不改名、不迁移数据。
- 聊天卡保留 notes_added 实际新增内容和单个「查看并编辑」动作，删除记忆撤销专属逻辑。正文文件撤销独立保留。
- 复用现有 AI 记忆弹窗，卡片直达约定区域并聚焦文本框；普通头部入口从顶部打开。关闭/取消/保存后回到触发按钮。仅记忆结果不重复成功框，混合项目更新共享一个外框。
- 沿既有 RouterDecision 增加严格布尔 notes_append_allowed，缺省 false；当前结构化决策传入请求 ToolContext，在 notes 持久化处核验。续接不继承旧 notes 许可；parallel 与同请求续跑复用当前上下文。有尚未路由的新插话时收窄为不允许后续追加，不追溯撤销已完成调用。不增加模型调用或关键词判断；非聊天直接工具入口继续既有合同。summary、文件、任务等不扩成字段权限系统。
- 当前上下文明确 notes 值含空；历史消息不代表再次追加许可。作者保留面板人工编辑/删除和 expected_notes 冲突保护。
- 回归先证明删改后复活，再核验明确记住、再次记住、普通简介/写作、续接、并行、旧卡/入口、文件撤销与并发保护。目标工程检查和独立只读 review；真实模型只做有限记忆链和一条普通写作。桌面/手机关键状态截图与焦点、冲突、触摸可达验证。

## Alternatives considered

- 保留卡片撤销并持久化条目身份：作者可直接撤回，但需新增版本/条目生命周期，且不能解决手动删改后的历史重放；本次删除该操作并统一编辑入口。
- 仅加强提示与空值展示：改动最小、可降低误写，但模型可继续调用工具；本次同时在实际持久化处限制本轮追加。
- 删除墓碑或相似度匹配：可阻止旧条目复现，但妨碍作者明确再次记入，增加数据和语义复杂度；不用。
- 「补充设定」：适合世界观，但不能清楚涵盖禁忌、安排、行为要求。「备注」范围宽但不能体现后续持续遵守。选择「写作约定」，英文沿用设计稿 Writing Conventions，并通过角色事实、情节安排和创作边界的字段说明限定含义。

## Consequences

统一管理减少历史卡破坏后来内容的风险，本轮追加边界可独立验证。router-off 没有结构化许可时不追加聊天 notes，人工面板仍可编辑；本次不新增模型调用补齐此配置的语义。模型仍会看到历史，因此正文可引用旧对话，但不代表旧约定已重新持久化。未引入数据库迁移、依赖或其他字段 ACL。

验证：375 项后端目标回归、180 项前端回归、Web lint/token/i18n/typecheck/build 和 5 项 Chromium 窄场景通过。独立 Codex 只读复核未发现代码阻塞问题。本地隔离真实模型 4 次单发请求通过（明确记入→删空→正文保存且未复活→再次记入→人工改写→普通讨论保持），未自动重试；发布与生产合成验证凭证保存于 Git 外任务输出目录。
