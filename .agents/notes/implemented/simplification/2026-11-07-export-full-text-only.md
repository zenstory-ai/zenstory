# Agent Note: 导出只保留整本正文，历史面板用标准宽度

Status: implemented

调整 [作品名与带大纲导出](../feature/2026-10-09-export-title-and-outline.md) 的决策。

## Problem

项目导出有两个入口：整本正文和「导出大纲与正文」。后者多一个菜单项、一组按结果区分的提示文案（已含大纲、暂无大纲、未能包含）、文件名约定和接口参数，产品决定不再保留。

文件历史面板同时传了 `size="full"` 和 `max-w-[900px]`。`Modal` 的尺寸类和调用方的类都是 max-width，生效的是全宽那条，面板在宽屏上几乎占满窗口，也不符合其他弹窗使用的尺寸档。

## Decision

- 前端去掉「导出大纲与正文 / 剧本」的菜单项和手机端按钮，提示只剩一句成功文案；移除相关文案键和文件名判断。
- `GET /projects/{id}/export/drafts` 去掉 `include_outline`，文件名固定为 `{项目名}_正文.txt`。没有正文时返回 `ERR_EXPORT_NO_DRAFTS`，只有大纲的作品也一样。
- 「下载当前文件」保留：它不是整本导出的变体，是作者单独保存一份大纲或其他文件的入口，帮助文档改为指向它。
- 文件历史面板改用 `size="xl"`（800px），高度和内部布局不变。
- 来源未知的文件被拒绝删除或整份替换时，工具卡片说明文件没动、可用文件菜单或编辑器，不再显示「会换个方式继续」。

## Alternatives considered

- **只隐藏入口，保留接口参数。** 最强理由：改动最小，随时能恢复。被否：没有调用方的参数和分支仍要维护测试；需要时可从 Git 恢复。
- **连「下载当前文件」一起去掉。** 最强理由：导出只剩一个入口，最简单。被否：去掉后作者没有自助保存单份大纲的途径，也偏离这次只针对带大纲导出的范围。
- **面板保留 900px，只修类冲突。** 最强理由：差异视图更宽。被否：项目弹窗已有固定尺寸档，800px 足够放下列表和对比，不需要再多一个例外。

## Consequences

- 收益：导出只有一条路径，少一组文案和分支；历史面板与其他大弹窗同宽。
- 代价：需要大纲和正文合在一个文件的作者要分别下载后自行合并。
- 代价：部署期间打开的旧页面仍会带 `include_outline=true`，新接口忽略它，返回只含正文的文件，页面提示大纲未包含；刷新后消失。
