# 辅助历史读取只查询消费者需要的字段

## Problem

建议生成读取最近五条消息，只使用角色和正文；恢复跨轮工作集读取最近两条 assistant 消息，只使用工具记录。两个查询目前都加载整条 `ChatMessage`，包括不参与结果的思考、工具结果或界面 metadata。主会话历史已有自适应分页；辅助查询不应再把不用的字段传回进程。

## Decision

两个辅助查询使用列投影：建议读取 `role/content`，工作集读取 `tool_calls`。保留原来的归属校验、活跃会话解析、会话和角色过滤、排序、limit，以及工作集的去重和已删除文件处理。不改主历史窗口、模型输入、来源面板、编辑差异、消息存储、版本或计费。

真实 SQLite 回归先验证原实现的两处查询均返回未使用的大字段；改为投影后，六项回归覆盖最近窗口、相同时间戳、角色过滤、越权拒绝、跨会话隔离、工作集去重/删除及空或旧工具记录。相关建议、会话、历史分页与会话解析共 129 项测试通过，Ruff 通过。合成大字段样本用于比较查询载荷和 Python 分配，不将样本差异外推为账单降幅。

## Alternatives considered

- **保持 ORM 查询，使用 `load_only`。** 能沿用实体对象和既有属性访问；但消费者只需要一两个标量，直接投影更明确，也不需要保留延迟加载的实体行为。
- **进一步缩小主历史或上下文预算。** 能减少模型输入和内存，但会改变写作连续性与模型可见资料，不属于本批的行为保持范围。
- **截断发送给前端的来源或编辑全文。** 能直接减少一部分响应字节；来源面板支持阅读全文，编辑审阅需要完整基线，不能仅为压缩载荷删掉这些功能。

## Consequences

减少两处辅助读取返回的未用消息字段，查询次数和返回内容保持。消息和工具记录仍原样保存，真正需要全文的读取路径保留。总节省受字段大小和调用频率影响；不承诺模型调用费或公网 egress 同比例下降，私网数据库流量也不计为公网费用。
