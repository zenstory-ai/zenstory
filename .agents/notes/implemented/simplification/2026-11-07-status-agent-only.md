# 状态页只展示 Agent

## Problem

用户希望状态页只关注网站写作 Agent，不再将去 AI 味润色作为独立服务展示。初版按两条调用链拆分，导致总体状态还会受润色的无数据或异常影响，与新的页面范围不符。

关联：[初版数据口径](../feature/2026-11-07-public-agent-status.md)、[弱入口与精简展示](./2026-11-07-status-secondary-entry.md)。

## Decision

1. 页面标题为 Agent 状态，仅显示 Agent 近期调用状态、成功率和默认折叠的 30 天历史。沿用首页页脚弱入口。
2. 聚合仅包含 agent/router 两种来源，不包含 polish；润色失败、成功或没有调用均不影响 Agent 状态。继续排除取消、无结果、补录等既定非观测记录。
3. 尚未发布的接口直接返回单份 status、success_rate、history，移除组件列表、组件分类/总体合并与未使用的最近记录字段。前端同步删除多服务类型、排序、映射与翻译。
4. 不改实际 Agent 或润色调用链，也不修改计费、路由、发布流程。

## Alternatives considered

- 仅隐藏润色行改动更小，但总体状态仍可能被它影响，也留下只为两种服务设计的无用分组；因此从统计源头去掉。
- 将润色调用并入 Agent 能覆盖更多请求，但会改变“Agent 状态”的含义，不采用。

## Verification

先运行新的 Agent 单服务回归，旧实现 10 项失败；修改后状态页 10 项及相邻后台指标/调用账本测试合计 37 项通过。临时 PostgreSQL 14 实测润色不能影响 Agent、仅有润色时未知、Agent/router 失败切换分母、取消排除、北京跨日、保留窗口和扁平 DTO，通过后已删除测试库。

前端相关测试 44 项、站点脚本测试 22 项、lint（仅两条原有警告）、tokens、i18n keys、类型检查/生产构建及 Vercel finalizer 通过。构建产物浏览器 18 个场景通过，覆盖中英/深浅色/390与1280px、只呈现一份历史、键盘/触摸选日、错误/过期/超时、已登录访问与页脚入口；无横向溢出、页面 JS 错误或 serious/critical axe 问题。删除原来仅对多服务有意义的“部分服务无数据”浏览器场景，保留单 Agent 无数据测试。

本轮只更新 PR #361，未合并、未上线，没有真实模型或生产数据操作。
