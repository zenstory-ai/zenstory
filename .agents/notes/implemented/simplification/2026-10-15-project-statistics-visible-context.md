# Agent Note: 项目统计直接呈现进度与手写上下文

## Problem

用户看过 PR #243 前后截图后指出「更多记录是什么，UIUX 我觉得还能在优化下」。上一版移除了推断评分，但手机仍把三个概览纵向堆叠，桌面底部则是三个同权、无内容预览的折叠盒。「更多记录」还混合手写连续天数与 AI 消息/会话遥测，读者无法预判入口内容。产品设计角色复看 390/1440px 截图后确认，这是信息取舍和可发现性问题，不只是命名问题。

本 note 局部替代 [上一版决策](../../implemented/simplification/2026-10-15-project-statistics-single-page.md) 的三折叠区与 AI 使用记录展示；统计口径、后端与接口约束仍有效。

## Decision

- 仅修改项目统计前端，不改后端、API、计数、类型或依赖；保留既有净字数、已写=完成+进行中、完成率=已完成/已知计划、北京时间、精确文件导航与旧字段兼容。
- 页头第一行标题和工具，项目名独占下一行，返回创作为次级按钮。字数摘要在手机上也用两列，周期选择器置于摘要底部整行，不再堆三层大数字区块；作者/AI 字数拆分常显。
- 正文进度和完成/进行中/未开始三个状态常显。仅实际文件列表折叠，入口说明作品单位和实际明细条数，不能把规划总数当文件数量；完成率仍明确标为已完成，不把已写数用于进度条。
- 删除「更多记录」入口和 AI 消息/会话、最长连续天数的 UI 展示，不删除接口字段。AI 产出已有字数拆分，消息数既不是产出也不是额度，没有必要保留一个遥测抽屉。
- 「手写活动」为次级轻量信息区：最近手写日期、当前连续天数直接可读。服务端在已中断后仍保留旧长度，因此 broken/none 展示为 0，active/at_risk 保留服务端当前长度，不按浏览器日期重算；保留真实日历日期和手写满 10 字才计天的解释；无记录显示一行空态，不造醒目空卡。只有手写字数趋势收起，继续按需加载及当前项目刷新，不改查询窗口和负值呈现。
- 桌面正文进度/手写活动为 7:5 两栏；手机顺排。使用现有 HSL、Button/IconButton 和 44px 控件，不新增组件层或图表库。

## Alternatives considered

- **仅将「更多记录」更名。** 改动小且保留全部字段，但仍需猜入口、仍混合两类数据，不能解决用户提出的 UIUX 反馈。
- **拆成「写作习惯」和「AI 使用」两张卡。** 每组名称更准确，但重新放大低价值指标、增加同权卡片，拒绝。
- **删除全部手写信息。** 最精简，但会丢失「项目最近何时手写」这一明确上下文；保留最近日期/当前连续并降低视觉权重，不保留历史最长。
- **默认展开全部列表与趋势。** 信息可发现，但长项目会把页面拉得很长、首次增加趋势请求；只让必要上下文常显、明细按需。

## Consequences

无需点开抽屉即可读到字数、正文状态及最近手写，手机首屏密度更合理。AI 消息/会话和最长连续天数不再从统计页查看，是有意的前端取舍，不影响正文/AI 字数、服务端统计或账号配额。截图仍使用同一合成项目，不能声称读取了用户私有项目。

## Verification

先改回归并在旧 UI 上确认失败，再实现。验证核心数据/状态直接可见、两类真实明细按需展开、实际条数与规划区分、AI 遥测不渲染、手写空态与日期不偏移、趋势懒加载/负数/错误/刷新。浏览器检查 390/768/1440px × 中英文 × 深浅主题、44px 控件、无横向滚动、手机首屏手写上下文与桌面两栏、axe，以及同数据新旧截图。最后运行前端完整测试、lint/token/i18n、类型和构建；独立产品/代码审查后发 PR，CI 通过再合并，不发布生产。


结果：旧 UI 上新回归 10 项先失败、4 项通过；中断连续天数的两项旧值回归也先失败。实现和修复后，完整前端 296 个文件、4665 项通过、1 项既有跳过，四种连续状态与真实 query 生命周期均覆盖。最终 Chromium/WebKit 34 项全部通过（统计中英文/深浅/390/768/1440px、既有长项目名390/1280/1920px及截图），包括 axe serious/critical 检查；390×844 的最近手写行无需滚动可见。最后再用 Chromium 1x 捕获同数据 390/1440px 两图，合成上一版/本轮对比。首次同时运行两组浏览器时共享 Vite 被拥有它的 runner 关闭、造成 connection refused；已改成单 runner 顺序完成验证，不改产品启动流程。

lint、token/i18n、TypeScript 和完整构建通过，保留既有 useAgentStream 的无效 eslint-disable 与打包体积警告。独立产品角色实际复看两张新截图并 APPROVE，独立代码审查在修复中断连续展示后 APPROVE。没有后端、类型、依赖或锁文件改动，没有读取线上私有项目或付费模型调用。本地证据位于 `.omx/evidence/project-stats-round2/`。
