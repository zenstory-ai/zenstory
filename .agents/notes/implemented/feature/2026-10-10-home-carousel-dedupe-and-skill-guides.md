# Agent Note: 首页手机展示区横滑、全站去重复、补六篇 skill 教程

Status: implemented（承接 [project-pages-toc-task-groups](2026-10-10-project-pages-toc-task-groups.md)；首页规则例外由用户 2026-10-10 批准）

## Problem

- 首页展示区在 390px 手机上五张案例卡竖排约 3300px，要滑四屏多才到创作路径。之前受 DESIGN 的“除代码与表格外不横向滚动”“不用 CSS 隐藏文字”两条规则约束，用户 2026-10-10 同意为这一区放宽。
- 用户指出页面上有重复元素。对主要页面类型统计 `<main>` 内重复链接，看得见的重复有：首页展示区第五张卡就是首屏的《西游记》案例；知识区“完整工作流”重列创作路径与案例卡已链的三篇文章；“入门”层重列想法路径第一步；DSH 与工作台两行的标题和“项目详情/工作台介绍”指向同一页。文章页顶部和文末各有一个“下一步”，出处行的 skill 与方法文件在文末“用 skill 来做”里又列一遍并附 GitHub 按钮。指南页首尾各链一次所属项目，出处行重复“来源”节的两条链接。/guides 的“入门”“改稿”层重列完整路径里的文章。各项目页“实用指南”清单里的指南全部已在“流程”问答里作为示例链出。/projects 每张卡的标题和“安装与详情”指向同一页。152 篇文章的 SEO 标题以“｜ZenStory”结尾，模板再加“ | ZenStory AI”。
- 六个 skill 没有任何文章：story-long-scan（扫榜，术语表“扫榜”也因此没有“怎么做”）、story-short-scan、story-short-analyze、novel-game-analyze、video-understanding、video-reference。用户要求补扫榜文章并多补几篇。

## Decision

- **手机横滑**：≤720px 时展示区改为 scroll-snap 横向排列，每张卡 84% 宽、下一张露出；卡片保留全部文字，统一 16:10 画框（竖屏视频叠在模糊海报上）；上方一行仅手机显示“左右滑动，查看全部 N 个演示”。展示区 3304 → 955px，/zh 10119 → 7964px。DESIGN 两条规则写入这项例外。
- **首页去重**：展示区跳过首屏那条带 chain 的案例，剩四张（桌面 6 列网格：写作演示 4 + 竖屏短剧 2，解说 3 + 3D 3）；“完整工作流”层改为链到 /guides 的四条完整路径（`workflow:<id>`，显示步数）；“入门”层把与想法路径重复的那篇换成“AI写小说提示词怎么写”；无安装步骤的工具行不再另给详情链接。测试检查知识层不重列路径里的文章、首屏案例不在展示区重复。
- **其他页面去重**：文章顶部路径条只写位置，下一步只在文末；文末只列出处行没显示的方法文件，按钮改为“安装并使用 X”；指南页文末去掉“了解 X”，出处行改为“N 个方法文件 ↓”指向本页来源节；/guides 第 1、4 层跳过完整路径已列的文章；项目页“实用指南”只列“流程”未引用的指南，全部被引用时整节不出，第 3 步改为指向“流程”；/projects 卡片第二个链接改为安装步骤或去掉。
- **标题品牌**：文章 `<title>` 先去掉 SEO 标题结尾的“｜ZenStory”，再接唯一的“ | ZenStory AI”；内容数据不改。
- **六篇新教程**：每篇依据固定提交（oh-story-claudecode `79b2970`、novel-to-game `03feee9`、video-recap-skills `5391686`）的 SKILL.md 与 references，配完整原创例，手写表格注明非 skill 原生产物；分别由六个子代理起草，逐篇人工审校（核对来源说法、虚构标注、“已发生/计划”区分），调整一处首页案例措辞（“改编目标”而非“边界”），视频理解因 `user-invocable: false` 改由 `$video-recap` 运行到简报暂停点。渲染器不支持围栏代码块，样例改为引用块中的行内代码行。六个 skill 加入测试的已核实 skill 名单与 `skill-labels.json`；扫榜术语 `how_to` 指向新文章；`llms.txt` 指南节顶部加入中英条目；批次记录 `docs/content/2026-10-10-quality-batch-19.csv`。

## Alternatives considered

- **手机展示区折叠（details）而非横滑**：最强理由是不引入横向滚动。没有采用：折叠后只看得到标题，失去“先看到真实成果”的作用；横滑保留每张卡的画面与文字。
- **保留第五张 RPG 卡**：最强理由是展示区独立完整、四种工具各有一张。没有采用：首屏就是这个案例，向下再看一次是用户指出的重复；Novel to Game 仍有 3D 原型卡，改编分支卡也用 RPG 截图。
- **删掉“流程”问答里的指南链接、保留“实用指南”清单**：最强理由是清单更好扫读。没有采用：问答链接是带示例名的内容引用，属于项目内容；清单是生成器加的重复。
- **改 152 篇文章的 seo_title 内容**：最强理由是数据本身干净。没有采用：模板去重即可，避免大范围内容改动。
- **为扫榜之外的平台选择单写一篇**：没有采用：已有“番茄和起点哪个好”“AI写的小说能签约吗”。

## Consequences

- 手机首页更短；展示区需要横向滑动才能看到后三张。首页少一张案例卡。
- 页面上同一链接/同一信息只出现一次；GEO diff 中出现大量链接减少（预期）与 152 个文章 `<title>` 变短。
- 新增 6 篇，目录 436 篇；文章 SEO 标题不再带品牌后缀。
