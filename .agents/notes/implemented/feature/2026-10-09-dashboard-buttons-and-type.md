# Agent Note: Dashboard 按钮与字体统一到一套规则

Status: implemented

关联：`DESIGN.md`「React workbench buttons and type」；新用户审计报告 2026-10-09 第 4 节（UI-1～UI-15、UI-17）与 P3-11；`feature/2026-10-09-material-free-trial.md`（素材页头「开通 Pro」的保留规则，本次只改样式层级）；`feature/2026-10-09-project-card-progress-and-word-count-refresh.md`（卡片进度行的位置）。

## Problem

审计在 1440×900 和 390×844 下实测 dashboard：
- 同一层级的页头主操作有 5 套尺寸（高 32/40/44，圆角 6/8/12/16），「开通 Pro」在素材库、订阅权益、设置里长得都不一样；并排的「开通 Pro」32px 和「兑换码」34px 底边不齐。原因是 `ui/Button`、`.btn-*` 类和手写 Tailwind 三套写法混用，`Button` 没有 44px 档，也没有图标按钮。
- 手机上页头按钮各自退化：「新建项目」只剩无名「+」，素材库「开通 Pro」只剩一个书本图标，技能页只剩两个灰图标。
- 首页「开始创作」空输入时是半透明灰，看起来像禁用，其实可点（空想法会建一个空白项目）。
- 全局规则让所有 `h1–h6` 用衬线，于是同一层级的标题有的衬线（`h*`）有的无衬线（`div`）；设置弹窗里分区标题有 4 种写法，主按钮有 5 种（含橙色渐变通栏）；「生成邀请码」在手机上折成两行。
- 筛选选中态是实心蓝，和页面主按钮抢焦点；长篇类型徽章用 `bg-white/5`，浅色主题下看不见；额度徽章绿字在浅色主题下对比度约 1.6:1；空状态说明比页面副标题还大；卡片进度行跟着简介高低浮动；手机菜单没有当前页高亮。
- 试用可用时素材页出现两个并列实心主按钮（页头「开通 Pro」和正文「免费试拆」）。

## Decision

- **按钮原语**：`ui/Button` 新增 `touch` 尺寸（44px），所有变体都带 1px 边框，并支持 ref。primary / ghost / danger 的透明边框必须写成 `border-transparent!`：`index.css` 里有一条不在 layer 里的 `* { border-color }`，在 Tailwind v4 下它会压过任何未加 `!` 的边框颜色工具类，否则这三种按钮会多出一圈灰色描边（ghost 看起来就和 secondary 一样）。页头和弹窗操作统一 `md`（40px、圆角 8、14/500、图标 16、间距 8），手机用 `touch`，保留短文字。新增 `ui/IconButton`：`label` 必填（无障碍名称 + 提示），桌面 32px、768px 以下 44px，`danger` 色调用于删除、`strong` 色调用于栏上的主控件（手机菜单开关）、`plain` 色调不带任何文字颜色（需要自定义颜色时用它，颜色只写在 className 里）；其它色调不再在 className 里叠第二个文字颜色——两个文字颜色类谁生效取决于样式表顺序而不是类名顺序。迁移了项目卡、素材卡、技能卡、API 密钥行的图标按钮、弹窗关闭按钮和手机菜单按钮。技能卡在手机上有 3～5 个 44px 操作，放在标题行会把技能名挤到 8px，所以手机上操作单独占内容下方一行（右对齐），桌面仍在标题行右侧；API 密钥行同理（三个 44px 操作在 390px 下把密钥名挤到约 48px、「活跃」竖排），手机上操作也放到下方一行。
- **页头**：我的项目「新建项目」primary；素材库有权益时「上传小说」primary，免费作者的页头「开通 Pro」改为 secondary——正文始终带着主操作（免费试拆、开通 Pro 或试用横幅里的开通 Pro），一屏不出现两个实心主按钮；技能页「导入」「技能使用统计」ghost；订阅权益「开通 Pro / 兑换码」md。手机上都保留文字。
- **首页「开始创作」**：始终是实心 primary（空想法也会建空白项目，这是真实可用的入口）；只在创建进行中禁用，并显示「正在创建项目…」。类型切换保留 44px 胶囊，选中态改为侧栏样式并加 `aria-pressed`。
- **选中态**：筛选胶囊、首页类型切换、设置 tab、手机菜单当前页统一为侧栏的「蓝 15% 底 + 蓝字」；手机菜单项加 `aria-current="page"`、44px 行高。账户菜单的主题/语言分段按钮统一 28px 高。
- **字体**：新增 `.ui-sans-headings`，挂在 dashboard 主区域、设置弹窗内容、`Modal` 内容根（弹窗通过 portal 渲染在 `<main>` 之外）和确认弹窗标题上：页面 H1 仍是衬线（`DashboardPageHeader`），h2–h6 用无衬线；控件区里出现的正文（`.prose`、`.editor-content`）标题仍是衬线。标题字体规则（全局 `h1–h6` 衬线、`.ui-sans-headings`、正文例外）都放在 `@layer base` 里，只是默认值：标题上显式写的字体（Tailwind `font-*` 工具类，或 `.heading-display`）总能生效，不会被作用域规则吃掉。灵感页卡片和分区标题按「卡片/分区标题无衬线」的规则去掉了原来的 `font-[var(--font-display)]`。分区标题 16/600；卡片标题 14/600、描述 12/400，不再随视口反向变化；设置弹窗的分区标题统一为「通用」tab 的 12/500 灰色标签；`DashboardEmptyState` 标题 16/600、说明 14/400，「我的项目」空状态改用它；技能「发现」页没有搜索或筛选时不再显示「换个关键词试试」。
- **卡片**：首页与「我的项目」共用 `dashboard/ProjectCard`，进度行和类型/时间行一起放进 `mt-auto` 页脚；在删除按钮上按回车不再同时打开项目。长篇类型徽章改用强调色浅底。
- **对比度**：新增 `--success-text / --warning-text / --error-text`，浅色主题下取更深的色值，`Badge` 的状态文字使用它们（额度徽章因此达到 AA）。
- **设置弹窗**：签到、兑换、开通、创建密钥（入口和表单里的提交/取消）、生成邀请码、退出登录都改用 `Button`（primary/secondary/ghost，桌面 md、手机 touch）；「用积分兑换 Pro」弹窗去掉紫蓝渐变确认按钮，改为同一个 primary；「生成邀请码」不换行，手机上标题在上、按钮全宽。积分 tab 的「积分余额」「每日签到」标签也改为 12/500，和同 tab 其它分区一致。
- **设置弹窗手机补漏（2026-10-10，wall-r3 `settings-390.txt` 复核）**：上一条写了「开通…桌面 md、手机 touch」，但订阅 tab 的 `SubscriptionStatus` 当时没传尺寸，390px 下「开通 Pro / 续费 Pro / 兑换码」仍是 40px，现在组件内用 `useIsMobile` 取 `touch`/`md`（与 `InviteCodeList`、`AgentApiKeysPanel` 同法），桌面仍 40px。API 密钥 tab 的复制按钮（连接指引的命令复制、密钥前缀复制、新密钥弹窗复制）原是 20×20 左右的裸按钮：768px 以下加到 44×44（与同面板 `IconButton` 的手机尺寸一致），桌面保持原来的小内边距不变，并补 `type="button"`，原有 `aria-label` 保留。邀请 tab 空状态删掉第二个实心「创建第一个邀请码」，页头「生成邀请码」是该视图唯一的主按钮，空状态说明改为先指向「点上方『生成邀请码』」，`referral.json` 删除不再使用的 `inviteCodes.createFirst`。
- **素材页试用已用完且书已删除**：免费作者删掉试用书后，空状态不再给「上传第一本小说」（上传会被拒），改为说明试用已用过，并给出唯一的实心「开通 Pro」。

## Alternatives considered

- **把全局 `h2–h6` 改成无衬线。** 最强理由：一条规则覆盖全站，不需要作用域类。被否：会同时改变隐私条款、文档页、管理后台和工作区里大量有意使用衬线的标题，超出这次 dashboard 范围，回归面太大；作用域类只覆盖审计过的控件区域，以后可以按页扩展。
- **素材页免费作者的页头不放「开通 Pro」，只留正文入口。** 最强理由：每屏只有一个「开通 Pro」。被否：数据加载时正文按钮会在「开通 Pro」和「免费试拆」之间切换，页头入口随之出现/消失会跳动；而且已有决策要求试用可用时页头保留 Pro 入口。改为 secondary 既保留常驻入口，又不和正文主按钮抢焦点。
- **空输入时禁用「开始创作」并提示「先写一句想法」。** 最强理由：引导作者先输入想法，减少空白项目。被否：空想法建空白项目是首页唯一的「新建项目」路径（我的项目页的「新建项目」也跳回这里），空状态文案也写着「想法可以先空着」；禁用会让想直接开写的作者无路可走。
- **API 密钥复制按钮直接换成 `IconButton`（2026-10-10）。** 最强理由：DESIGN 规定图标按钮统一用 `IconButton`。本次没采用：`IconButton` 桌面固定 32px，会把桌面上 text-xs 的命令行和密钥前缀行撑高，而本轮要求桌面样式不变；而且它默认的悬停底色是 `bg-tertiary`，正好等于命令行的底色，悬停反馈在那一行会看不见。所以只给原按钮加手机 44px 触控尺寸。以后如果要统一桌面尺寸，需要同时调整这些行的高度和悬停色。
- **邀请空状态的按钮降为 secondary 而不是删除。** 最强理由：空卡片里就近有操作。被否：页头按钮在手机上就在空卡片正上方、全宽，两处触发同一操作只是重复。
- **IconButton 用 `pointer: coarse` 判断触屏尺寸。** 最强理由：更准确地对应触控设备。被否：项目其它地方都以 768px 断点区分手机（`useIsMobile`、DESIGN 的 44px 规则），用同一断点行为可预测、截图可验证。

## Consequences

- 收益：同一层级的操作在各页尺寸、圆角、字重一致；手机页头按钮有文字、有名称、44px；首页主按钮状态诚实；选中态不再和主操作抢焦点；标题字体按「页面 H1 与正文衬线、控件区无衬线」一条规则走；卡片网格的进度行底部对齐。
- 代价：`Button` 所有变体多了 1px 边框（实心和 ghost 用 `border-transparent!` 保持无描边，盒子高度与 secondary 对齐；以后给这些变体加边框颜色也要带 `!`）；`Modal` 内的 h2–h6 全站改为无衬线（正文类容器除外）；`.ui-sans-headings` 是新的作用域约定，新页面要记得挂上；素材页页头「开通 Pro」从实心变为描边；工作区、聊天面板、额度弹窗内部的「开通 Pro」入口（UI-2 的其余位置）和 UI-16 的颜色语义不在本次范围。
