# 订阅页：恢复用户明确选择的最初页面

Status: implemented — 已恢复最初订阅页并验证；未部署，公告不变。

## Problem

用户否定单 Pro 销售卡和随后的一体对照表设计，并在澄清后明确选择「最初的」订阅页。原页面基线为 `a55042d7b8130df4e9fea9d9672b4d5d3da4a53a` 的 `BillingPage.tsx`，不是[商业化聚焦实现](../../implemented/feature/2026-10-17-subscription-conversion-focus.md)或[克制表格提案](../../rejected/feature/2026-10-17-subscription-calm-comparison.md)。

## Decision

- 恢复原页面的页头、当前套餐卡、可见用量卡、免费／Pro 两张对比卡、原字号与间距。删除新增销售展示组件及专属测试和无引用文案，不叠加另一套布局。
- 保留此前明确要求的兑换入口弱化：不放页头、不在正常页头副标题提示找码；只在页尾默认折叠的「帮助与支持」内提供兑换。支付明确不可用时说明真实状态和该入口位置，原深链兑换行为不变。
- 保留目录驱动的真实权益、免费每日 3 条规则、原年付默认／明确月付意图、开通与续费归因、支付可用性和既有结算流程。保留上一批修复的结算权益摘要，不恢复硬编码「不限」。
- 公告的页面、权限、存储、迁移和测试均不修改；不部署、不修改共享数据库。
- 在最小回归证明恢复前的失败后实施，验证原结构可见、兑换折叠、免费／Pro／未知状态、目录失败、支付关闭／失败和周期意图。截图采用合成账号与 mock API。

## Alternatives considered

- **继续精修新表格。** 信息密度与对照清晰，技术改动有限；但用户已明确排除，不再猜测新风格。
- **全部退回原始代码，包括页头兑换按钮。** 最接近原图，但会丢掉用户此前仍有效的“兑换码不要抢注意力”要求；只恢复布局，保留这一个明确的入口调整。
- **保留销售组件但暂不引用。** 以后切换快，但当前已被用户否定，留下无用途组件和测试容易再次误用；直接删除本次新增文件，设计历史留在原型与决策记录中。

## Consequences

恢复熟悉的账户管理布局，不再要求价格与购买按钮占满手机首屏。较长的原用量区域会让手机端方案对比在下方，这是本次明确采用的原设计。价格、权益、支付逻辑和公告不变。

最终验证：前端相关 11 文件／170 tests、Chromium mock 浏览器流程 5 tests 通过；TypeScript／构建、ESLint（0 error、3 条未修改文件中的既有 warning）、CSS token 与 i18n key 检查通过。实际页面截图位于 `.omx/design/subscription-original-restored/`，使用合成账户与模拟 API。25 个公告／后端／接线文件的 SHA-256 与上一批已验证版本一致。没有部署、下单、调用付费模型或迁移共享数据库。
