# Agent Note: 按服务端配置屏蔽特定邮箱域名注册

Status: implemented

## Problem

部分邮箱域名需要能够快速停止用于新账号。此前没有这项能力，只能改代码。屏蔽只针对新账号，这些域名上已有的账号不能受影响。具体名单属于站点运营，不写进仓库。

## Decision

- 配置：环境变量 `REGISTRATION_BLOCKED_EMAIL_DOMAINS`，逗号分隔。未设置或为空时不屏蔽；写法可以带 `@`、`*.`、前后点和大小写，无法解析的项跳过并记 WARNING。不加管理界面，改配置随部署生效。
- 匹配：用现有的 `email_validator` 解析出 ASCII 域名（含大小写和 IDNA 归一化），按标签比较，命中配置域名本身或其子域名。相似域名、本地部分里的同样文字都不会命中。
- 覆盖的入口（都在创建账号、写入地址和发信之前）：`/register`、`/registration-email`（未完成注册改地址）、`PUT /auth/me` 改成新地址、Google OAuth 的新账号分支、`/resend-verification`、`/verify-email`。守卫测试扫描代码里所有 `User(` 创建点，新增创建点会失败。
- 规则上线前已开始、尚未验证的注册：不能再发码，旧验证码也不能完成验证，因为验证才是注册完成的时刻。这些账号登录时仍是原来的「未验证」结果。
- 不影响：已验证账号的登录、Google 登录、找回密码、阅读和其他功能；不封号，不退款。资料保存时邮箱没变也不受影响。
- 答复：统一 400 `ERR_AUTH_EMAIL_DOMAIN_NOT_ALLOWED`，「暂不支持使用此邮箱注册，请更换邮箱」。注册、重发、验证都在查询账号之前判断，同一域名上账号是否存在、是否已验证都得到相同答复，不泄露账号状态。OAuth 跳回注册页显示同一文案。日志只记入口（`registration_email_domain_blocked`），不记地址。

## Alternatives considered

- **名单写在代码里并提供默认值**。最强理由：不依赖部署配置，不会漏配。否决：仓库开源，名单是运营信息，改名单不应要求发版。代价是必须在各环境配置并读回。
- **后缀字符串匹配（`endswith`）**。最强理由：实现一行。否决：`notblocked.com` 会被误伤，IDNA 变体会漏掉。
- **让已开始的注册用旧验证码完成**。最强理由：作者已经收到验证码，体验连贯。否决：这正是绕过规则的路径，受影响的只是未完成的注册。
- **屏蔽域名上的已有账号一律拒绝登录**。否决：超出范围，且会影响正常作者。

## Consequences

- 收益：新账号入口统一受控，改名单不用发版。
- 代价：配置漏设时规则静默失效，发布时必须读回；域名规则对更换邮箱服务的用户无效，只是提高成本。改用已有账号改成屏蔽地址也会被拒绝，这是有意的，否则可以先注册再改。
- 只对这些入口生效，已有账号的数据和权限不做任何清理。

## Verification

`apps/server/tests/test_api/test_registration_email_domain_denylist.py` 走真实路由，覆盖域名、大小写、子域名、相似域名、空配置、多个域名、全部入口不建号不发信、旧验证码、答复不泄露账号状态，以及已有账号的登录、读取、改资料、找回密码和 Google 登录。
