# 订阅页：方案对比前置，用量保留

## Problem

用户确认[恢复的原订阅页](2026-10-17-subscription-original-layout-restored.md)后，要求将「选一个适合你的方案」与「当前用量」交换，其余没有问题，并要求完成 deslop。

## Decision

- 阅读顺序改为页头与购买／续费 → 当前套餐 → 方案对比 → 当前用量 → 默认折叠帮助，Free／Pro 与电脑／手机一致。
- 移动完整 JSX 区块，DOM 和视觉顺序一致，不用 CSS 排序。保留已确认的字体、间距、当前套餐高亮、两张方案卡、价格权益及显式用量。
- 做有限代码清理：复用已有金额格式化函数，去掉冗余条件、单按钮重复外壳和无信息注释；公告横幅去掉多余渲染标志／非空断言，后台仅规范缩进。不提炼新组件或引入依赖。
- 保留手动兑换入口移除、旧激活深链、支付异常区分、无价格不下单、公告故障降级／本地关闭及管理员草稿恢复。后端与支付状态机不变。
- 先运行既有行为测试，再以 Free／Pro 顺序失败回归验证移动必要性；最终跑浏览器几何顺序、主题／宽度、兼容与异常回归，并更新实际截图。清理计划与独立 reviewer 分离，证据在 `.omx/verification/comparison-first-deslop/`。

## Alternatives considered

- **保持用量优先。** 更像账户仪表板，但用户最新选择是先看方案再看用量；仅调整这两个区块，不重做页面。
- **只用 CSS order 调换。** 改动少，但读屏／DOM 与视觉顺序可能不同；移动真实 JSX 更直接。
- **再做一次商业化重设计。** 可以让购买更突出，但用户已认可其他部分，不再变价格样式、配色或增加营销内容。

## Consequences

方案更早可见，用量依然完整保留，只是向下移动。手机仍按自然文档流显示，不承诺所有内容挤入首屏；不宣称转化提升。仅本地修改与验证，未部署、未改共享数据库或产生真实订单。
