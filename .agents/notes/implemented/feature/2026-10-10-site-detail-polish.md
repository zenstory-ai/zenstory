# Agent Note: 子页面细节打磨与来源标签去生硬

Status: implemented（承接 [natural-wording-design-unification-language-memory](2026-10-10-natural-wording-design-unification-language-memory.md)；用户 2026-10-10 指出搜索框间距、/projects 首屏说明、star 日期行、Agent 列表，并要求“多打磨这些细节”）

## Problem

- /guides 搜索：输入框里浏览器自带的 × 与旁边的“清空”按钮重复；“24 篇结果”紧贴输入框。
- /projects 首屏：眉标、长标题、一大段说明和对比链接叠在一起，用户认为不如直接一句“从一个灵感，到小说、短剧、游戏和视频。”；“GitHub star 数截至 2026-09-29。”多余；Agent 列表希望换成多行排列。
- 按同样标准走查其他子页面，发现：项目卡眉标重复 tagline、元信息换行；项目页 H1 带“（网文写作 skill 包）”括注在手机上单独成行，且和眉标重复；“你需要什么”里 Agent 名单是一长串顿号、安装命令在页面上出现三次；工作台页主按钮是 GitHub 而非“打开工作台”；每个项目页底部又重复一遍那段长说明；/guides 与项目页的创作路径步骤有为列表序号预留却不显示的缩进，链接带下划线，和其他列表不一致；文章表格在手机上把“第一章”挤成“第一/章”；术语表英文对照全大写、首屏下双分隔线、导语生硬；对比页大量规格式说法（自有项目选择指南、配置责任、版本化第一方来源）；项目介绍和亮点里有“本地 verifier 检查契约”“与指纹绑定的一次性确认”“家族里的浏览器成员”等。
- 文章顶部“方法来自”和文末“更多方法依据”的来源链接标签（文章 970 个、指南 195 个）大量是规格式短语：让选择与结果在场景里发生、阅读承诺与阶段交付、作者文风与事实边界、权威追踪状态与派生视图。

## Decision

- 搜索：隐藏 `::-webkit-search-cancel-button`，保留“清空”；结果行上方 12px。
- /projects：眉标“六个开源项目 · MIT”，H1 为 tagline，删除说明段和 star 日期行；Agent 名单改为三列（手机两列）网格；项目卡眉标显示形态（Agent skill 包 / 制作 skill 合集…），元信息为“N 个 skill · ✦ star 数”；对比页链接移到卡片下方一行。
- 项目页：中文括注作眉标、H1 只写名称；宿主改为可换行的小标签；去掉“你需要什么”的安装行；工作台页按钮顺序为打开工作台、文档、GitHub 源码；底部项目表去掉长说明；来源说明去掉 star 统计括注。
- 创作路径步骤在首页以外也用描边数字圆圈（与首页一致），去掉空缩进与下划线。
- 手机表格单元格内边距 9/10px、最小宽 6em，首列至少容纳三个汉字；抽查 153 页 270 张表，首列三字标签换行 0，横向溢出表格 7→6。
- 试过全站中文标题 `word-break: keep-all`：在 938 个抽样标题里有 35 个出现末行只剩一个字或标点单独成行，已放弃。
- 术语表、对比页、项目介绍按原意改成口语；测试里固定措辞的断言改成检查同一区分（如“只写小说/仅限小说写作”“自托管/自己部署是另一回事”）。
- 来源标签：三个子代理按同一份简报逐条给出改写（文章两批 368 个标签、指南与文章残留一批 141 个），人工审读后应用；统一“…与不能改的事实”“X 优先于默认写法”“目的（议程）”“作用/分工（职责）”等说法，修正了几条添加原文没有内容的改写（如“打脸舞台…层层震惊”“前中后期打法”）。链接地址不变。

## Alternatives considered

- **保留 /projects 的说明段，只缩短**：最强理由是首屏信息更完整。没有采用：用户明确要一句话；六个项目的说明就在下方卡片里。
- **保留 star 日期行以保证数字可追溯**：没有采用：用户要求删除；项目页仍写明源码核对日期，DESIGN 记录了这一例外。
- **全站中文标题 keep-all 防止词内断行**：见上，短行和孤字更难看，只对 /projects 的短语标题做不断行处理。
- **把来源标签换成文件名**：最强理由是不会生硬。没有采用：中文读者看不懂英文路径，标签需要说明这份文件讲什么。

## Consequences

- 子页面首屏更短、重复信息更少，手机上标题、表格、标签不再被挤断。
- 约 580 处来源标签措辞变化（文章 450 处、指南 125 处）；URL、日期、结构化数据类型不变。
- /projects 的 star 数没有日期，需要时以项目页源码核对日期为准。
