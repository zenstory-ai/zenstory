# 公开 AI 服务调用状态

## Problem

作者遇到 AI 写作或去 AI 味异常时，没有可匿名访问的近期服务状态页。已有模型调用账本记录成功、错误、超时及取消，但它是 provider attempt 口径，自动切换模型可能先失败再成功，不能由此声称用户整轮写作失败或连续时间可用率。

关联：[后台模型调用指标](2026-10-24-admin-model-call-metrics.md)。

## Decision

入口与页面层级已由[弱入口与精简展示](../simplification/2026-11-07-status-secondary-entry.md)调整；以下保留初版决策背景，数据契约仍有效。

公开 App `/status` 与匿名 `GET /api/status`，复用 App 设计语言与既有账本。展示 AI 写作（agent/router）和去 AI 味（polish）最近 60 分钟调用状态及北京日期的近 30 天记录。任一有效错误/超时表示该窗口出现异常调用；全成功表示近期调用正常；没有有效记录表示未知。总体有异常优先，否则有未知即未知，两项正常才正常。成功率为成功次数除以成功、错误、超时次数之和，不标成 uptime。

排除取消、无结果、补录以及未覆盖的 suggest/material；不查询对话、用户、项目或模型详情。SQL 按组件与日期聚合，只回传状态、成功率、最近观测时间和历史日期。单进程 30 秒缓存限制重复查询；生成时间之后 120 秒失效。前端每分钟刷新、支持手动重试，获取失败或数据过期时不得保持正常状态。查询失败返回 503，不伪造正常记录。无探测模型调用、数据库变更、事件后台或订阅系统。

公开导航及首页页脚提供入口，组织站同路径跳转到 App。部署脚本沿用 pricing 的 React HTML 入口生成方式，为状态页提供正确的标题、canonical、robots 和 App sitemap；不复制另一套静态页面内容，预览环境继续 noindex。

前端只读请求 10 秒超时，可手动重试。每个请求只清理自己的超时计时器，覆盖 StrictMode 和窗口重新聚焦导致的请求替换。过期后不再显示旧的正常或异常为当前状态，也隐藏当前成功率；历史仍按原日期展示。只有所有观测调用都成功才显示 100%，接近边界的值使用 `>99.9%` 或 `<0.1%`，避免四舍五入掩盖失败或成功。

## Alternatives considered

- 独立外部 uptime 探测能在主站故障时继续报告，也能确认连续可用时间，但需要新部署、任务、凭据和真实模型费用；本轮先交付已有数据支持的调用状态页，不声称具备外部监控能力。
- 直接公开后台模型统计能少写聚合代码，但会泄露模型、用量、成本，也混入作者不需要理解的后台指标，因此使用独立最小公开契约。
- 根据调用失败自动生成故障和恢复事件会更像商业 status 产品，但失败可在同一回复中恢复，没有事件起止真值；本轮只显示可核实的日记录，不编造事件时间线。

## Consequences

无需额外付费模型或基础设施，用户可看到近期调用情况与有证据的历史。账本写入是 best effort，取消也包括部分部署中断，故本页不能证明端到端写作成功率或连续可用时间。状态 API 与主站共享服务/数据库；主站不可达时页面诚实显示无法取得状态。未观测的服务和日期保持未知。

参考官方页面的信息层级与历史展示：[OpenAI Status](https://status.openai.com)、[Claude Status](https://status.claude.com)。视觉沿用 ZenStory，不复制第三方品牌。

## Verification

后端 37 项相关测试及一次临时 PostgreSQL 聚合实测通过；前端 57 项组件/接口/路由测试、85 项站点脚本测试、lint、tokens、i18n keys、类型检查和生产构建通过。lint 有两条 `useFileSearch.ts` 原有的未使用禁用注释警告。构建产物通过 17 个浏览器场景，覆盖中英、390/1280px、深浅色、键盘与触摸选日、无数据、失败重试、过期、10 秒超时和已登录访问；没有严重或关键无障碍问题。
