# 积分与邀请的用户入口默认关闭

## Problem

积分兑换 Pro 已在 [10-16](../bug-fix/2026-10-16-disable-points-pro-redemption.md) 服务端关闭，生产前端也用 `VITE_POINTS_PANEL_ENABLED=false` 隐藏了设置里的积分页。但用户菜单里的「签到领积分」没有接这个开关：10-05 后有 65 个新用户签过到，攒的积分既看不到余额也花不出去。设置里的「邀请」页和注册页的邀请码输入框也一直显示，可邀请奖励只能换积分；10-05 后的 550 个新注册里只有 1 人通过邀请来，奖励邀请也只有 1 次。用新用途重新启用积分的方案被否决（见 [积分换消息提案](../../rejected/feature/2026-10-20-points-redeem-ai-messages-and-project-slots.md)），用户要求用环境变量关闭积分和邀请，减少对作者的干扰。

## Decision

- 前端新增两个构建期开关，缺省、空值或非法值都视为关闭，写法与 `VITE_INSPIRATIONS_ENABLED` 一致：
  - `VITE_POINTS_ENABLED`：控制设置里的积分页，以及桌面端和手机端用户菜单的签到按钮；关闭时不请求签到状态。它取代原来只管积分页、默认开启的 `VITE_POINTS_PANEL_ENABLED`，旧变量不再读取。
  - `VITE_REFERRAL_ENABLED`：控制设置里的邀请页，以及注册页的邀请码输入框。
- 设置被关闭的页签（含 Dashboard 深链传入的 `points`/`referral`）时回到个人资料页。
- 注册页：邀请关闭且服务端策略为「邀请码可选」时，不显示输入框，邮箱注册和 Google 注册都不提交邀请码，URL 里的 `invite`/`code` 参数也被忽略。服务端要求邀请码时（门槛注册），输入框照常显示并提交，不受此开关影响。生产和 staging 的 `/api/auth/register-policy` 都是 `global_optional`。
- 服务端不改：签到、积分、邀请码与奖励接口照常可用，已有积分和邀请记录保留；兑换 Pro 仍由 `POINTS_PRO_REDEMPTION_ENABLED` 默认关闭。管理后台的积分、签到、邀请页面不受影响。
- Playwright 托管的前端开发服务器默认把两个开关设为 true，使现有积分与邀请 E2E 继续运行；外部复用的服务器需要相同配置。
- 文档同步：README 改为在线版注册不需要邀请码；自部署时邀请码由后台「邀请系统」生成，开启 `VITE_REFERRAL_ENABLED` 后「设置 → 邀请」也能生成。站内用户指南（中英）删去「邀请与积分」小节、积分页说明和「邀请奖励在哪里看」问答；注册步骤改为「页面显示邀请码时」再填写。

## Alternatives considered

- **沿用 `VITE_POINTS_PANEL_ENABLED`（默认开启），只把签到按钮也接上，再加一个默认开启的邀请开关**。最强理由：不改变量名，本地和 staging 行为不变，生产已经设为 false 的积分开关立即对签到生效。未采用：邀请要真正关闭，还得新改 Vercel 的生产和预览配置；新环境或漏配又会重新显示，和 10-16「关闭不应依赖额外云端操作」的结论相反。
- **服务端也加开关，关闭签到、邀请码创建与奖励接口**。最强理由：入口隐藏后，旧客户端或直接调用 API 仍能签到和创建邀请码，服务端开关才算彻底关闭。未采用：这些接口只产生无法消费的积分，没有成本或权益风险，与 10-16 的 Pro 兑换不同；加服务端开关要同时处理注册时的邀请归因、OAuth state 与既有测试，超出「减少用户干扰」的范围。以后若要下线这两个体系，再单独评估。
- **邀请关闭时仍静默提交 URL 带来的邀请码**。最强理由：已经分享出去的邀请链接还能给邀请人记奖励。未采用：邀请人看不到邀请页和积分，奖励对他不可见，静默归因只会产生不可见的数据；保持「关闭即不显示、不提交」更好解释。

## Consequences

收益：作者在设置、用户菜单和注册页不再看到无法使用的积分与邀请，部署后即生效，不需要改 Vercel 配置。

代价：
- staging（Vercel Preview）和本地开发默认也隐藏这两块，要测试时需显式设为 true。
- 以后恢复积分或邀请，需要先设置开关、再重新构建前端。
- 已经发出的邀请链接在注册时不再归因。
- 旧的 `VITE_POINTS_PANEL_ENABLED` 变量留在云端配置里不再起作用，可在以后的配置清理中删除。

## Verification

新增开关的取值回归，以及设置页签隐藏/显示与回退、用户菜单两端签到隐藏且不发状态请求、注册页「可选时隐藏且不提交 / 必填时照常提交」的回归。设置页、用户菜单、注册页（含 lifecycle）与开关测试共 70 项通过，相关文件 eslint 和前端 `tsc` 通过。积分与邀请 E2E 依赖 Playwright 开发服务器的环境变量，本地未运行，以 CI 为准。尚未部署，staging 与生产效果须在发布后核对。
