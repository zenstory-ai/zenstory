# Feature Note: 送审带上前两章，返修带上被审正文

Status: implemented

关联：[只给作者一份总结与送审证据](../bug-fix/2026-10-11-author-reply-single-summary-and-real-word-counts.md)、[按范围读取](2026-10-19-query-files-range-reads.md)。

## Problem

#275：用生产 DeepSeek 在 40 章合成合集上跑"续写第41章 → 自动送审 → 返修"并记录每个角色的工具调用：

- 送审包对长文件只附改动段和前后各 600 字；审稿提示要对照"同一文件或前两章"核对重复和事实，于是审稿人每次都再按 4000–8000 字读文件结尾（3/3）。送审包末尾的说明还写着"核对前文事实时再读取"。
- 审稿人交回返修时，审稿任务消息（含送审正文）会从历史里去掉，读取快照也按 agent 清空；返修 writer 看不到正文，为了写出逐字的 old/anchor 又读一遍结尾（2/2）。

## Decision

- 送审包（`_review_payload_block`）对放不进预算的长文件：改动之前能放下两个章节/分集时，从倒数第二个标题起附完整原文（放不下两个就一个，再放不下退回原来前后 600 字的窗口），总预算仍是 9000 字。说明改为写明"附了改动之前的 N 个章节"，其余没附上的部分"按章节读取那一段，不要整份重读"。标题识别与 query_files 的 section 共用一套规则。
- 返修交接（审稿人 → writer）按当前落库版本重新附上同一份送审片段，标为"[返修对象当前正文]"，说明可直接逐字引用作为 edit_file 的 old/anchor，要改的地方不在其中时再按范围读取。审稿任务消息照旧不回放给 writer；陈旧检查照旧以本请求写下的整份正文为快照，作者在期间改过文件仍会被拒绝。
- 独立审查保留：不跨角色收紧读取守卫，不跳过送审，不把"读过的文件 id"当作已看过正文。

## Alternatives considered

- **跨角色共享读取快照/读取计数。** 最强理由是彻底避免重读。未采用：接收角色确实没看到工具结果，把别人的读取当作自己看过会让模糊匹配和"已核对"建立在没看过的正文上；issue 也明确不能跨角色收紧读取。
- **送审包直接附全文。** 未采用：长合集会超出预算，且大部分正文与本轮改动无关。
- **只改审稿提示让它别读。** 未采用：审稿人需要前文核对事实；给它所需的前文比禁止读取更可靠。

## Consequences

- 返修 writer 不再为引用原文重读（实测 2/2 直接 edit_file，一次之后只按 section 读了第41章核对）。
- 审稿人重读减少但样本有限：改后两次可用的实测中一次没有读取、一次只读 3000 字（改前 3/3 读 4000–8000 字）；其余几次因当时上游连接超时未能完成，不计入。上线后以审稿阶段的 query_files 调用量继续观察。
- 送审包在放得下时会多附前两章原文（仍在 9000 字预算内），审稿人若仍重读，这部分是额外输入。
