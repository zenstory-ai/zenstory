# Agent Note: 每日 AI 消息用完时，聊天常驻说明卡片、发送改为打开额度墙；首页不再先建空项目

Status: implemented

## Problem

PR163 审计（`/Users/pite/audit-runs/20261009-pr163-audit/report.md`）里和额度墙有关的几条：

- **P2-5**：免费用户第 10 条发完后，输入框占位提示一打字就消失；发送键变灰，回车没有反应，没有卡片也没有弹窗，只剩页头红色 10/10 和一个 22×22 的无字星形图标。作者以为产品坏了。只有页面缓存过期、请求走到服务端 402 时才会弹出额度墙；被拦的消息还变成一条「已发出」的气泡，输入框被清空，刷新后就没了。
- **P2-6**：首页 10/10 时点「开始创作」，会先新建一个空项目（占掉免费 3 个项目名额里的 1 个），进到项目后再 402，想法丢失。
- **P2-12**：线上付款关闭（`ZPAY_ENABLED=false` 或配置不全）时，订阅权益页蓝色「开通 Pro」只弹兑换码框，旁边还有一个功能完全相同的「兑换码」；页面没说为什么不能付款。素材库的「开通 Pro」又跳回这一页。生产环境付款是开着的。
- **UI-16**：同一个 10/10，页头额度徽章是红色（error），订阅页的数字和进度条是琥珀色（warning）。

## Decision

- **聊天常驻卡片**（新组件 `ChatQuotaCard`）：`ai_conversations.used >= limit` 且 `limit > 0`（Pro 的 -1 和没有每日条数的 0 都不算用完；聊天和首页共用 `isAiMessageQuotaExhausted`）时，固定显示在输入框上方：「今天的 {{limit}} 条免费 AI 消息用完了」+「北京时间 {{day}} 00:00 恢复。写好的内容会留在输入框里，到时再发。想现在接着写，可以开通 Pro，AI 消息不限条数。」+「开通 Pro」（到订阅权益页，`source=chat_quota_blocked`）。`{{day}}` 来自 `/subscription/quota` 的 `reset_at`，按北京时间格式化成「10月10日」；缺失时写「明天」。卡片出现时记一次 `chat_quota_blocked` 的升级曝光（surface `toast`），撞墙不再只靠 QuotaBadge 兜底统计。只提每日条数，不提任何成本或第二道限制；Pro（-1）永远不显示。
- **发送与回车**：`MessageInput` 新增 `onBlockedSend`。额度用完时 `ChatPanel` 不再把发送键置灰，而是传入 `onBlockedSend`：点发送或回车打开 `UpgradePromptModal`（今天的免费 AI 消息用完了），输入框内容原样保留。占位提示缩短为「先把想法写下来，额度恢复后再发。」（原句在桌面上被截断，且和卡片重复）。
- **程序触发的发送**（首页想法自动发送、停止后的「重新发送」）在 `handleSendMessage` 入口同样拦截：把内容存成该项目的输入草稿，并打开额度墙。
- **服务端 402 兜底**：页面缓存过期、请求被服务端以 `ERR_QUOTA_AI_CONVERSATIONS_EXCEEDED` / `ERR_QUOTA_AI_DAILY_COST_EXCEEDED` 拒绝时（此时消息不会落库），把刚加上的乐观气泡移除，原文放回输入框；发出后作者已经在输入框里打了新字时不覆盖，原文放在前面、空一行接着新字（新字里已包含原文时不动）。只处理服务端尚未接受（还没收到 `session_started`）的那一条；已开始的轮次出错照旧保留气泡。额度卡片显示时，原来的内联 402 错误卡不再重复显示。
- **首页拦截**：`DashboardHome` 读取同一个额度查询（新 hook `useAiMessageQuota`）。额度用完且输入框里有想法时，「开始创作」（以及新手清单打开的建项目弹窗）不建项目，改为打开 `IdeaQuotaWallModal`：「北京时间 {{day}} 00:00 恢复。你的想法还留在输入框里，到时点「开始创作」就能接着写。想现在就写，可以开通 Pro，AI 消息不限条数。」想法保留在输入框，并按用户存到 `localStorage`（`zenstory_held_dashboard_idea:<userId>`），刷新后回填；恢复后作者再改这条想法，存的副本跟着更新，刷新不会回到旧版本；输入框清空（包括第二天成功创建后）时删除。建项目弹窗的关闭、取消和 Esc 只关弹窗、清作品名，不清首页输入框里的想法（以前会一起清掉，10/10 时等于把刚答应保留的想法删了）。没有想法时仍可建空项目（不发 AI 消息）。新手引导页本身不建项目，无需处理。
- **线上付款关闭时的订阅权益页**：付款选项明确返回 `enabled=false` 后，不再渲染只打开兑换码的「开通 Pro」；免费用户看到一行说明「暂时不能在线付款。有兑换码的话，点「兑换码」就能开通 Pro。」，「兑换码」升为主按钮并记 `redeem` 点击；副标题同步说明。付款开启时页头仍是「开通 Pro / 续费 Pro」+ 次按钮「兑换码」，行为不变。付款选项请求失败不算「关闭」（生产环境付款是开着的）：照常显示「开通 Pro」、不显示「暂时不能在线付款」，`?plan=pro` 打开付款弹窗而不是兑换码框；付款弹窗会再取一次付款选项，真的不能付款时由弹窗说明。素材库（素材页页头、介绍区、试用横幅、试用已用空状态、素材库弹窗、编辑器侧栏提示）在付款选项明确返回 `enabled=false` 时，把唯一的 Pro 入口改名「兑换码开通」并就地打开兑换码框（记 `destination=redeem`），页头下方显示「暂时不能在线付款。有兑换码的话，点「兑换码开通」就能开通 Pro。」，弹窗说明末尾追加同一句；兑换成功后订阅状态刷新，素材库直接可用。素材页只有这一个 Pro 入口，不存在订阅页那种两个按钮做同一件事的问题，所以用带动作的名字，而不是单独一个「兑换码」。付款选项还在加载或请求失败时按「未知」处理，保持「开通 Pro」跳订阅权益页（`hooks/useOnlineCheckoutKnownOff`），生产上偶发一次失败不会告诉作者不能付款。
- **颜色一致**：订阅页用量卡在 `used >= limit` 时数字和进度条用 error 色，≥80% 未用完用 warning 色，与页头徽章的 blocked / reminder_80 一致。

## Alternatives considered

- **只在点发送时弹窗、不加常驻卡片。** 最强理由：界面更干净，聊天区不多一块。被否：作者不点发送就不知道为什么灰，也看不到什么时候恢复；审计里两位盲测作者都是先看页面、再犹豫要不要点。
- **额度用完时禁用输入框。** 最强理由：最明确地表达「现在发不了」。被否：作者常会先把想法写下来，第二天再发；禁用会把这条路堵死。
- **首页照常建项目，只把想法存为项目草稿。** 最强理由：作者第二天打开项目就能直接发。被否：仍然占掉一个免费项目名额，作者也不一定还想用那个空项目；留在首页输入框里，第二天点同一个按钮即可，项目只在真正开始写时才建。
- **付款关闭时把按钮改名「兑换码开通」并保留两个按钮。** 最强理由：主按钮位置不变。被否：两个按钮做同一件事，审计已经指出这种重复让人困惑；/pricing 与错误文案也都叫它「兑换码」。

## Consequences

- 收益：撞墙时作者看得到原因、恢复时间和继续写的办法；按发送有反馈；被拦的文字不再丢；首页不会白白占掉免费项目名额；付款关闭的环境不再让「开通 Pro」看起来是坏的；同一状态同一颜色。
- 代价：额度判断依赖前端缓存（QuotaBadge 每 60 秒刷新）。缓存过期时仍可能先到服务端 402，此时由兜底把消息放回输入框，首页仍可能建出空项目（概率很低）。额度卡片占用输入区上方约 3 行高度。`chat_quota_blocked` 的曝光量会比以前多（卡片每次挂载记一次），看漏斗时需要知道这一点。
