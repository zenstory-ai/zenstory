# 月付成为默认选择，模型成本说明按供应商区分

Status: implemented — 随当前修复批次合入 main，不单独发布。

## Problem

订阅入口沿用 2026-10-08 的年付默认，但后续实际销售中 ¥399 年付无人购买。作者从公开定价页或订阅页开通 Pro 时先看到较高的一次性金额，不符合当前购买行为；同时，明确选过年付或通过带计费周期的深链进入时，选择仍必须保留，不能被新的默认值覆盖。

后台「用量与成本」已经汇总 DeepSeek 与 MiniMax 等账本记录，并按每行自己的 `pricing_version` 估算费用。旧说明却把整页写成 DeepSeek 用量，并把 API 返回的 DeepSeek 参考价格表写成所有模型的统一高峰／空闲价格。实际契约中 DeepSeek 按北京时间工作日时段区分价格，MiniMax M3.1 Flash 全天使用同一价格；高峰／空闲费用列仍是调用发生时段的分组，不表示 MiniMax 高峰翻倍。

## Decision

- 公开定价页、订阅页普通入口和付款弹窗默认选择月付；年付仍可手动选择。
- `cycle=month|monthly` 与 `cycle=year|yearly` 作为现有链接使用的明确深链意图，优先于默认值；公开定价页写入的会话内选择继续传到登录后的订阅页。未知值不猜测，回到月付默认。
- 中英文后台副标题改为「模型用量与估算成本」，不再把汇总范围写成 DeepSeek 专属。
- 价格行只保留 DeepSeek 按峰谷计价、MiniMax 全天固定价两项必要事实，不再在主说明重复完整价格与时段；估算、非供应商账单、仅含返回用量的调用、取消／超时边界、向量嵌入不计入等事实保留为第二行。
- 不改价格、支付方式、权益、订单参数、后台计价逻辑或页面布局。

## Alternatives considered

- **只把付款弹窗改成月付，公开定价页仍默认年付。** 最强理由是改动最少。未采用：作者会先在定价页看到年价，登录后又看到月付，入口之间的默认不一致；公开页选择也应直接传入付款。
- **删除年付或降低年价。** 最强理由是年付当前没有成交，减少一个选择可能更简洁。未采用：用户只要求调整默认选中项，价格与套餐结构需要独立商业决策，本批不越界。
- **把 MiniMax 费用全部移出高峰／空闲列。** 最强理由是最不容易误解成分时价格。未采用：现有 API 与表格按调用发生时段聚合，改变列口径需要后端合同和历史报表迁移；本批用准确文案说明固定价即可。

## Consequences

- 收益：普通开通路径先展示 ¥49 月付，显式年付选择和深链仍稳定；后台说明与混合供应商账本、各模型计价表一致。
- 代价：年付的优惠不再默认展示在计划价格上，但仍保留在计费周期选择器中；高峰／空闲 KPI 仍按时段分组，查看具体模型时需结合「按模型」表与价格说明理解。
