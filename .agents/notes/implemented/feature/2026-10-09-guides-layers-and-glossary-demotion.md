# Agent Note: /guides 按四层循序渐进、每篇露出 skill 方法；术语表退出主导航

Status: implemented（主导航部分推翻 [首页逻辑 note](2026-10-03-homepage-material-first-logic.md) 与 DESIGN.md 原“Main nav remains Projects · Guides · Glossary · GitHub”；首页本身的改动见 [homepage-guidance-polish](2026-10-09-homepage-guidance-polish.md)）

## Problem

2026-10-09 对 /guides 与 /glossary 的只读审计（390px 无头 Chrome 实测线上静态页）：

- /zh/guides 页高 6752px，约 8 屏。“按创作任务浏览”在第 2 屏才出现，十张分类卡各列 3 篇精选，11 篇路径文章又在分类卡里重复一次；62 个链接里只有 41 个不重复。
- 学习路径只有小说、短剧、解说三条，没有游戏；进了步骤页没有下一步（9 处相邻衔接缺 5 处）。
- 搜索按文件顺序列出，分类名也参与匹配：“去AI味”返回 40 条、主文排第 4；“对白”86 条、第一条是视频解说；“怎么写开头”“扫榜”“拆文”都是 0 条。
- 读者看不到文章背后的 skill 方法：固定版本的 skill 文件链接只在文末“用 skill 来做”里。
- 术语表 11 条占一个主导航位；其中 10 条已有同题完整文章，但只有 2 条术语页链过去。官网没有统计，Search Console 10-03 报告 979 个 URL 只收录 6 个，术语表的价值没有正反证据。

用户要求：指南要循序渐进，并展现 skill 里的 knowhow；术语表按建议降级。

## Decision

- **四层结构**：/guides 按首页知识层的顺序排：01 入门（入门分类的精选 3 篇 + 网页工作台直达注册 `org_guides_start`）→ 02 完整创作路径 → 03 按任务深入（十个分类的紧凑卡片：名称与篇数，不再列精选文章）→ 04 改稿与查询（改稿分类精选 3 篇 + 术语行）。搜索框下有四层跳转。`#learning-paths`、`#browse-topics` 锚点不变，首页知识层的落点照旧。390px 页高 6752 → 4826px。
- **完整路径**：生成器常量 `WORKFLOWS`，按起点材料分组：从一个想法开始（写出第一章）、已经有小说（做出第一集短剧；做出可玩的游戏原型——新增：小说改游戏怎么做 → 选什么玩法 → 叙事原型 → 测试改编游戏）、已经有视频（把视频剪成解说）。每一步页面顶部显示“创作路径 · 路径名 · 第 n/4 步 · 下一步”，文末给出下一步或“看看其他创作路径”。渲染时跳过当前语言未发布的步骤（测试夹具会替换文章库），真实内容由测试保证四条路径各 4 步全部发布。
- **展现 skill knowhow**：每篇指南和文章的开头显示“方法来自 `<skill>`”及前两个方法文件（固定提交链接）；文章用 `skill` 与 `sources` 字段，指南从来源 markdown 链接里取 `/skills/<name>/`，只引了参考文件的 5 篇指南指向同一提交的 SKILL.md（已用 GitHub API 核对存在）。路径步骤、入门与改稿列表标出 skill 名，分类页每行显示 skill 与方法文件名。
- **搜索**：标题命中 10 分、描述（含 skill 名与方法文件名）3 分；分类名与项目名只在某个词在所有标题和描述里都找不到时才计 1 分；按分数重排。去掉问句填充词（怎么、如何、吗……；how、to……），有多字词时忽略单个汉字，“写开头”这类去掉开头的动词；少量同义词（拆文/拆书、开头/开篇/黄金三章、对白/对话/台词、剪映/CapCut 等）。没有完全匹配时，按中文双字片段列出最接近的 20 篇并说明。11 个术语进入索引。
- **术语表降级**：主导航改为 项目 · 指南 · GitHub。术语表保留在页脚、首页“排错与参考”层、/guides 第 4 层的“查术语”行。`glossary.json` 为 10 个术语加 `how_to`（扫榜暂无对应文章），术语页在定义下方显示“怎么做”与那篇文章，术语索引每条附链接。URL、sitemap、DefinedTerm JSON-LD 不变。

## Alternatives considered

- **H1 下直接列十个分类（审计原建议的顺序）**：最强理由是带着具体问题来的人一屏就能选到分类，页面最短。没有完全采用：用户要求循序渐进；分类改为第 3 层的紧凑卡片，同时首屏用四层跳转让找问题的人一下跳到“按任务深入”，搜索框也在首屏。
- **学习路径直接复用首页三条材料路径（home-reading.json）**：最强理由是首页与指南页只有一套路径定义。没有采用：首页路径是 1–3 步的起步入口，/guides 第 2 层承接首页“完整工作流”层，需要从开始到检查的 4 步；改为沿用首页的起点材料分组，加上游戏路径。
- **把路径写进 content JSON**：最强理由是内容与代码分离。没有采用：路径步骤只是引用已有文章，原先也在生成器里；新增 JSON 要同步测试夹具，收益不大。
- **在文章顶部放完整“用 skill 来做”段落**：最强理由是方法一眼可见。没有采用：那段是可复制的执行提示，放在读完正文之后更合用；顶部只放 skill 与方法文件的出处行。
- **术语表 301 合并进文章**：最强理由是一个查询只留一个主页面。没有采用：违背保留现有 URL 的约定，要改重定向与多个测试，扫榜也无文章可去；收录多数未完成时收益无法验证。
- **术语表保持现状**：最强理由是零维护且有结构化定义。没有采用：主导航位置留给使用频率更高的入口，术语与文章互不连接的问题也需要解决。

## Consequences

- /guides 在手机上短约三成，首屏能看到四层路线；分类卡不再列精选，精选仍在各分类页“先看这几篇”。
- 每篇文章顶部多一行出处链接，与文末“用 skill 来做”的来源链接部分重复；GEO diff 会显示这些新增链接。
- 搜索脚本约 3.3 KB，仍随共享壳内联在每个页面；同义词表是手写的小表，需要随内容增补。拼音与英文词形变化不支持。
- 主导航少一项；术语表页面不再有导航高亮。首页知识层“查术语表”入口保留。
- 扫榜没有 `how_to`，等有对应文章再补。
