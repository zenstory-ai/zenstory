# Agent Note: AI 记忆在原面板采纳提议，人工保存核对备注基线

## Problem

D01 的聊天编号确认曾承诺整批升格却没有完成，D02 的删除询问也曾引导作者答应无法放行的操作。[类型化权限边界](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md) 已取消从答复文字推导长期来源和破坏性权限。现有 AI 记忆仍只有带来源标题的文本框，作者须手搬提议才能采纳；普通保存不会改变仍在提议标题下的内容。

人工 PATCH 虽与 Agent 共用项目写锁，但没有草稿基线条件。面板脏输入期间可收到 AI 更新，或另一个客户端已改备注，旧文本仍会覆盖最新内容。后台刷新还会更新项目对象，不能拿最新对象给旧草稿作基线。

## Decision

- 原 AI 记忆备注旁增加「采纳全部提议」，由作者明确点击，将当前文本中完整的提议分区并入作者确认，保留已有作者条目和分号组。复用人工 notes PATCH，只写备注，不连带保存其他字段的草稿；成功后面板保持打开并反馈已采纳。没有提议时不展示动作。没有新模型调用、确认卡、数据库实体或依赖。
- 人工 PATCH 增加可选 `expected_notes`，与 notes 同时提交时，在现有项目锁内刷新后逐字比较基线；null 与空串同为空备注，不忽略空基线。冲突以 409 拒绝整次请求，其他字段及时间戳也不写。条件字段不持久化。旧客户端省略条件保持既有无条件语义，不宣称旧客户端已有防覆盖能力。
- 面板发送 notes 草稿实际起点，脏输入期间后台刷新不推进此起点；未改备注或本地全文与最新备注已一致时可接收新基线。成功保存使更早的背景读取失效，不能回退已采纳内容与基线。冲突后保留本地草稿，不自动合并或重发。「查看最新备注」仅 GET 并显示只读文本，不修改输入；读取失败仍保留草稿，作者可重试。看到最新文本后，作者选择使用最新备注（只替换本地输入）或保存自己的版本（基于刚查看的最新备注再次有条件 PATCH，仍可能冲突）。其他字段的脏输入保留。项目切换与旧响应继续受现有 owner/save 边界保护。
- 「按以上设定继续写」是当轮创作要求，直接执行，不以长期记忆采纳为前置，也不自动升格来源。长期采纳由原面板动作完成；AI 仍只能维护提议，不能改写作者区。预算反馈只指导精简提议，作者约定仍由人工维护。
- 删除描述与既有保护对齐：聊天确认不能解除受保护正文或其文件夹的删除限制，作者使用文件菜单。普通 edit_file 的局部修改与全文 replace 能力保持不变，不把它说成一律禁止整份修改。

## Alternatives considered

- **恢复聊天编号、复述或「好」的解析**：操作省一步，也贴近聊天习惯；但无法为展示列表、来源或删除对象建立可信授权，且已被类型化边界否决。本条只增加现有人工面板动作。
- **只增加采纳按钮，继续无条件 PATCH**：前端改动最少，但旧 textarea 会覆盖 AI 或另一端的新内容；复用写锁不能识别草稿是否陈旧，因此补最小 wire 基线条件。
- **使用 project.updated_at 作整个项目版本**：已有字段可复用，但 current_phase、summary 等无关更新也会使纯备注保存冲突。本条比较已有 notes 原文，无需新增版本列。
- **新增提议实体和逐条确认卡**：可承载逐项选择与版本，但需要迁移和另一套交互。完整采纳用现有分区已足够，局部维护仍使用原文本框。

## Consequences

作者可以用一个明确动作持久采纳整批提议，不消耗 AI 消息。冲突时本地草稿不会被后台响应或查看最新的 GET 覆盖；只有作者明确选择后才替换输入或提交自己的版本。基线随 notes 请求传输，最多增加一份原备注文本。采纳变换保留原有作者/未标来源文本、缩进和空行；人工 PATCH 仍沿用整个字段首尾 trim 的既有合同。手动编辑和兼容客户端仍存在，来源格式继续使用已有中文标题；不增加自动合并、自动重发或付费调用。

## Verification

- 回归先红：面板采纳/草稿基线 8 项，API 条件字段 12 项；接入 wire 后的两个陈旧写入仍先红，再加锁内比较。独立审查发现旧背景 GET 可回退已保存采纳后，补 2 项红测并复用现有 loadSequence 使其失效。
- 前端组件和分区变换 63 项通过；项目 API 模块 34 项通过，补充真实 HTTP 409 断言后的 CAS 子集 12 项通过；备注/提示 16 项与 notes 工具 6 项通过。ESLint、Ruff、tokens、i18n keys、TypeScript/Vite 构建通过。
- 本地真实 App 的离线 API 浏览器观察覆盖 390 中文浅色、768 英文深色、1440 英文浅色，3 项断言通过（含键盘采纳、409、本地保留、查看最新、显式使用最新、刷新持久投影，模型请求为零）。私有 runner 在断言完成后的清理阶段挂起并以 SIGINT 130 退出，不能当作标准 E2E 完整绿；标准 CI E2E、PG 和真实 staging 验收由集成后的最终源执行。
