# Feature Note: query_files 按章节或范围读取长文件

Status: implemented

关联：[全文标注与工作集](../bug-fix/2026-10-08-agent-context-full-text-and-working-set.md)、[作者改了什么给模型看](../architecture/2026-10-12-author-edits-shown-not-guessed.md)。

## Problem

#274：query_files 按 id 读取只有全文（summary 只是开头预览，offset 是列表分页）。续写只需要上一章结尾、返修只需要某一集，模型也只能拉取整本合集；合集越长，每次局部创作的未命中输入越多。生产近 7 天 3,071 次 query_files 中按 id 读取占绝大多数。

## Decision

- query_files 按 id 读取时可选三种范围（一次只用一种）：`section`（章节/分集标题，读到下一个同级标题为止；「第3章」按章号比较，不会匹配「第13章」或「第3集」，中文数字可用）、`tail_chars`（结尾若干字符）、`start_char` + `max_chars`（默认 6000）。单次范围上限 20000 字符。
- 结果在原来的行上只替换 content，并给出 `content_range`（起止字符）、`content_length`（全文长度）、`content_partial`、匹配到的 `section` 和一句"范围外没有读到、不要当成全文"的说明；`word_count` 仍是整个文件的字数。标题找不到或多义时返回错误并列出识别到的标题，不猜。
- 陈旧保护：范围读取在切片前记下读库时的整份正文，作为新的快照来源 `range`，只用于 edit_file 的陈旧检查；它不算"看过全文"，old/anchor 仍只按逐字匹配。读取之后作者又改了文件（任何位置），edit_file 照旧以 stale_content 拒绝。换 agent 时与普通读取一样清空。
- 工具说明和工作集里"未附全文"的提示都指向按范围读取；作者要求通篇检查或改动牵涉全文时仍读全文。工作集的选文规则、上下文预算和缓存前缀不变。

## Alternatives considered

- **工作集里直接附长文件的结尾片段。** 最强理由是不需要模型主动调用。未采用：会改变每轮注入的内容和缓存前缀，且不知道这一轮需要的是结尾还是某一章；按需读取更准。
- **按行号读取。** 未采用：模型手里没有行号，网文里一段一行，行号与章节对应不直观；章节标题和字符范围更符合实际用法。
- **把范围读取也记成"看过全文"。** 未采用：会让模糊匹配在模型没看过的段落上生效，并可能把局部内容当全文核对。

## Consequences

- 生产 DeepSeek 实测：40 章、约 1 万字的合成合集"在末尾续写第41章"，各跑两次，未命中输入从约 2.1 万降到约 1.4 万 token（约 -30%），单次成本约 0.07→0.056 元（高峰价）；四次续写都紧接第40章结尾、原文前缀逐字不变。节省随合集长度增长。
- 是否使用范围读取仍由模型决定；没有可靠标题的文件只能用 tail_chars / start_char。
- 范围读取后要改范围外的内容时，模型需要再读那一段或全文。
