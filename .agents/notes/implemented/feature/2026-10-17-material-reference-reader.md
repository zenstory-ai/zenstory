# 素材阅读页对齐工作台视觉与正文换行

## Problem

素材详情使用独立、重复的手机/桌面渲染结构，目录图标和标签混用多种固定颜色，未跟随工作台控件与深色主题。正文使用未安装 typography 插件的 `prose-sm` 等类，段落间距没有生效；API 原样返回 `original_content`，但 Markdown 的软换行在浏览器中折叠。合成正文实测桌面单换行前后文字位于同一行，并非已证明的存储丢行。

## Decision

- 保留独立阅读页和原有目录查询、按版本隔离、阶段可见性、试用权限、计费重试及路由切换生命周期。合并重复布局分支，仍按原768px手机边界切换目录/内容。
- 复用 IconButton、Button、DashboardSearchBar、Badge；目录使用中性背景、256/288px宽度，选中项保留用户强调色。文件夹暴露展开状态，当前条目有可访问标记。
- 居中正文宽度上限704px，手机16px、桌面17px，行高1.9；保留正文与章节标题衬线字，元信息与控件使用现有无衬线层级。摘要保持可见，降低颜色与边框强度。
- 仅为素材内容增加局部 Markdown 排版；正文段落使用 `white-space: pre-wrap` 保留软换行。保留原字符串、Markdown列表/强调、原有HTML转义和代码块行为，不改全局 `.prose`。
- 章节读取失败显示明确错误和GET重试，不调用付费拆解 retry。手机返回目录保留搜索和展开状态，书名不随条目标题重复切换。
- 先增加三项回归，原实现3失败/29通过，修改后32通过；独立评审补齐目录失败重读按钮的44px触控规范与第四项回归，最终相关6套件165项；另用真实浏览器验证换行位置、计算样式、阅读宽度与滚动边界。截图使用合成小说，不搬运生产素材。

## Alternatives considered

- **新增 remark-breaks 或全局修改 Markdown**：最直接地把软换行变成硬换行；但会扩大到其他写作/聊天/文档界面，且需要新依赖或修改共享语义。局部段落样式即可解决已复现问题。
- **纯文本替换 Markdown 渲染**：能严格保留原文，逻辑最少；但会移除已有强调、列表等显示能力。本批保留兼容性。
- **后端补换行或重解析素材**：若存储确实丢失分段，这是根本修复位置；当前代码与合成链路证明换行保留，不能据显示缺陷修改原始内容。
- **新增字体设置、阅读偏好和书签**：长篇阅读有潜在价值；但不属于此次视觉一致性与换行修复，不新增入口或存储。

## Consequences

- 正文分段和排版可读性提高，目录与主要页面共享控件/主题，手机与桌面不再复制两套内容树。
- 更舒适的行高和阅读宽度会增加长章纵向滚动，这是阅读取舍，不是要求把整章压入一屏。
- 局部CSS需要覆盖真实Markdown结构的浏览器回归；生产具体素材24需要登录，当前证据不声称已读取其私有正文。此批不修改后端、上传或模型调用，也不自动发布生产。
