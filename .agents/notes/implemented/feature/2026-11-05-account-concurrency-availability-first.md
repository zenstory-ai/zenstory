# Agent Note: 账号并发限制优先保障写作可用性

Status: implemented

本记录替代[每个账号最多同时运行 2 个 AI 写作任务](2026-11-05-account-two-concurrent-writing-tasks.md)中的故障拒绝与恢复等待决策；原记录保留历史取舍。

## Problem

原实现把 Redis 可用性变成写作的前置条件：故障、缺少配置、首次初始化或数据全丢时拒绝新任务，恢复窗口长达 30 秒。用户明确要求优先保障可用性，宁可暂时没有并发限制，也不能因此阻断写作。

审查还用真实 Redis 复现了误占位：获取请求读取存活任务快照之后，旧任务结束并释放；获取脚本随后用旧快照重新加入已释放成员，造成实际只有一个任务时仍返回账号满额，最长 90 秒。

## Decision

- 所有套餐健康状态下每账号最多同时运行 2 个 `/agent/stream` 写作任务，跨项目、会话、设备和进程共享。路由、内部模型调用、审稿、工具和 `/steer` 不另占名额；建议、编辑器润色和素材任务不计入本次限制。
- 获取脚本只回收过期成员、判断容量并原子登记当前任务。只有 Redis 明确返回已有 2 个有效任务时拒绝，返回 409 `ERR_ACCOUNT_RUNS_BUSY`，发生在额度预扣和模型调用之前。
- Redis 获取异常或线上缺少 Redis 配置时允许任务开始；首次初始化和数据丢失没有全站拒绝窗口。取消 `ERR_ACCOUNT_RUN_LIMIT_UNAVAILABLE`、epoch 和恢复窗口。
- 不再维护和批量回写其他任务的存活快照；每个任务只续租自己的成员，续租与释放仍互斥。Redis 获取超时结果未知时保留同一任务 id，后续续租和释放尽力处理可能已经写入的成员。
- 保留每 20 秒心跳、90 秒失效回收、墙钟时限后的续租上限以及幂等释放。正常与失败路径在服务收尾后释放；停止和断线在残稿保存及会话清理之后释放。
- 并发检查降级不影响原有鉴权、项目权限、限流、免费额度、成本保护、同会话并发保护和退款结算。
- 前端只对明确的账号满额显示忙碌提示，恢复本次文字和技能、保留附件与引用，不自动重发。

## Alternatives considered

- **保留故障拒绝和 30 秒恢复窗口。** 最强理由是在可观测状态丢失后等待存活任务重新登记，减少跨进程超发。拒绝：用户已明确写作可用性优先，该窗口也无法统计首次发布期间仍在运行的旧版本任务。
- **保留批量回写，增加账号锁。** 最强理由是恢复时能立即统计本进程的全部任务。拒绝：它继续增加快照和释放之间的协调成本，而故障时临时超限已是允许的产品取舍，删除批量回写能直接消除已复现的误占位。
- **故障时改用数据库或本地强制计数。** 最强理由是故障期间仍保留部分并发保护。拒绝：数据库方案增加新状态和写入成本，本地计数不能代表全账号真实任务；本次只在可靠确认满额时拒绝。

## Consequences

健康 Redis 下可阻止同账号第三个写作任务；Redis 故障不再因并发检查拒绝写作。代价是 Redis 故障、状态丢失、心跳延迟或首次混合版本发布期间可能暂时超过 2 个任务；已在运行的任务不会为恢复上限而被中止。

进程崩溃或释放写入失败时，旧成员仍可能在失效窗口内占位。首次发布前启动的旧版本任务不会计入新限制，直到旧任务结束；上线状态必须与实际部署来源及新版本验收分别核对。
