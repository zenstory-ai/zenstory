# Agent Note: 写作技法文章（articles.json）：自由分节、中文必有、英文可选

Status: implemented

## Problem

五个 skill 仓库的 `references/` 里有大量写作与改编方法（题材卡、章尾钩子、金手指、短剧格式、三视图、解说文案等），网站上几乎没有对应页面。已有的 21 篇指南全部套用同一个工具手册模板：开始之前 / 操作步骤 / 示例 / 预期文件 / 验证结果与边界 / 来源（测试断言这六个锚点，且要求至少 4 条固定提交的 GitHub 源码链接）。这个模板适合"怎么用某个 skill 做某件事"，放到"网文断章技巧有哪些"这类技法问题上，小节标题不含搜索词，"预期文件""结果边界"也无话可写。另一方面，很多中文技法问题没有对应的英文搜索需求，硬写英文版只会多出一批没人搜的薄页面。

## Decision

- 新增内容文件 `apps/web/content/articles.json`，每篇文章路由与指南相同：`/<project>/<slug>`，中文在 `/zh/<project>/<slug>`。不新增路由前缀，所以 `site-routing.json` 与 `vercel.json` 不变。
- 正文是自由分节：`sections[]` 的每节有 `id`、标题与一段轻量标记（段落、`- ` 列表、`1. ` 列表、`|` 表格、`> ` 原创示例、单独一行的 `### ` 小标题；行内支持 `code`、**粗体** 与链接）。混用的块、残缺表格、指向不存在页面的站内链接都会让构建失败，且在写出任何文件之前失败。
- `langs` must 含 `zh`；含 `en` 时写两种语言并互相 hreflang，不含时只写 `/zh` 页：没有 hreflang 对，语言切换的 EN 指向所属项目的英文页，英文页面和英文索引 never 链接纯中文文章，sitemap 条目不带 alternates。
- 每篇只显示一个日期（`updated_on`），JSON-LD 为 `Article`，带 `datePublished` / `dateModified`。`seo_title`（中文 ≤30 字、英文 ≤60 字符）与 H1 `title` 分开；`description` 中文 ≤90、英文 ≤160。
- 每篇末尾是"用 skill 来做"：一段说明，加所属项目页与该 skill 的 GitHub 目录两个链接，代替工具手册式的多条固定提交源码引用。
- 文章出现在所属项目页的"写作技法"一节和 `/guides` 索引对应项目下；`public/llms.txt` 的 Guides 一节列出每篇（纯中文文章给 `/zh` URL）。
- 同批修正：中文页正文里以绝对 `https://zenstory.ai/...` 写的站内链接现在也改指 `/zh`；所有成对页面增加语言级 `hreflang="zh"`。站点地图计数测试改为从内容 JSON 推导。

## Alternatives considered

- **在 guides.json 里加一个 `format: "article"` 分支。** 最强理由：一个内容文件、一个索引列表。被否：指南测试逐条断言六段模板、源码链接数量与路由顺序，分支会让每条断言都要加例外；两种页型的验证规则（源码引用、双语对齐）本来就不同。
- **所有文章都写中英两版。** 最强理由：保持"每条路由两种语言"的旧不变量，生成器不需要纯中文分支。被否：拆解发现多数网文技法词（断章、打脸、追妻火葬场）几乎没有英文搜索，英文版会成为批量生成的薄页，拖累整站质量信号。
- **新开 `/craft/...` 或 `/xiezuo/...` 前缀做技法库。** 最强理由：URL 本身带类别词。被否：要改路由契约、重新生成 vercel.json、调整导航测试；挂在项目前缀下还能把链接权重留在对应项目。

## Consequences

- 收益：一篇技法文章只改 `articles.json` 与 `llms.txt` 两个文件，不再碰测试；标题、描述长度和站内链接在构建时就被卡住。
- 代价：生成器多了一个轻量标记解析器，只支持上面列出的几种块；需要更复杂排版时要先扩展它和测试。
- 纯中文文章没有英文对应页，英文访客从语言切换回到项目页，而不是 404。

## Verification

`cd apps/web && pnpm test:site`（新增 `scripts/__tests__/article-pages.test.mjs`：双语与纯中文夹具、标记渲染、sitemap 条目、非法数据在写出前失败）与 `pnpm build:vercel`。
