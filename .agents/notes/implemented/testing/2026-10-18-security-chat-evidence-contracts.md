# 安全与模拟聊天测试的证据边界

## Problem

独立复核发现，正文安全用例在三秒自动保存前只等待半秒，重载后的空字符串也被视为通过；特殊字符用例只检查结果仍是字符串。CORS 用例接受未认证请求的 401，无法区分正确的源限制与允许任意源。模拟聊天根据当前消息返回固定人名，不能证明服务端记住上下文；一次性完成的 SSE 响应也不证明分段到达。

## Decision

正文用例读取实际 textarea 输入，等待相同正文的真实 PUT，并逐字检查成功响应与独立 GET。重载后的编辑器只允许 CR/CRLF 至 LF 的换行等价，其他字符保持不变；原生输入与受控赋值的换行处理不同，不能预设插入时已规范化。XSS 同时捕获并拒绝实际对话框。CORS 直接访问 API 源，检查未授权源的预检被拒绝且无允许源响应头。错误签名令牌用例准确命名为无效令牌。模拟聊天只声明已完成响应的显示与多轮消息留存；先确认首轮完成，再发送第二轮。

## Alternatives considered

- **只记录旧测试局限。** 改动最少，但这些断言已被用于本批次上线判断，故修正直接影响结论的假绿。
- **增加固定等待或接受正文被清空。** 容易兼容旧实现，但仍不能证明保存与安全共存，故按真实接口和文字编辑器合约断言。
- **把模拟返回内容解释为模型记忆。** 无需额外服务，却不能证明模型或真实会话行为，故保留确定性模拟并收窄名称；真实会话 ID 传递由另一用例验证。

## Consequences

不改产品、超时预算、重试或外呼规则。浏览器测试多等待已有自动保存，并明确区分认证、浏览器源限制、文本保真和模型行为；最终运行结果绑定本批次代码。
