# 导出与性能验收：修复可假绿的行为断言

## Problem

独立语义复核发现，上一生产 tag 之后的完整 E2E 修复中仍保留数条无法证实其名称的断言：章节顺序允许缺失章节的 `indexOf=-1` 参与比较；聊天滚动以宽泛可选容器测量，反复赋同一底部位置且在赋值后才开始计时；大文档自动保存吞掉等待超时且没有时限断言；撤销重做没有校验撤销结果或执行重做；内存释放仅打印数字。绿灯不能证明这些行为。

## Decision

限定修改 `export.spec.ts`、`performance.spec.ts` 与 `large-document.spec.ts` 的已确认假绿路径，不改产品、依赖、重试、超时或其他测试。导出校验每章存在及完整标题正文顺序。聊天选择真实 `message-list`，无条件要求可滚动，交替到顶到底并核实每次位移，从动作前计时，保留原 30 FPS／100ms 预算。自动保存按 SimpleEditor 的实际 3000ms debounce 等待确切文件与内容的成功 PUT，完整响应请求仍使用原 2000ms 预算，并读取服务器核实字节内容。撤销用 API 初始内容隔离原生编辑历史，以真实键盘做单次插入、撤销、重做并校验完整内容。垃圾回收时间不具备确定性 oracle，移除“内存已释放”结论，改为大／小文件切换的可观察内容隔离，不发明内存阈值。

## Alternatives considered

- **接受原绿灯，仅保留说明。** 工作量最低，但不能满足本次独立语义验收，也会继续把空操作当覆盖；不采用。
- **调高超时或性能预算。** 可降低波动，但与缺失断言无关；保持既有有效预算，不改运行策略。
- **强制 GC 后增加内存下降阈值。** 看起来接近原测试名称，但各浏览器支持和回收时序不同，无法从当前产品推导稳定阈值；改为真实数据隔离行为，并记录无法证明 GC 释放的边界。

## Consequences

验收会对缺失章节、无实际滚动、失败／未发生的自动保存、不可用撤销重做和文件内容混淆显式失败。代价是更严格的真实运行验收可能暴露已有问题；本地静态检查和最小 counterexample 不能替代最终源 SHA 的浏览器结果。

已完成上述有限修复。三个目标 spec 的 ESLint、Chromium／Firefox 测试收集（连同 setup 共 101 项）和 diff 空白检查通过。仓库外的最小 Chromium oracle 探针复用真实聊天测量回调，证明正常位移成功、空滚动和无溢出显式失败，同时验证跨平台键盘插入／撤销／重做序列；缺首章的导出反例证明旧断言可过、新断言会拒绝。当前机器缺少已安装版本的 Firefox 二进制，未安装或伪称已运行。探针不是完整 App E2E，最终合并 SHA 的实际双浏览器结果仍需独立取得。
