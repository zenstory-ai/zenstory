# 版本历史端到端证据的语义校验

## Problem

生产 tag 至当前主线的独立源码复核发现，[Full E2E 契约修复](2026-10-17-full-e2e-contract-repair.md)仍留下数个假绿入口。历史正文用例允许预览按钮不存在，并将原本就存在的编辑器视为预览；变更类型断言 `count >= 0` 永远成立；自动保存用例使用同时 PUT 正文、POST 版本的 fixture，关闭浏览器防抖保存后仍能通过。连续人工编辑会合并最新版本，因此比较列表前两行可能是在比较相同正文，页面级颜色查询又可能命中版本徽标。

对应反例是删除预览处理函数、删除编辑器三秒防抖 effect、隐藏变更类型徽标，或把比较结果的实际新增／删除行去掉；原断言不能可靠拒绝这些变化。它们不能作为相应功能的上线证据。

## Decision

- 历史正文必须通过指定 v1 行的真实预览按钮打开，等待该版本 GET，并逐字校验 API 返回值和 `version-preview pre`。
- 自动保存通过真实编辑器输入等待自己的 PUT，随后读取正文、版本列表与最新版本全文；不由 fixture POST 版本，不改变三秒防抖或版本合并规则。
- 比较显式选 v1 与最新行，校验成功 API 返回的版本号和非空真实差异；新增／删除断言限定在对话框 `.diff-add`／`.diff-remove` 的目标正文。
- 变更类型校验实际行徽标及 API 元数据。手工快照说明仍验证现有 API 能力，名称准确说明该入口；五次编辑不声称已跨过五十条分页边界。
- 保留全局超时、重试、额度和独立项目 fixture。只运行受影响的定向浏览器用例；最终发布证据仍绑定合并后的精确 SHA。

## Alternatives considered

- **仅在报告中列出覆盖缺口。** 最快且不改变旧用例，但这些用例已经用于本批次上线判断，继续保留假绿会削弱后续回归，故修正相关断言。
- **禁用合并或固定版本行下标。** 可以简化测试数据；但会把当前产品的人工版本合并规则改成测试方便的行为，故保留合并并选择明确的 v1。
- **增加等待、重试或构建不存在的手工说明 UI。** 可以让旧标题看似成立；但不能校验真实功能，故依照已有编辑器、预览和 API 合约修改测试。

## Consequences

本次只加强版本历史测试证据，不改产品行为、历史合并、额度或接口。代价是自动保存用例需要等待现有三秒防抖，以及最终候选 SHA 需要重新验证这些受影响场景。缺少本地运行服务时先记录未验证状态，不以静态 review 代替浏览器结果。

实现与验证：已完成上述测试修正，定向 ESLint 与 `git diff --check` 通过。浏览器运行证据由本批次统一验证并绑定最终源 SHA；不把断言修正或静态检查称为 E2E 通过。
