# Agent Note: 基础提示的项目目录资料集中后置

## Problem

[完整工具协议先于目录映射](../../implemented/bug-fix/2026-10-16-agent-static-tool-guide-prefix.md) 已把合成公共前缀扩至 10,458 字符，但目录映射仍位于工具指南末尾，挡住后面的能力、内容结构、文件类型和写作指导。目录结构及角色目录引用又引入其他项目 UUID。用户要求进一步优化缓存，同时不牺牲输出质量。

## Decision

- 沿用既有隔离 feature worktree，只调整基础提示：新增固定 `TOOL_USAGE_PROTOCOL` 与目录映射渲染函数，`get_tool_usage_guide(folder_ids)` 继续拼回原有完整指南；不解析提示字符串拆段。
- 全部静态协议和数据库写作规则保留原文、原相对顺序。完整目录映射、数据库目录结构、完整角色资料规则集中在末尾、项目 ID 之前；动态段之间也保持原顺序。
- 先补公共前缀回归，原实现三种项目目录组合均失败，再实现；覆盖两项目隔离、空/子集目录、角色规则覆盖、缺失目录不编造、数据库配置原文及身份优先级。
- 独立加载 8e65a655 基线，验证工具指南兼容输出、静态段及动态段逐字节保留、完整提示等长。只读获取三类线上配置用于离线组装比较，没有输出或保存私有提示原文。
- 不移动 MessageManager 上下文、技能或 nodes 角色规则，不改模型、推理、预算、路由、质检、文件权限和计费。无新依赖、付费模型调用、数据库写入或发布。

## Alternatives considered

- **只把目录映射后移，其他位置不变。** 改动更小；但数据库目录结构会紧接着成为新断点，后面的固定写作指导仍无法跨项目复用，因此本轮连同完整目录/角色资料段一起集中。
- **所有固定角色规则前置，素材任务共享模板。** 还有潜在缓存空间；不采用，因为会改变跨角色、项目事实或任务的关系，验证范围和输出质量风险更大。
- **对完整提示做字符串分割/替换来搬运目录段。** 无需拆分现有生成函数；不采用，因为布局应由结构化组装负责，不增加依赖中文标题解析的脆弱路径。

## Consequences

跨项目的静态协议和写作指导可形成完整公共前缀，但小节顺序仍会影响模型注意力。离线内容保真、结构与权限回归不等于真实生成质量已证实；本轮不发布，也不把字符增长当成实际命中或节省。真实质量与 usage 收益须在另行授权的 staging 验证后判断。
