# 新用户试用的三处小文案：剧本导出、验证码输错、生成模式

Status: implemented

关联：[快速模式默认保留路由](../feature/2026-10-20-fast-mode-default-keeps-router.md)、[组织站与工作台入口](../feature/2026-10-09-org-site-app-handoff.md)。

## Problem

2026-10-24 三位合成新作者的首轮试用里记下的低风险摩擦（不是故障）：

1. 短剧项目左栏叫「剧本」，顶栏导出入口仍叫「导出整本正文（TXT）」；导出的三集内容本身正确。
2. 验证码输错后统一提示「验证码无效或已过期，请重新获取」。那次原码仍在有效期、随后可用，「请重新获取」会让人去重发。
3. 生成模式按钮点一下直接在快速 / 高质量之间切换，首次使用者以为会打开菜单；提示把快速说成「更快出结果（可能更简略）」，而它的实际含义只是写完不自动审稿（同一个 writer、同样的思考强度），单次请求照样可能很长。
4. 组织站「打开工作台」先落到登录页、新作者要再找注册。

## Decision

- 导出：沿用编辑器空状态已有的 `project_type === 'screenplay'` 判断，剧本项目的导出、带大纲导出与对应成功提示用「剧本」（`editor:header.exportScript*`），小说照旧用「正文」。导出接口、范围、文件结构、UTF-8 BOM 与下载行为都不变。
- 验证码：前端文案改为「验证码不正确或已过期。请核对后重新输入；如果已过期，再重新获取。」（英文同义）。仍是同一条错误、不区分输错与过期，不泄露验证码 / 账号状态；校验、限流、有效期都不变。
- 生成模式：提示与切换后的提示改成真实含义（快速 = 写完不自动审稿，通常更早出结果；高质量 = 写完自动审稿、需要时返修，用时更长），并说明点一下就切换。不新增菜单或模式，生成行为不变。
- 组织站入口：只记为低优先建议。`zenstory.ai` 按 DESIGN 是组织 / 开源站，不在本批改结构或跳转。

## Alternatives considered

- **导出入口统一改成中性的「导出作品（TXT）」。** 最强理由：一个词通吃所有类型。被否：小说作者熟悉「正文」，导出确实只含正文 / 剧本、不含大纲与角色卡，中性词反而说不清导出范围。
- **区分「验证码错误」和「验证码已过期」两种提示。** 最强理由：作者一眼知道该重输还是重发。被否：分开提示会让人能试探验证码状态；一句话同时给出两种处理方法已经够用。
- **把模式按钮改成下拉菜单。** 最强理由：符合首次使用者的预期。被否：只有两个选项，切换后已有提示；新控件属于界面设计改动，不在本批。

## Consequences

剧本作者看到的导出用语与文件树一致；输错验证码不再被引导去重发；模式提示不再把快速说成一定更快。代价是多四个导出文案键（中英）。组织站动线未改。

## Verification

Header 测试新增一例：剧本项目显示「导出整部剧本（TXT）」、小说仍是「导出正文（TXT）」；Header 64 项通过。验证码与模式文案是纯文本修改，不另加逐字测试；i18n key 检查与相关组件测试一并运行。
