# 文件正文续跑说明跟随作者语言

关联：[写完文件后续跑与如实完成](2026-10-11-file-stream-continuation-and-truthful-completion.md)、[同一 agent 续跑保持原输入](../architecture/2026-10-21-same-agent-runs-continue-the-previous-input.md)。

## Problem

英文真实写作样本的首个 writer run 和已保存正文均为英文，但文件正文结束后，graph 把全中文的内部续跑说明作为下一次同角色 run 的最新 user-role item，最终总结转成中文。原说明虽要求不得改变回复语言，最新输入本身仍与作者语言冲突；已保存文件、任务板和交付范围均正确，不需要改变续跑条件或文件权限。

## Decision

`_file_stream_continuation_context` 接收由现有 `state.language` 判断得到的 `english` 标志。英文作者的续跑主体操作说明使用英文；中文分支保持原文。子系统约定的机器标记、已保存标题、任务文本与进度、router 交付范围均原样带入，只翻译该说明的固定标签和指令。英文说明继续要求遵守作者原话的语言、长度和格式，并按工具结果如实总结。通用交接包装、读写摘要和清单保留原逻辑，不绕过已有事实保护。

## Alternatives considered

- **只保留原来的“不能改变回复语言”句子。** 改动最小，也表达了目标；但真实复验已经证明，全中文的最新 user-role item 会压过这句软约束，因此不足以修复问题。
- **根据已生成正文重新识别语言。** 能在缺少界面语言时猜测当前文本语言；但会增加新的语义判断，并可能把引用、双语正文或局部外语误当成作者偏好。现有入口已提供结构化语言状态，直接复用更可靠。
- **翻译已保存标题、任务和范围。** 能让说明表面完全统一；但会改变作者和系统已有的原始交付数据，增加模型误解范围的风险，因此仅翻译固定说明。

## Consequences

英文作者在文件保存后的同角色续跑不再收到中文操作说明；中文行为不变。此修复只影响内部续跑上下文，不改变 router、只读与写文件权限、文件协议、SDK schema、计费或已存正文。语言仍以请求入口写入的 `state.language` 为准，不新增内容语言检测。
