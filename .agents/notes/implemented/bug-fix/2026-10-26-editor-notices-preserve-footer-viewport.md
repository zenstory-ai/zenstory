# Agent Note: 编辑器提示不再把操作栏推出视口

Status: implemented

## Problem

恢复未保存草稿后，恢复提示与 `SimpleEditor` 作为同级元素进入固定高度的编辑器面板，但 `SimpleEditor` 仍占用整块面板高度。提示增加的高度因此落在面板高度之外，保存、版本历史等底部操作在 390×844 手机和桌面视口中都被推出可见区域；外层工作台禁止滚动，正文的内部滚动也无法到达这些操作。恢复对比展开或服务端同步失败提示会进一步放大这个问题。

## Decision

- 文件编辑状态使用纵向、可收缩的满高容器；提示区与编辑区明确分配同一面板高度。
- 恢复提示和服务端同步失败提示共享一个最多占面板 45% 的内部滚动区，展开草稿对比时只滚动提示区。
- `SimpleEditor` 放入 `min-h-0 flex-1` 区域，继续由正文区负责稿件滚动，标题和保存／版本历史操作栏保持在编辑器可见边界内。
- 浏览器回归在 390×844 与 1440×900 展开长草稿对比，检查正文内部滚动区仍有可用高度且底部操作栏没有超过编辑器面板。

## Alternatives considered

- **让整个编辑器面板改为外层滚动。** 可以让底部操作最终可达，但会新增正文区和面板的两层滚动竞争，破坏现有固定标题与操作栏的编辑体验。
- **缩短或折叠恢复提示内容。** 能减少常见情况下的高度，却不能保证长文对比和多个提示同时出现时的操作可达性，也会改变恢复流程的信息展示。
- **只给 `SimpleEditor` 增加 `min-h-0`。** 改动更小，但没有为提示区建立上限；展开长对比仍可能吃完整个面板。

## Consequences

恢复草稿、服务端同步重试、保存、版本历史与正文编辑语义不变。提示区在内容较多时拥有自己的滚动条，最多使用编辑面板的 45%；正文仍保留独立滚动并至少获得剩余空间。固定百分比是在保持提示可读与编辑器可操作之间沿用现有删除草稿提示布局的取舍。
