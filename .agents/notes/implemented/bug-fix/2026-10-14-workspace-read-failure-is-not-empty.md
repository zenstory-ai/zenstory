# 工作区读取失败与真实空结果分开

## Problem

预发布原生切换中，已有正文和四条对话历史的项目重新加载后，编辑器正确提示文件无法打开，文件树却显示“还没有文件”，聊天显示首次欢迎。文件树 catch 直接清空 tree；普通历史 catch 清空 messages 并返回空数组，继续请求初始建议。失败不代表已保存内容消失。

相关约定：[异步状态](../../../../docs/ui-async-state-standard.md)、[新对话失败恢复](2026-10-13-new-chat-concurrency.md)、[成功新树才判断删除](2026-10-13-deleted-open-file-terminal.md)。

## Decision

- 桌面和手机树的读取失败在原内容位置提供一句错误和显式重试。失败保留当前项目已有树与选择；项目切换仍清空旧项目，只有成功新树参与删除判断。重试只重读 GET，成功空结果才显示原空态。
- 普通历史读取也复用已有 `sessionRecoveryError`、同步发送暂停与原重试区，失败返回 null，不显示欢迎或请求初始建议。显式重试只读取历史，不创建会话或发生成，不清本地输入；成功空历史才欢迎。所有请求继续按原项目和序号隔离。
- 已有新会话创建失败恢复仍按未知活动会话处理，不保留可能已经过期的旧消息。没有新对话实体、自动重发、额外面板或服务端改动。

## Alternatives considered

- **只弹一次 toast。** 最小，但提示消失后仍是误导的空态，也没有直接重读入口；未选。
- **统一刷新整页或新增错误面板。** 可以重新加载，但扩大影响到正在编辑的区域，重复解释并增加层级；复用各面板原有内容位置和重试合同。
- **自动重试所有请求。** 可以掩盖短暂读取失败，但容易扩大到创作与写入，且不能让未知结果冒充成功；保留作者显式 GET 重试。

## Consequences

短暂读取失败不会暗示作品或对话已被删除。未知历史期间仍可保留输入，发送等待读取恢复。此修复改善中断后的展示与恢复，不改变持卷部署限制，也不证明原生切流无中断。

## Verification

新增回归在修改前为 8 项失败、126 项通过；修改后受影响五个组件测试文件共 268 项通过，覆盖桌面／手机树与真实 ChatPanel 的普通／StrictMode 生命周期。定向 ESLint、完整 typecheck/build、token 与 i18n 检查通过。实际 Chrome mock API 浏览器案例在 390、768、1440 宽度通过，截图核对错误／重试和恢复后的布局，按钮触控高度至少 44px；重试仅 GET，四条历史与本地输入恢复，未发建议／生成或文件 PUT，原稿保持不变。
