# Agent Note: AI 整章写入的小说正文补上漏掉的第一段缩进

相关：引号规范化走同一个写入开关，见 `feature/2026-10-09-agent-writes-normalize-cjk-quotes.md`；单循环的写正文协议见 `architecture/2026-11-16-single-loop-agent.md`。

## Problem

AI 用 `<file>` 写的小说章节里，后面各段都以「　　」开头、只有第一段顶格的情况占用「　　」缩进的章节约一成半（多 agent 图时期也有）。捕获和保存路径不会去掉行首空白（已有回归测试覆盖），是模型自己漏写了第一段的缩进。

单循环的 write_chapter 示例原来给的是顶格的「第三章的正文...」，规则里也没提段首缩进。第一版修复把示例改成带「　　」的两段，复审指出：同一段文件协议也用于剧本（场景标题、动作行、台词按剧本格式顶格）和英文作品，带缩进的示例会把「　　」带进这些稿件。

## Decision

- 提示：write_chapter 规则 7 写明第一段的段首格式和后面各段、和这部作品已有章节一致；中文小说章节段首用「　　」时第一段也用；剧本、英文作品按各自的格式。示例恢复成不带格式的「第三章的正文...」。系统提示仍是各项目类型共用的固定文本，前缀缓存不变。
- 确定性补齐：`paragraph_layout.indent_unindented_first_paragraph` 是纯函数，只看稿子自己的体例。开头的标题行（`_is_heading_line`）跳过，看标题下面的第一段。第一段之后的非空、非标题段落至少 3 段，且其中至少 80% 的段首缩进恰好是「　　」；第一段没有任何行首空白、以文字、开引号或「——」「……」开头（只有破折号、省略号的分隔行不算），并且像一段话（以句末标点、破折号或闭引号收尾，不是只有编号的「1.」「一、」）时，在第一段行首补「　　」。「序章」「楔子」「一」「Chapter One」、不带分隔符的「第一章雨夜」、单独的标题词和剧本式的「1-1 日 内 公司大堂」都不像一段话，原样不动。其他情况原样返回。英文稿件不用「　　」，自然不满足条件。
- 只用于应用内 agent 的整章写入，只对 draft：`edit.normalize_ai_body_first_indent` 由 `FileCRUD.update_file`（流式新章节落库，`StreamAdapter._save_file_content_sync`）和 `FileEditor.replace_body`（write_chapter 整章替换）在 `normalize_quotes=True` 时调用，紧接在引号规范化之后。script 和资料文件不动；Agent API、作者保存、edit_file 的局部修改都不经过这里。
- 补的只是两个全角空格，`count_words` 不变；整章替换返回的 `new_content`（diff 审阅）、`new_word_count` 和撤销锚点都基于补齐后的正文。编辑器实时打字看到的仍是模型原样输出，流结束后编辑器按服务端正文重新加载（和引号规范化相同）。

## Alternatives considered

- **只靠提示词（带缩进的示例或更强的规则）。** 最强的理由：零代码、模型直接写对，实时打字也一致。没选为唯一手段：图时期的提示早就写了「段首缩进和已有章节一致」，漏写比例没有消失；带缩进的示例又会影响剧本和英文作品。
- **按项目类型或界面语言给不同的示例。** 最强的理由：中文小说直接看到正确写法。没选：短篇、长篇里也有英文作品，项目语言不等于稿件语言；多一份示例还让同类型项目的系统提示分叉。
- **按上一章或项目已有章节的体例补缩进。** 最强的理由：新项目的第一章之外，可以覆盖整章顶格写错的情况。没选：要多一次查询，而且会把模型有意换的体例改回去；本问题只是第一段漏写，看本章自己的后续段落就足够确定。
- **在 StreamProcessor 捕获时实时补。** 最强的理由：作者实时看到的第一段也带缩进。没选：第一段输出时还不知道后面的段落是否缩进，只能猜；在保存点按全文判断才是确定性的。

## Consequences

- 收益：后续段落体例明确的中文章节不再出现第一段顶格；剧本、英文、无缩进或混用缩进的稿子一个字不变。
- 代价：
  - 第一段之后不足 3 段、或者缩进混用低于 80% 的章节照旧依赖模型自己写对；第一段不以句末标点、破折号或闭引号收尾（如以冒号结尾引出下一段对白）时也不补。
  - 实时打字时第一段仍是顶格，流结束重新加载后才显示缩进。
  - 作者故意让第一段顶格、后面缩进的稿子，经 AI 整章写入后会被补上缩进（作者可在编辑器里删掉，后续 edit_file 不再补）。
- 验证：`tests/test_agent/test_first_paragraph_indent.py`（纯函数与 file_type 门槛）和 `tests/test_agent/test_loop_write_chapter.py` 里经真实 loop 引擎、write_chapter、StreamAdapter 的新建与整章替换两例（落库、diff 审阅新稿、字数），后两例在没有补齐时失败。
