# 单次运行停止原因与低打扰拒写说明

## Problem

StreamAdapter 跨角色运行累计用量，但上一 run 的 end_turn 会残留到下一 run 没有 MESSAGE_END 的错误中。截断覆盖保护正确保住旧稿，却把工具名、协议标签、文件 ID 和内部字符数当作作者正文，英文界面也收到中文诊断。

## Decision

- AGENT_SELECTED / MESSAGE_START 标记新 run，只清停止原因，累计 usage 不清。同 run 的结构化 MESSAGE_END 后 ERROR 继续保留熔断/无进展原因。
- 截断覆盖判断、原稿与版本保护不变。作者按请求已有 language 收到“本次改写未保存，原文保持不变。”或英文等价句；详细事实留在诊断日志。
- 原提示只由 SSE 发出，并没有回喂模型。保留模型已有 create_file 结果和 graph 纠偏协议，不为改一句作者说明增加反馈队列、模型调用或补写权限。
- 对聊天中的伪工具协议残片，不新增通用 XML/正则清洗：模型内容没有可信来源标记，可与作者故意引用的相同文字重合。该子项延期独立处理，不删除任意正文或文件内容。

## Alternatives considered

- 只在 ERROR 清空停止原因：代码最少，但会抹掉同 run 真实熔断/no_progress。选择在已有运行边界复位。
- 删除保护提示：最安静，但作者不知道本次改写未保存。保留简短真实保存结论，不公开诊断。
- 在聊天边界删除已见协议字符串：可快速遮住个别样例，但没有足够来源信息证明不会删掉合法引文，不按事故字面量加黑名单。

## Consequences

历史停止原因更准确，累计统计保持。拒写仍可见但不再像内部崩溃。单元和 SQLite 落库回归保留原稿逐字不变及正常闭合重写对照；真实模型协议残片仍可能出现，需后续在可信协议边界另行解决。
