# Agent Note: edit_file 恢复反馈区分协议缺失、性能保护与批内锚点失效

Status: implemented

## Problem

`edit_file` 已经要求每项显式携带 `op`，缺失时也会整批回滚并在 `failed_edits` 中保留索引；但工具 schema 没给最小规范示例，模型仍容易漏字段。近似匹配的静态工作量保护、扫描截止时间和完整扫描后确实没命中都返回 `None`，调用方统一要求复制“更长”原文；前两种情况下扩大锚点反而更容易继续触发保护。批量编辑还存在另一种可恢复失败：前项合法改掉了后项仍引用的批次开始原文，后项只得到普通找不到锚点，无法区分误抄与批内依赖。

这些问题不能通过推断 `op`、放宽匹配、忽略前项、自动重试或取消整批原子性解决。

## Decision

- 在现有 schema 中给出包含显式 `op` 的最小 `replace` 示例，并说明缺失项仍按现有 `failed_edits` 的 0-based index 返回；不自动补字段。
- 沿用 `find_approximate_match(..., stats=...)`，增加静态工作量跳过和截止时间到达两个诊断标志。完成扫描但无唯一命中的对照组保持两个标志均为零。
- replace / insert 的失败反馈根据诊断说明扫描为何未完成，并统一建议从当前正文取较短、逐字、唯一的片段，必要时按段拆分；不提高工作量或时间上限。
- 只有某项已失败为 `anchor_not_found`、其 `old/anchor` 能在批次开始正文中用现有精确或引号等价定位、却已从前项编辑后的暂存正文消失时，才在该失败项增加批内锚点失效提示。建议基于前项后的文本重定位，或拆成单独调用后重读。执行顺序、合法链式编辑和整批回滚保持不变。

## Alternatives considered

- **缺 `op` 时按 `old/new/anchor/text` 自动推断。** 最强理由是少一次工具往返。被否：同一组字段可能对应不同操作，猜错会直接改坏正文；现有显式协议和失败索引已经提供安全恢复路径。
- **提高近似匹配上限或延长截止时间。** 最强理由是长章节里可能多命中一些错误锚点。被否：现有上限保护事件循环和 SSE 响应，放宽会重新引入已修过的阻塞风险；反馈应引导更小、更确定的输入。
- **凡前后编辑范围可能重叠就拒绝整批。** 最强理由是实现简单且容易解释。被否：后项引用前项 `new` 的顺序链式编辑是合法能力；本次只在真实定位失败后解释已证实的原始锚点消失，不增加执行拒绝规则。

## Consequences

- 模型能从现有错误结果区分协议缺失、静态保护、扫描超时、真实无唯一命中和批内锚点失效，并按当前正文重建完整批次。
- 原子性、陈旧检查、歧义保护、段落边界、匹配阈值、工具失败累计和收费模型调用次数均不变。
- 诊断只说明程序已经确认的匹配事实，不保证模型之后一定给出正确参数；较短片段仍必须逐字且唯一，否则继续安全失败。
