# Agent Note: 快速模式保留 writer 总结；create_file 之后那次回复只能写正文

Status: implemented

关联：[快速模式默认保留路由](../feature/2026-10-20-fast-mode-default-keeps-router.md)、[正文分两次回复写](2026-10-10-file-streaming-protocol-two-replies.md)。

## Problem

1. **快速模式**：WRITER_PROMPT 要求 writer 正文超过阈值就交接给 quality_reviewer，交接前只写一句进度（如「我再通读核对一遍」），要告诉作者的话（旧稿可以在历史版本里找回、要问作者的问题）写进交接的「[要告诉作者]」。快速模式只在指令里加一句「不要交接」，writer 仍按送审协议交接时，图把交接丢掉，作者只看到那句进度、没有总结，「[要告诉作者]」整段丢失；第一条消息的「补跑一轮写总结」排在丢弃之后，快速模式下永远触发不了。同一句「写完直接结束」也发给了规划角色，可能让规划完就结束、不交给 writer 写正文。
2. **正文流式协议**：两次回复协议要求 create_file 之后的下一次回复以 <file> 开头写正文。实测部分模型（备用供应商尤其明显）在这一步改调 update_project / query_files / edit_file，用 edit_file 分段追加正文：编辑器里看不到实时正文，调用次数成倍增加。create_file 的返回里也没有任何「下一步写正文」的提示，全靠系统提示记住。

## Decision

1. 快速模式的指令分角色：writer 明确「送审规则这一轮都不适用，自己写完整总结，『[要告诉作者]』的话写在总结最后，作者要求审稿时说明这一轮没审」；规划类角色只说「不要交接给 quality_reviewer，其他交接照常」；审稿人不加。
2. 快速模式与第一条消息共用一个丢弃分支：丢弃 writer → quality_reviewer 的交接后，writer 没写总结（快速模式按交接前的话不足 80 字判断；第一条消息沿用原规则：完全没写）时补跑一轮只写总结，并带上交接里「[要告诉作者]」的话；已写了总结时把那些话直接补给作者。
3. create_file 建好空文件（非文件夹）时返回 `awaiting_body: true` 和 `next_step`（下一次回复以 <file> 开头写正文，不要先调用其他工具）；同名重复创建的返回同样带上。
4. `openai_agents/model.py`：模型输入末尾那批工具结果里有 `awaiting_body` 时，这次调用 `tool_choice="none"`，只能回复文字。只看末尾那批，较早的未写文件不会把模型锁在工具之外；tool_choice 是请求参数，不影响前缀缓存。

## Alternatives considered

- **快速模式也照常送审，只是不自动送审**。最强理由：writer 的送审协议不用改。被否：快速模式就是作者选择不审稿，送审会让快速模式名不副实，且成本回到高质量模式。
- **只在系统提示里强调正文协议**。最强理由：不改调用参数。被否：协议本来就写在系统提示里，模型仍然会在这一步改用工具；强制只能回复文字是唯一稳定的做法。
- **create_file 直接接受正文参数**。最强理由：一次调用完成。被否：正文作为工具参数时不能流式显示，正是两次回复协议要避免的。

## Consequences

- 收益：快速模式下作者总能看到这一轮的总结和需要知道的话；规划角色照常把正文交给 writer。
- 收益：建文件后的下一次回复只能是正文，正文实时流式显示，不再用 edit_file 拼接。
- 代价：快速模式下 writer 仍交接时多一次只写总结的模型调用；建文件后的那次回复如果模型没写 <file>，由原有的空文件纠偏轮处理。
