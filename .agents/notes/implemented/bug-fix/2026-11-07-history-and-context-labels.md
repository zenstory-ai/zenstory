# 历史版本与上下文标签统一到现有组件

## Problem

手机截图中的「AI 编辑」「当前内容」直接使用旧颜色类，没有组合 `.badge` 基础样式，导致缺少小字号、留白和圆角；旧成功色也没有使用可读文本 token。历史列表只有一条时仍固定占据 80vh，长文件名和版本元数据缺少换行空间。检查同类显示后，聊天上下文优先级仍使用实色背景配白字，与现有 Badge 不一致。

## Decision

- 历史来源复用中性 Badge；当前内容使用共享 success Badge。复用原有图标按钮，整理标题、元数据的换行和间距。
- 少量历史按内容高度显示，多条记录保持内部滚动；打开预览和对比时保留阅读高度与手机返回位置。
- 上下文优先级复用 Badge 的语义变体。删除没有剩余调用的旧 badge 样式，不引入新的组件或依赖。
- 保留版本来源判定、选择/对比、恢复确认、文件并发保护和 API。用既有 75 条组件/摘要用例作为基线，再用真实浏览器验证手机/桌面、中英、明暗主题的样式与滚动。

## Alternatives considered

只给历史标签补 `.badge` 类改动最小，但仍保留两套颜色实现及旧文本对比度。统一为现有 Badge 能同时修复根因和后续一致性。没有采用新的时间轴或卡片列表，因为当前任务不需要改变版本选择方式。

## Consequences

来源与当前状态的视觉权重降低，少量版本不再撑出大块空白。历史 API、正文和恢复行为不变；浏览器验收需同时覆盖长列表与预览，防止收紧高度后破坏滚动。

## Verification

154 条组件/摘要测试通过。Chromium 和 WebKit 各 7 个浏览器场景通过，覆盖 390/768/1440px、中英、明暗主题、触摸目标、长列表预览返回和聊天五种优先级；axe 对比度检查通过。新增用例在改动前能复现历史标签字号为 16px 的缺陷。TypeScript、Vite build、CSS token、i18n key 检查通过；全量 lint 无错误，保留 useFileSearch.ts 两处既有警告。独立复核无阻塞项。浏览器仅使用合成数据和 mock API/SSE，未操作生产数据或调用付费模型。
