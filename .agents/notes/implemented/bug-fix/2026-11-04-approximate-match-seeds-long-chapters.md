# Agent Note: 长章节的近似匹配用种子定位，不再整段跳过

## Problem

`find_approximate_match` 是逐窗口全扫（窗口尺寸数 × 原文长度 × pattern 长度），曾实测 5000 字原文 + 260 字 pattern 跑 39 秒，因此有两道静态工作量线：归一化原文超过 5000 字，或估算工作量超过 500 万次字符操作时直接跳过，报「近似扫描因工作量保护未执行」。[2026-10-26 恢复反馈](2026-10-26-tool-edit-recovery-feedback.md) 拒绝了放宽上限（会重新阻塞事件循环）。

生产 11-01 至 11-03：长章节里只差一两个字的长 old（相似度 0.87–1.00）因此必然找不到，大批编辑整批回滚，是熔断变多的主因（见 [锚点失败不再提前熔断](2026-11-04-anchor-misses-do-not-trip-early.md)）。只删掉静态线也没用：1 秒的扫描截止时间仍会让 25k 字章节 + 800 字 old（约 10^9 次操作）超时失败。

## Decision

- 静态工作量线以内的输入照旧逐窗口全扫，行为不变。
- 超出时改走种子定位 `_seeded_approximate_scan`：pattern 的 3 / 6 / 12 字片段在原文里按出现位置给对齐偏移投票（出现超过 64 次的片段不投票），按偏移带宽汇总，取得票最多、彼此不重叠的至多 8 处；每处用 SequenceMatcher（不开 autojunk）对齐出窗口，再用与全扫相同的 ratio 打分。
- 相似度阈值、非重叠次优的歧义间隔（0.08）、跨段换行约束、映射回原文的边界处理都与全扫共用；1 秒截止时间保留，扫描不完整时照旧放弃。
- `workload_skipped` 统计恒为 0；找不到原文的提示去掉「工作量保护」一支。

## Alternatives considered

- **直接删掉静态线。** 最强理由是改动最小。被否：全扫在长章节上仍要上亿次操作，会撞 1 秒截止时间照样失败，还在工作线程里长时间占住 GIL 和文件编辑锁。
- **提高静态线和截止时间。** 最强理由是不引入新算法。被否：全扫代价随长度平方增长，放宽到能覆盖 3 万字章节需要分钟级，10-26 已因阻塞风险否决。
- **换第三方模糊匹配库。** 最强理由是更快、更成熟。被否：引入新依赖需另行授权，且要重新验证歧义与跨段规则。

## Consequences

- 长章节、长 old 的小差异能被近似定位；合成测试中 3 万字章节 + 800 字 old 单次约 50 毫秒，30 次约 1.7 秒。
- 种子定位只看得票最多的几处，极端重复的正文里可能漏掉真正的匹配并照旧报找不到；歧义检查只比较这些候选，相距较远、几乎一样的两段仍会形成各自的候选而被拒绝。
- 近似命中仍是兜底，结果照旧报 `match_mode=approximate` 与相似度。
