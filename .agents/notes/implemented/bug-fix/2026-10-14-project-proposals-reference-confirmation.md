# Agent Note: 已有提议可按上一轮同批编号明确确认

## Problem

项目备注已有「AI 提议·待作者确认」来源分区，但作者按 AI 刚列出的编号确认时，工具仍只认复述内容。模型于是要求作者逐条复述，或承诺「全部确认」后实际没有升格。编号如果脱离上一轮展示和当前备注核对，也会误认另一份清单或已经改动的提议。

本条补充并局部替代 [项目备注来源分区](../architecture/2026-10-11-project-notes-source-sections.md) 中「必须复述内容才能确认已有提议」的限制；新条目和来源分区保持既有合同。

## Decision

- 复用 `ToolContext.author_previous_offer_context` 里的上一轮 AI 原回复，备注专用解析完整的明确待确认列表。只忽略主题标题，保留全部阿拉伯编号项和原索引，不受文件授权选项的收尾行数、条数和单项长度限制；不接受模型自报清单，不按当前提议筛选或重排。较早提到待确认不使末尾“下一步”操作清单变成提议；完成报告不作为待确认列表。原有文件授权解析保持原样。
- 展示的每个编号组与数据库提议共用现有分号拆分和规范化规则；完整展开后的条目数量、内容集合必须一致且无重复，展示编号必须连续。数据库行顺序不作为授权条件，完整清单重排后仍按作者看到的编号选择；选择一个编号会升格该组全部分号子项。模型改写、新增的条目不能借此进作者确认；缺项、截断、另一份清单或当前提议已改变时继续保留待确认。
- `author_quotes` 必须对应作者最新一条完整答复。支持有限的整句编号选择（如「确认第1、3条」「第2条」）和明确全批确认（如「确认以上全部提议」「全部确认」），不把「好」「谢谢」、问句、否定、带条件或另附清单的答复当确认。只升格被选中的已有提议；未选提议保持原样。
- 当前原话直接支持新条目、复述已有提议、外部无作者上下文、整体替换和共享字数限制沿用现有行为。提示词、工具说明和工具结果使用同一确认合同，没有新增界面、状态字段、数据表或模型调用。

## Alternatives considered

- **继续要求逐条复述**：逐字核对最容易定位内容；但已完整展示且作者明确引用时，重复输入没有增加信息，本条在严格核对同批原文后支持引用。
- **根据“好”“都按你说的”或模型自报的列表猜测确认**：覆盖自然说法更多；但无法稳定区别客套、其他清单和已经改变的提议，故只支持有限的完整答复合同。
- **增加确认按钮或结构化提议实体**：可精确携带 ID 和版本；当前备注和上一轮选项已能定位这一批，增加存储和界面成本没有必要。

## Consequences

作者无需为固定提议重复整条内容，工具也不会把未选条目或新推断搭车升格。需要把同批确认合并在一次 `update_project` 调用中；第一次升格后剩余列表已变化，原批编号不会继续复用。没有明确待确认引导、编号缺失、措辞改变以及含糊答复会继续保留提议，作者可明确说出内容。带新改动并说“其余全部确定”的复杂答复不在本条自动引用合同内；仍可记录当轮逐字支持的新规则，不猜应排除哪条旧提议。此处不改变旧的逐字复述路径及其语义限制；真实模型是否准确调用并如实说明结果，仍需独立效果验收。

## Verification

真实 staging 的两条编号提议各含一个分号，数据库规范化后有四个子项。修复前，全批确认和分别选择第 1、2 组的三项回归均失败；修复后配置测试 66 项通过，现有备注工具集成测试 8 项通过，Ruff 通过。回归同时覆盖完整重排后的展示编号、缺项、重复、新增、改写、空组及不连续编号。用现场保存的上一轮展示、作者原句和工具参数做本地纯函数回放，结果为两组共四个子项升格、无剩余提议；这不代替集成后的真实 staging 验收。
