# 语音输入按键交互修复

## Problem

工作台聊天输入框的语音按钮（`MessageInput` → `VoiceInputButton` → `useVoiceInput`）在手机和窄屏桌面上不可靠：

- 手机“按住说话”：手指落在按钮中央的麦克风图标上时，录音开始后图标被波形替换卸载。之后的 `touchend` 派发到已脱离文档的节点，冒泡不到 React，松手不会停止，录音一直持续到 55 秒自动停止。
- 交互模式按视口宽度（<768px）选择。窄屏桌面窗口中鼠标点击和键盘都无法开始录音。
- 首次授权弹窗出现时，用户必须松手去点“允许”。松手被当作取消，等待期间也没有任何状态反馈，授权完成后什么都没录到；松手后被拒绝时，错误提示也被吞掉。
- 短按（<200ms）没有任何反馈。
- 55 秒自动停止后再松手，会调用取消，中止正在进行的识别请求，文字丢失。
- 旧的手机 E2E 指向未被产品引用的 `MobileChatInput` 测试 id，并用 `if (isVisible)` 包住断言，因此始终空通过。

## Decision

- 按住说话改用 Pointer Events，并对按钮调用 `setPointerCapture`。按钮子元素设为 `pointer-events: none`，同时加 `touch-action: none` 和 `-webkit-touch-callout: none`。图标替换后，松手事件仍能送达按钮。
- 只有“手机宽度 + touch 指针”使用按住说话。鼠标、触控笔、键盘在任何宽度都走点击切换；宽屏上的触摸点按维持原来的点击切换。触摸结束后浏览器合成的 click 会被忽略；键盘触发（`detail === 0`）不受此影响。
- `useVoiceInput` 新增 `releaseRecording()`，表示“按住结束”：
  - 正在录音时，停止录音并识别；
  - 麦克风请求仍在等待时，记下这次松手。授权返回后立即释放麦克风、不录音，并通过 `onReleasedBeforeStart` 提示“麦克风已就绪，请再次按住说话”；若被拒绝，照常显示错误；
  - 其他状态（例如自动停止后正在识别）不做任何事，识别结果正常回填。
  另有 `cancelPress()` 处理系统取消触摸（`pointercancel`）：正在录音时取消并提示“已取消录音”；麦克风请求仍在等待时（原生权限界面常常以 touchcancel 收走触摸），按松手处理；正在识别时不做任何事。是否录音依据 hook 内的 ref 判断，而非渲染时的状态，避免早期取消时状态过期。
- 一次会话从开始到结束都保持它启动时的交互模式（组件内的 `sessionModeRef`）。手机宽度且可触摸的设备也可能接了键盘或鼠标：
  - 由键盘/鼠标启动的会话（等待授权或录音中），之后再触摸按钮时不进入按住说话。松手时：录音中就停止同一段录音并识别；等待授权中就取消，不会再发起第二次麦克风请求。短按和长按都一样，不会重开新录音、丢弃前一段。
  - 反过来，按住说话期间用键盘停止，手指松开后不会多出新会话。键盘触发的 click 不会消耗“触摸结束后合成 click”的抑制标记。
  - 触摸未满 200ms 时键盘/鼠标接管：待触发的按住计时器作废，只保留键盘/鼠标启动的那一次会话；手指松开时合成的 click 仍被抑制。触摸仍按下时到达的 click，不视为触摸的尾随 click。
  - 按住后系统放弃旧授权、再次按住，仍按原规则重新开始。
- 空闲时按钮名称统一为“语音输入”（任何宽度都可点击）；“长按说话”只在手机触摸短按时作为提示出现。
- 等待授权期间显示独立状态：浅强调色底和跳动的麦克风图标，`aria-label`/`title` 为“正在请求麦克风权限…”。桌面在等待期间再次点击，取消并提示“已取消录音”。
- 短按显示“长按说话”提示，不打开麦克风。
- 新增 `apps/web/e2e/voice-input-mocked.spec.ts`：在 Chromium 中运行真实工作台，使用假麦克风和 CDP 触摸，API 全部在本地 mock，不访问后端，也不调用识别服务。覆盖图标中央/边缘长按松手、短按、键鼠与触摸混用（键鼠开始后短按/长按、等待授权时切换输入、按住后键盘停止、200ms 阈值内键鼠接管）、首次授权的允许/拒绝/延迟、授权界面收走触摸、松手与取消的竞态、系统取消触摸、自动停止后松手、窄屏鼠标和键盘、宽屏点击，并校验上传的 WAV 为 16 kHz 单声道 PCM16 且非静音。该 spec 加入 `ci.sh` 的 release 车道；full 车道也会运行它。
- 删除 `mobile.spec.ts` 中空通过的语音测试。同一段落里的两个聊天输入测试（发送按钮触控尺寸、输入框自动增高）不依赖语音，作为 `Mobile chat input` 段保留。

## Alternatives considered

- **只给子元素加 `pointer-events: none`，保留 touch 事件。** 这是最小的改动，单独就能修复中央图标松手不停的问题。但窄屏鼠标和键盘不可用的问题仍在，而且 React 的 touchstart 是被动监听，`preventDefault` 无效，长按仍会触发滚动和系统菜单。改用 Pointer Events 后，这些问题能用同一套事件处理解决，所以 `pointer-events: none` 只作为附加保护保留。
- **手机端也改成点按切换，不再按住说话。** 这样能彻底绕开授权弹窗与松手的竞态，交互也更简单。但这会改变现有的手机交互习惯，超出本次修复范围。保留按住说话，再把授权等待单独处理，已经能消除“幽灵录音”和“松手即丢”的问题。
- **授权返回后继续录音（即使手指已松开）。** 能少按一次，但用户已松手、并不知道正在录音，会产生幽灵录音，因此不采用。

## Consequences

- 好处：手机按住说话的结果不再取决于手指落在按钮的哪个位置；窄屏桌面可以用鼠标和键盘；首次授权有明确反馈，下一次按住即可录音；自动停止后的识别不会再被松手打断。有了真实组件的浏览器回归，同类问题不会再空通过。
- 成本：按钮上禁止了从按钮开始的页面滚动；首次授权仍需要按两次（第一次授权，第二次说话）。浏览器模拟不等于真机：iOS Safari 和 Android Chrome 的原生权限界面与真实触控命中，仍需在物理设备上确认。`MobileChatInput` 仍是未被引用的组件，本次未删除。
