# 积分兑换 Pro 默认关闭

## Problem

生产前端隐藏了积分面板，但服务端兑换接口仍允许活跃登录账号消耗积分开通或续期 Pro。2026-10-16 用户提供了真实兑换流水，说明隐藏入口没有关闭兑换能力。用户授权上线关闭积分兑换 Pro。

## Decision

在积分服务的兑换方法最前面检查 `POINTS_PRO_REDEMPTION_ENABLED`，通过已有 `_get_bool_env` 解析器读取，缺省或非法值均为关闭。关闭时返回 403 和 `ERR_POINTS_REDEMPTION_DISABLED`，在任何积分与订阅操作之前结束；中英文错误映射分别说明积分兑换 Pro 已关闭。保留认证路由与开启后的原有原子扣分逻辑，查询、签到、邀请、已有积分与 Pro 权益不变，兑换码仍按原流程处理。开启该开关需要再次授权，本批不修改任何云端配置。

## Alternatives considered

- **只隐藏前端入口**。最强理由是范围小，不影响服务端及历史记录。未采用：旧页面和直接 API 调用仍可兑换，已被真实流水证实。
- **删除兑换接口和服务实现**。最强理由是完全移除能力，后续没有误开启配置的风险。未采用：本次授权是关闭线上渠道，默认关闭的服务端检查足以阻断，保留实现便于单独授权后的恢复，也保留旧客户端明确的失败响应。
- **默认开启，只在生产环境设置关闭**。最强理由是现有本地测试和其他环境不必修改。未采用：漏配或新建环境会重新放开，关闭不应依赖额外云端操作。

## Consequences

积分足够的免费账号不能开通 Pro，已有 Pro 账号不能通过积分续期；拒绝不改变积分流水、订阅、配额或订阅历史。已有的开启路径测试需局部显式开启，默认关闭回归独立检查缺省和 false。再次开放需要单独授权并显式设置开关。

先添加默认关闭回归，旧实现对缺省开关的足额账号返回 200、扣 100 积分开通 7 天 Pro，红测复现。实现后，本地 SQLite 下积分 API、积分服务、默认关闭回归、积分端到端契约与 ledger worker 共 111 个测试通过；相关后端 ruff 与 `git diff --check` 通过。默认关闭回归覆盖缺省/false、7/14/30 天、免费/已有 Pro 账号，逐字段比较持久化积分流水、订阅、配额及订阅历史，另检查匿名请求仍为 401。这是本地实现证据，线上生效须在最终 main SHA 的 CI/E2E 通过并授权发布后，分别核对 provider 来源与运行行为。
