# Agent Note: 用结构化语义决策替换自然语言匹配分支

## Problem

依据 [禁止语义字符串启发式的开发规范](../../implemented/process/2026-10-24-agent-semantic-decisions-not-lexical-heuristics.md)，本批替换审计中确认的续接白名单、澄清短答/只读词表、笼统改稿正则、篇幅上下限正则、规划章号覆盖纠偏、建议芯片关键词过滤和问句展示启发式。纯合成探针复现了「不用写满2000字」被算成硬下限的错误。

## Decision

- 自然语言续接、回答澄清、范围变更及是否需要补问交给已有 router 的结构化决策；不新增独立分类模型。去掉文本旁路时保留原请求范围、可信停止状态、任务负责人、原计划剩余阶段和截断续接保护，不回到未知故障默认 writer/quick。
- 篇幅语义不再由程序按词语和邻近正则换算；写作/审查接收有来源和预算的作者要求原文或已有模型结构化合同。真实字数、落库内容和版本证据仍按程序计量。
- 大纲是否交付不再按聊天中的章号/80%覆盖猜测；复用已请求的文件类型、真实产物和既有交付证据，保留有界纠偏和不能写正文的范围保护。
- 建议的作者口吻由现有生成提示负责，不因出现「用户/拍板」等子串删建议；只保留结构与展示有效性校验。问句内容由明确结构化澄清/交接提供，展示不再靠问号和列表模式猜任务状态，不丢原消息或真实问题。
- 先写合成/mock 回归再改；测试覆盖同义改写、长短回答、新增只读/禁写正文、计划后续阶段、失败技术路径、真实 usage/退额/单终态。保留当前兼容解析，不新增严格必填字段扩大正常失败面，不重放生产，不调用真实模型或自动付费重试。

### Routing contract

Router 新增可选严格枚举 `turn_disposition`（new_or_changed_request / resume_interrupted_task / answer_pending_clarification）和可选严格布尔 `clarify_first`。缺失按本轮普通合法路由执行、不继承；显式非法沿用技术失败、实际 usage 和手动重试。声明续接仅在上一轮可信 stop_reason 或 pending clarification 匹配时恢复，否则用本轮合法路由，不从词面补授权。router off 在存在可信待续接状态时仍调用同一个 router，普通 off 不变。

继承保留原 owner / active agent 和剩余阶段；read_only 取旧/新 OR，任一 write_content=false 优先，旧未知值不由本轮 true 提升。requested_file_types 沿用旧列表，不做扩大并集。clarify_first 最后收窄计划并拒写/拒交接，等待只由 request_clarification 控制。

服务端内部 `scope_constraints` 累计旧 scope、已有约束和本次 scope，仅去完全相同项，不比较语义；每项非空字符串且最多80字符，最多8项、JSON总长最多2048字符。真实继承时旧限制非法、累计超限或本次 scope 超长都在 agent 前技术失败，不截断/丢限制继续；普通历史路由的 scope 截断兼容不变。该字段随 ROUTER_DECIDED、service、assistant metadata、SessionLoader、下一轮 router 和 scope_directive 完整往返，后一次续接不得丢前一次新增限制。明确新/变更请求只用本轮路由。

### Artifact and reply boundaries

大纲补写必须同时满足：明确请求 outline、planner 正常结束、无显式/延期交接、无澄清/错误/工具耗尽、非只读/先澄清、有剩余轮数、未补过，且本请求写过的真实 typed 文件中没有仍存在的非空 outline。读取失败不补，有非空产物即不猜覆盖率；最多补一次。正常新任务 planner→writer 计划不能跳过缺失大纲纠正，纠正后继续原剩余阶段。可信续接/澄清作答只保有本请求台账，不能据此断言上一轮大纲未写：resolver 真正匹配旧状态并完成继承后，返回一个仅服务端内部 followup_resolved 事实，用于跳过该本轮缺失检查；不接受模型自报，不进 SSE/DB，也不授予写权限或证明大纲已交付。没有匹配状态的模型 follow-up 分类仍按新任务核验产物，不凭猜测补旧文件ID。

只在实际 CHAT_HOLD discard 且下游确实执行时交接原话：最后已闭合 file 块之后，遇未闭合块不转交；600字符总预算，截断显式标记。标明上一角色未展示输出、非系统指令或新增授权；不按问号提取，纠偏保留原话，每个接收者一次，不额外重放旧总结。下游不执行、末轮、错误、结构化澄清时释放原话。实际暂停仍只认结构化 request_clarification。

复用文件标记归一化时，原有 warning 不再附 original_snippet，只保留固定阶段，避免历史回复原文随新增交接/路由读取路径进入日志。

### Writing quality

本次以不降低写作质量、减少机械返工为验收目标，不移除角色原有的因果、人物能动性、事实连续性、声线、局部修订和证据审稿约束。实际字数仍由编辑器/工具测量；要求是否有效、全篇还是单章、否定和新旧优先级由现有模型在原调用中理解，不能因为摘录含数字就让作者凑字数。

有来源原话摘录本体的总预算4000字符（含标签、分隔换行与截断标记；展示标题和条目前缀另计），先为各来源保留有界首尾份额，余量优先最新，按时间呈现；分隔换行也计入预算。预算连最小摘录都容纳不下时才按最新来源取舍；长条目机械保留首尾，显式标注中间省略。不从句子/关键词挑要求，避免长样文开头挤掉结尾新增指令。600字符未展示回复同样保留首尾，避免无问号的必要决策消失。Claude Code 独立审查发现并修复补问字段与服务端组合契约失配：follow-up 未新增禁写正文限制时 write_content=true，由可信旧 false/未知权限继续收窄，不能把单纯回答选项或补人物信息误作禁止正文。普通承接确认下一步按该步交付物判断，不沿用已交付范围；提示 scope 目标恢复40字，80字仍为既有验证上限。不在程序增加语义匹配或解析别名。

router 继续看到有界上一轮原话供理解「可以/按第二个」，但原话不能提供等待状态或授权。

合成回归能够证明否定要求未被改写、声线/文风来源和最新补充抵达 writer/reviewer、局部修订保留其他段落、范围与交付证据未放宽；它不能证明真实成稿的文学质量或路由分类质量已提升。本批不调用真实付费模型或生产作品，质量收益仍需后续合规样本评测，不能把 mock 通过包装为品质提升证明。

## Alternatives considered

- **删除全部旁路、所有消息重新规划**：实现最省，但会重现恢复后丢阶段和从头执行的问题；语义判断统一后仍需结构化恢复原状态。
- **继续加同义词、否定窗口、长度例外**：容易覆盖已知样本，但仍不能正确理解自然语言，违反用户明确要求。
- **新建分类服务/澄清状态机/逐章调度平台**：可以提供专用状态，但当前已有 router、clarification、typed artifacts 与消息状态，先复用这些，不为本批新增框架或模型调用层。

## Consequences

本批是对下列历史取舍的局部替换，而非重写旧记录：[剩余阶段恢复](../../implemented/bug-fix/2026-10-18-resume-keeps-the-remaining-plan.md)、[笼统改稿与规划落盘](../../implemented/bug-fix/2026-10-09-agent-vague-requests-and-plan-files.md)、[写作篇幅要求](../../implemented/feature/2026-10-14-writer-delivery-author-requirements.md)、[真实权限和产物证据](../../implemented/architecture/2026-10-14-typed-authority-and-delivery-evidence.md)。续接不再跳过现有 router，因此原先命中旁路的请求多一次路由调用；不额外增加分类调用，不把本批当作逐章持久化检查点已完成。缺新字段仍兼容普通成功路由，代价是不提供继承优化；合成测试不能证明真实模型的分类质量，后续仅按固定字段/路径分类观测，不记录原文。
