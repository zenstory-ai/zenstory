# Agent Note: 页面刷新前同步保留未保存正文

Status: implemented

## Problem

Vite 在发布后遇到旧 chunk 会触发 `vite:preloadError`，现有恢复逻辑直接刷新页面；用户主动刷新也会经过同一风险窗口。正文编辑器只在停止输入 3 秒后异步自动保存，卸载时的保存同样是异步请求；用户刚输入的标题或正文可能在刷新时丢失。`beforeunload` 网络请求无法为硬刷新提供可靠写入保证。

## Decision

- `chunkRecovery` 把 `vite:preloadError` 作为 Vite 的权威 chunk 失败信号，不依赖浏览器 payload 文案；它先派发可取消的 `zenstory:before-chunk-reload`，只有同步快照成功后才设置 once guard、pending 状态并调用 `location.reload()`。快照失败时保留原始 Vite 错误给错误边界处理，不把页面刷新掉。泛用 promise rejection 仍只按已知 chunk 错误文案触发。
- `SimpleEditor` 只在 dirty 时响应 chunk 事件以及普通 `beforeunload`/`pagehide`，把最新 `draftRef` 同步写入 localStorage，不发网络请求。一次退出只写一份快照，避免 chunk 捕获后又被 unload 改写捕获时间；正常写入成功不弹提示，只有 `beforeunload` 写入失败时请求浏览器原生离开确认，让用户选择留在页面。快照按 `AuthContext` 的当前用户、项目、文件隔离，包含 schema、标题、正文、`baseUpdatedAt`、捕获时间和原因。恢复后的内容保持 dirty，用户再次编辑或明确保存前不自动 PUT。
- `Editor` 在服务器文件加载后读取对应快照：标题和正文已相同时清理；`baseUpdatedAt` 精确相同时恢复本地 dirty 内容；令牌不同或缺失时先显示服务器正文，通过只在冲突时出现的提示提供版本比较、恢复本地草稿和保留服务器版本三个明确动作。不会把缺失令牌当成相等。
- 只有服务器已与快照相同、用户显式保留服务器版本，或已应用恢复内容后的任意最新 submission 成功保存且本地删除成功后才清理恢复状态。未应用的冲突、409、普通失败和本地删除失败都保留快照。localStorage 损坏、不可用或配额不足时不阻止编辑器加载，也不宣称草稿已受保护。
- Vitest 固定同步捕获、捕获失败阻止 chunk 刷新、普通刷新捕获、身份隔离、损坏存储、恢复判定、自动保存抑制、恢复后继续编辑成功清理、409 保留、显式丢弃后的单侧编辑和原有编辑器生命周期；mocked Playwright 固定普通刷新在防抖窗口内恢复，以及用户先查看服务器版本、比较、恢复、继续编辑、确认无自动 PUT，再手动保存的完整路径。

## Alternatives considered

- **依靠现有 3 秒自动保存和组件卸载保存。** 最强理由：没有新增本地状态，正常保存路径已经成熟。被否：刷新会终止异步请求，恰好在防抖窗口内的最新输入没有任何可靠副本。
- **刷新后直接把本地快照写回服务器。** 最强理由：用户无需额外操作即可继续。被否：旧页面的并发令牌可能已经落后，自动 PUT 会与 AI、其他标签页或其他设备的新版本冲突；令牌不同时必须先比较。
- **把所有编辑持续写入 localStorage。** 最强理由：也能覆盖浏览器崩溃等更多场景。被否：扩大了持久化范围、写入频率和隐私面；本批只在已知页面退出信号到达时同步留副本。

## Consequences

- 收益：旧 chunk 自动刷新和用户普通刷新前，dirty 正文有同步、身份隔离的本地副本；恢复不会自动覆盖服务器的新版本；存储损坏或不可用不会阻止编辑器加载，旧 chunk 捕获失败时也不会继续执行会丢稿的自动刷新。
- 代价：localStorage 不可用或配额已满时仍无法保证普通刷新前保存，因此界面不会在捕获阶段宣称已保护；并发令牌不一致时用户需要完成一次比较或显式丢弃。这是刷新恢复保护，不是通用离线编辑系统。
