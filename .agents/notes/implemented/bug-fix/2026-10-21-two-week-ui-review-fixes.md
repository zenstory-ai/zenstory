# Agent Note: 近两周前端改动的 UI/UX 审查与修复

Status: implemented

## Problem

按 DESIGN.md 审查 2026-10-07 以来的前端改动（管理后台与登录注册、工作台与计费、项目工作区三块），发现一批共性问题：浅色模式下状态文字直接用原始 `--warning/--success/--error`（只为深色调过，浅色只有 1.6–2.8:1）；手机上大量按钮不足 44px、旧 `.btn` 类与 `ui/Button` 混用；错误状态没有 `role="alert"` 或没有重试，部分加载失败会显示成「未开通」「还没有项目」「暂无数据」或 0；图标按钮缺少可读名称，悬停才出现的操作对键盘和触屏不可见；几个对话框有多层滚动；时间窗口选择器样式不一；英文界面出现全角括号；统计图标签直接显示服务端英文字符串。

## Decision

- 全站状态文字统一改用 `--success-text/--warning-text/--error-text`（深色模式取值不变），淡色背景仍用原始色。
- 修复按区域分批提交：管理后台（共享 `AdminSegmented` 时间窗口、北京时间显示、可滚动表格区域、各小节独立重试）、更新提示卡（44px 按钮、可见的「稍后」、避开底部导航与 toast）、注册（邀请码展开后聚焦、自绘邮箱补全）、工作区（停止按钮配色、错误卡片语义、触屏尺寸、文件树键盘操作、历史对话框单一滚动区）、计费与工作台（各卡片独立的加载与错误、首页加载失败不再显示为空、删除确认加载态、日期统一北京时间、价格页标题不跳动）。
- 每组都跑了受影响的单测；涉及行为（加载/错误态、标签、日期）的补了回归测试。

## Alternatives considered

- **把原始状态色在浅色模式改深。** 最强理由：一处改动覆盖全部。被否：同一变量还用于淡色背景和边框，改深会让所有提示底色变脏；按 DESIGN 约定区分「文字色」与「底色」更稳。
- **只修本批新增代码。** 最强理由：范围小、风险低。被否：问题集中在近两周多人改动的公共位置，留着会继续被复制。

## Consequences

- 收益：浅色模式状态文字达到 AA，手机操作目标与焦点可见性统一，加载失败不再被误读为空数据。
- 代价：未在真实后端数据下逐页截图验证；文件树有 tree 语义但还没有方向键导航（Tab + Enter/Space 可用），作为后续改进。
