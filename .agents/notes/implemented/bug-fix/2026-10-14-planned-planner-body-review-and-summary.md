# Planned planner body delivery uses the existing review gate and summary hold

## Problem

预发布合成创作复验中，质量模式计划为 planner→writer。planner 已创建大纲和五章正文，随后 writer 只读取五章、向第五章补了 81 字。自动质检门只计 writer 自己这程的写入，漏掉 planner 已完成的正文，因而没有 quality_reviewer；作者同时看到 planner 和 writer 对同一范围的两份交付总结。

这是已有[正文计量与单份总结](2026-10-11-author-reply-single-summary-and-real-word-counts.md)的交接缺口。事实连续性问题仍需模型效果验收，触发送审本身不证明稿件质量已经改善。

## Decision

- 只对作者明确要正文、质量门可用、当前 planner 的计划下一位为 writer 的路径，复用 `BodyWriteTracker` 观察成功正文写入。真正还有协作轮次并交给该 writer 后，复用已有接续列表携带正文记录，不携带 planner 的整段对话。writer 结束时按原 500 字门槛、原审查轮数上限决定自动送审。
- 不扩大计量对象：仍只算 draft / script 的实际新增、替换文字；大纲、规划说明、失败写入不算。快速模式、只读请求、只做规划、非计划交接和审稿返修不由此增加送审。
- 同一路径复用内部 `CHAT_HOLD`。planner 成功写正文后先扣对话、正文照常流式落库；实际交给 writer、其正文已达到送审门槛且没有收尾问题时，丢弃被后续总结取代的对话。低于门槛的说明保留，避免 writer 只核对、不发聊天时没有任何交付说明；这些正文记录仍接续，后续补写合计达到门槛仍可送审。没有执行交接、发生停止或仍向作者提问时，按适配器既有边界原样释放。是否向作者提问沿用已有判断，不识别或改写总结内容。
- writer 收到的接续正文已达到门槛时，在开始这程输出前扣留对话。即使它只读稿或补很少文字，真正送审时仍沿现有分支丢弃总结；不能送审时原样释放。
- writer 没有聊天输出但有正文记录时，仍执行原送审输入读取，附当前落库正文、字数和作者篇幅要求，沿用既有读取预算与回退规则。
- 当前正文读取失败或超时后，原输出只作为创作片段；已有交接内容标明未读取，并列本请求实际写过的文件 ID，要求审稿人在当前轮用 `query_files` 读取现稿后再判断或总结，不把原输出当最新落库版本，也不增加审稿轮次。
- 没有新增角色、持久状态、写权限、模型重试或审查循环。
- 基于 `acc78a11` 整合时保留结构化 `request_clarification`、typed 交付证据和 `requested_file_types` 控制。问句只影响是否保留作者可见说明，不恢复用标点阻断交接的旧路径；备注确认沿用已实施的 [typed authority 边界](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md)，本补丁不包含旧的聊天编号升格改动。
- 后续角色收到的手改保护拒绝记录明确引导作者通过现有文件菜单删除，不再承诺再次聊天同意可以解除删除或同名覆写保护；不把普通 `edit_file` 文本修改描述为一律禁止。

## Alternatives considered

- **让 planner 只能写大纲。** 优点是职责清楚，质检永远只需看 writer。未选：现有 planner 有正文写权限，收窄权限会改变所有工作流，并迫使已完成的稿件重新经过写入步骤。
- **所有角色的正文写入全局累计后统一送审。** 优点是覆盖更多混合交付。未选：会将不同交接范围、返修和非计划路径混在一起；本次只接续明确的 planner→writer 交付。
- **只提示 planner 少写总结或让 writer 主动送审。** 优点是无需图的改动。未选：不能保证实际已写正文进入质量门，也不能避免模型仍写两份总结。

## Consequences

计划内上游已写好的正文不会因 writer 只做小修而漏审，作者通常只看到最后一份交付总结。规划师说明可能延后到交接判定才出现；其收尾有问题时仍原样释放，因此该路径可能保留多段说明。既有停止时扣留文字的处理、正文持久化、配额和取消记账均不变。

真实 graph 与 StreamAdapter 回归覆盖五章正文→writer 补 81 字或只核对→审稿，以及正文逐份保存不变；数据库回归核对 writer 无聊天时的当前正文输入。反例覆盖大纲、失败写入、非计划交接、关闭质量门、只做规划、只读、剩余轮次不足和收尾提问；100 字正文后 writer 无聊天时保留说明，100+200 字保留 writer 最终回复，100+450 字合计送审且扣掉 writer 总结、保留 planner 小额说明，writer 提前出错时释放已有部分交付说明。真实模型的语义质量由预发布复验单独确认。

整合最新 main 后，六项回归在 main 实现上先失败：规划师正文接续的两种 writer 行为、无聊天送审正文、已写正文后结构化澄清／工具预算终止的扣留释放，以及拒绝反馈的真实后续角色输入。新增快速模式反例，保留现有结构化等待与返工上限测试；这不是新增审查轮数或停止／退款机制。
另以 writer 有聊天／无聊天两种真实图路径回归先复现读失败时缺少现稿读取指引，再验证精确文件 ID 与来源边界进入 reviewer 实际输入。

本批基于最新 main 的定向验证：`test_author_reply_shaping.py`、`test_thinking_loop_triggers.py`、`test_writing_graph.py` 和 `test_structured_control_boundaries.py` 共 102 项通过；修改的图与测试通过 Ruff、差异空白检查。尚未进行本批真实模型预发布复验，因此这里只确认确定性执行与输入契约，不宣称已消除全部连续性或总结质量问题。
