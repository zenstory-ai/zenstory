# 多文件送审保留逐文件证据

关联：[长旧稿送审只附改动段](2026-10-11-thinking-loop-contradictory-inputs.md)。本条调整多文件预算分配，保留旧稿改动段策略。

## Problem

#180 的输入检查发现，最新落库正文按文件拼接后统一保留 9000 字符的头尾，中间章节可能整份消失。各文件标题与字数清单不能说明哪些正文缺失，也没有将落库版本与精确读取入口绑定。长旧稿的改动段只在单文件超过总预算时选取，多文件合计超预算时仍可能漏掉中段修改。

## Decision

保留现有 9000 字符预算和落库读取入口，在拼接前按文件分配正文预算。每块标明文件 ID、updated_at 和精确读取入口，先按该文件预算选取本请求改动及邻接上下文，再截断该块；省略标记也占用预算。不增加模型调用、持久化事实实体或用户界面。读取失败路径仍需真实效果验收，不把输入修复说成语义连续性已解决。

## Alternatives considered

- 提高总预算能直接容纳更多正文，但批量足够大时仍丢中间文件，也增加每次模型输入；本次优先保留每份文件的身份、覆盖范围与读取方式。
- 全部正文交给模型工具读取最简单，但会让已有短稿也重复读取；继续直接提供可容纳的全文。

## Consequences

多章/多集均能获得预算内的直接正文或改动片段，未附部分可按 ID 读取。单份长稿仍可能需要进一步读取；这不保证模型一定发现事实错误。统计与行为测试仅证明输入覆盖，不代替真实模型效果验证。

## Verification

新增三个回归在修改前失败，修复后与既有送审/长稿改动/落库引号回归合计 31 项通过；Ruff 与 diff 检查通过。五份合计超预算的新稿仍逐份保留开头、结尾、文件 ID 和 updated_at；三份旧稿保留各自中段的局部修改；省略标记也计入 9000 字符预算。本地使用合成 SQLite 与 mock 模型，不据此声明语义连续性通过。
