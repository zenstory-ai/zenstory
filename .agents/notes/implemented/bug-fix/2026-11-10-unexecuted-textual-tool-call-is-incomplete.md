# Bug-fix Note: 写成文字、没有执行的工具调用如实记为未完成

Status: implemented

关联：[类型化的权限与交付证据](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md)（交付只来自实际执行的证据）、[正常收尾也给出写入回执](../feature/2026-10-18-completed-round-write-receipt.md)、[未闭合的文件块不是正文](2026-06-21-unterminated-file-block-is-not-prose.md)。

## Problem

模型偶尔把一次工具调用写成回复文字，而不是发出结构化的 tool call。这段文字原样显示、保存，那次调用并没有执行。如果同一轮里别的写入成功了，或者路由没有要求写正文，这一轮会被记为正常完成，作者看不出有一步其实没做。模型适配层只读结构化的 `delta.tool_calls`，仓库里也没有对这类文字做任何识别。

匿名样本里有几种形态：完整的调用结构、只有开头或只有结尾的残片、模仿历史面包屑的文字，以及文件结尾字面的 `</content>`。导出正文有截断，完整结构的数量无法从样本复算。

## Decision

- **识别范围**：`completion_evidence.unexecuted_tool_protocol` 只认样本里出现过的完整结构：成对的 `<tool_call>` … `</tool_call>`，里面至少有一个 `<invoke name="…">` … `</invoke>`，其间可能夹着模型专用分隔符；工具名必须属于当前 agent 在 registry 里实际注册的工具。以下内容不算：
  - `<file>` 正文（含未闭合到结尾的）、代码围栏、行内代码、Markdown 引用行；
  - 残片、没有外层 `<tool_call>` 的 invoke、未注册的工具名、普通叙述里提到工具名；
  - 单独的 `</content>`、面包屑标头。

  其他写法暂不支持，宁可漏报也不扩大词表。
- **检查时机**：图层在 agent run 正常结束后，只检查最后一次真实工具事件之后的尾段文字（`agent_tail_text`，遇到 TOOL_USE/TOOL_RESULT 即清空），所以命中的调用一定没有执行。另外要求当前角色有写文件工具，且本轮不是只读或先问清楚；同一请求最多标记一次。
- **记录方式**：命中时发一张 `iteration_exhausted`，layer 为 `unexecuted_tool_text`，不带 `limit`、`last_agent` 为空，所以不改 `stop_reason`，也不给“继续”提供路由线索。同时记一行 WARNING `textual_tool_call`，只写 agent 类型、次数和白名单内的工具名，不写参数和正文。`RoundWrittenFiles` 把它记为请求级的粘性事实，并入 `known_incomplete`，现有终态如实记为未完成（`done.delivery_incomplete`、`stop_outcome.reason=incomplete`）。
- **不做的事**：不改写、不删除这段文字（逐字节原样流出和保存），不把文字当工具执行，不自动重试或续跑，不改计费或退款（这个 layer 不属于失控停止，仍按原规则计入）。
- **前端**：卡片显示中性说明（“有一步没有执行……相关文件没有因此新建或修改”），不显示“继续完成/拆分”等下一步按钮。刷新后从 status_cards 恢复同一张卡。

## Alternatives considered

- **流式过程中或落库前清理协议文字。** 最强理由是作者不用看到乱码。未采用于本批：识别不了的写法会被半截清理；作者询问工具语法、正文或示例里出现同形文字时会误删；而且清理掉文字，作者就更看不出这一步没做。只做标记时，误报的代价只是多一张说明卡。
- **把识别出的调用当作工具执行。** 最强理由是作者要的东西能直接做成。未采用：会绕过参数校验、写锁和权限核验，模型之后再发真实调用时还会重复写入。
- **检测到后自动开一轮纠偏或重试。** 最强理由是不需要作者再说一遍。未采用：这是一次付费模型调用，需要 owner 另行决定。
- **用更宽的模式（单个标签、任意 invoke、模型名分隔符）提高召回。** 最强理由是能覆盖残片。未采用：残片没有结构依据证明“有一步计划没执行”，会把正常文字误判为失败。

## Consequences

- 写成文字的完整调用不会再被当作成功交付，作者在当场和刷新后都能看到“有一步没有执行”，这一轮记为未完成。
- 计费不变：这一轮仍按原规则计入；是否因此退款或补偿，另行决定。
- 召回有限：残片、其他写法、真实调用之前出现的协议文字都识别不到。外泄文字仍会显示并进入后续历史回放，可能被模型仿写；清理、面包屑仿写和文件尾 `</content>` 留作后续单独处理。
- 前端部署先于后端时没有影响；后端先于前端时，旧前端会把未知 layer 显示成通用的“先做到这里”卡，直到前端更新。
