# 自然润色先匹配原文整行，再兼容空白和引号差异

## Problem

[最初的行级协议](2026-10-09-natural-polish-cost-noop-and-format.md)用去空白、统一引号后的内容定位原行；[严格协议决策](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md)要求多义锚点失败，避免改错稿件。两者组合使合法选文也可能失败：两行只有内部空格或引号体例不同，模型逐字抄对其中一行，服务端仍会把两行当成多义；模型分别修改这两行时，按规范化内容去重也会误拒。

本地离线复现已确认两种问题，不据此认定它们就是历史线上单次 500 的根因；该请求的原始输出没有留存。

协议允许标记后有一个可选 ASCII 空格，解析器会移除它。若把段首空白当作身份，原文四空格缩进的合法锚点可能被读成三空格，从而误改另一行。因此边界空白只能作为原稿格式保留，不能用来区分同正文的两行。

## Decision

- 完整原行先去掉边界空白，再按其余内容逐字相等定位，内部空白与引号体例仍区分；没有匹配时，才使用既有空白、引号规范化兼容。
- 完整行匹配和去重按实际原行判断。真正重复、仅边界空白不同的原行、多义的规范化匹配和重复修改同一原行仍失败。唯一原行的缩进与尾空白继续由格式守卫按原样恢复。
- 子串替换保留原有唯一性、去重和同一行多个不同子串的支持。提示词、模型参数、格式与句子守卫、无改动和错误退款路径均不改。

## Alternatives considered

- 只加强提示词：不增加执行逻辑，但模型已经逐字给出唯一原行，无法修复服务端把不同原行合成同一锚点的问题，因此不采用。
- 只做逐字匹配、删除规范化兼容：定位规则最少，但会使原本可接受的缩进或引号差异失败，因此保留唯一的兼容匹配。
- 给协议加行号：可以区分完全相同的重复原行，但需要修改提示和模型输出协议；本次只修已可唯一定位却被误拒的情况，因此不扩展协议。
- 复用现有 JSON repair 恢复失败输出：仓库已有依赖，素材拆解也用它免调用模型修复未转义引号。但自然润色的原改行对不是 JSON，修复器不能消除原文定位歧义；对缺少新值的 JSON，它还可能补出空串，而本协议的空串代表删除。因此本次不增加第二套 JSON 编辑协议，也不修补 SDK 的上游 HTTP JSON envelope，避免猜测 `usage`、`finish_reason` 或传输完整性。素材拆解已有的 JSON repair 保持原有作用。

## Consequences

合法的完整行对不会因其他原行只差内部空白或引号而失败；无法唯一定位的输出仍走既有失败和补偿路径，不猜测改哪一行。仅缩进或尾空白不同的同正文行仍无法区分，需要拒绝。无需新依赖、客户端协议或数据库迁移，也不增加模型调用。

回归先在原实现复现四个失败场景：空白、引号两类选文，各自只改一行或同时改两行。独立复核再发现并复现可选空格导致的缩进误定位，以及尾空白不能作为行身份的边界。实现后服务与 API 的 66 项离线测试、受影响文件 Ruff 和 diff 检查通过；同时验证唯一规范化兼容、唯一原行的边界格式保留、拒绝真正多义和重复行、同一行多个子串修改及既有格式和退款路径。测试使用合成文本、mock 模型和本地临时数据库；未调用真实模型，也未据此宣称历史线上单次 500 的根因已唯一确认。
