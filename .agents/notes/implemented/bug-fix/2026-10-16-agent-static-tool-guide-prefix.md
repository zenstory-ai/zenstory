# Agent Note: 完整工具协议先于项目目录映射

## Problem

[项目 ID 后置](../../implemented/bug-fix/2026-10-16-agent-shared-prompt-prefix.md) 已使共用执行协议进入稳定前缀，但工具指南中间的目录 UUID 仍把后面的流式写入、标题与交互规则挡在跨项目公共前缀之外。继续降本的约束是不削弱写作质量、权限、保存和质检。

## Decision

- 只将 `get_tool_usage_guide` 中完整的「创建文件时的 parent_id」小节移到同一指南末尾，保留所有文字、真实目录映射与映射顺序；未移动其他项目配置、角色或动态上下文。
- 先补回归，确认原实现不能让完整固定工具协议进入跨项目公共前缀，再移动小节；保留项目与目录隔离，覆盖六类单目录、空目录、乱序混合子集和全量目录。
- 独立对比 Git 基线与修改后的组装结果：九组目录输入中，排除被移动的完整小节后逐字节一致，工具指南及基础提示总字节长度不变；不新增锁死全部写作规则的哈希快照测试。
- 不改模型、推理强度、输出/上下文预算、路由、自动质检、计费或退款；不调用付费模型，不修改数据库或生产配置，不自动发布。

## Alternatives considered

- **保持现状。** 无需改变提示顺序，没有新增模型行为风险；未采用，因为目录参数不必夹在固定工具协议中间，可以在同一指南内集中保留。
- **把所有动态段移到基础提示末尾，或把角色规则前移。** 可形成更长前缀；本轮不采用，因为会改变数据库写作配置、角色与项目事实的相对位置，质量风险和验证面明显更大。
- **降低推理、输出上限或减少质检。** 可直接减少部分输出或调用；本轮不采用，因为现有账本不能区分必要正文与可避免推理，尚无质量对比依据。

## Consequences

固定工具协议可被不同项目共同匹配，不新增缓存层或依赖。小节顺序变化仍可能影响模型注意力，结构性回归不能证明真实生成完全不变；实际命中与节省只能在另行授权发布后，按相同负载的真实 usage 观察，不把字符前缀增长宣称为 token 命中或节省金额。

## Verification

- 新缓存前缀回归在原实现失败，目录映射等既有约束仍通过：`1 failed, 10 passed`；补充混合子集后最终提示回归为 `12 passed`。
- 提示组装、数据库配置来源、目录解析、语言、项目权限、技能、写作协议、角色、流式输出和历史相关测试共 `80 passed`，不调用付费模型。
- `ruff check agent/ api/ services/ tests/test_agent/test_prompt_alignment.py` 与 `git diff --check` 通过。
- 同配置、独立项目与目录 UUID 的离线合成样本，公共字符前缀从 `8,000` 增至 `10,458`；九组输入的非映射正文逐字节相同，完整指南和基础提示等长。这不是 tokenizer token 数或线上成本结果。
- 原有模型、推理、输出/上下文预算、路由、质检、权限、计费与退款路径未修改。尚未执行 staging 真实生成质量对比，也未发布生产，因此不声称线上质量或节省已验证。
