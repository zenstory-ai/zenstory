# 部分交付复用回合结尾说明，并以实际保存回执为准

## Problem

#183 的 A03 现场创建了五份角色文件，其中一份没有正文；上游报错后作者需要逐份打开才能知道写到了哪里。绿色 create_file 卡片准确表示文件壳已创建，不证明正文完成。[隐藏错误态下一步卡片](2026-10-14-next-step-card-hides-on-stream-error.md) 已去掉「框架已就绪」的冲突提示，本决定补齐剩余的本轮交付事实。

既有 RoundWrittenFiles、RunOutcome 和 message_metadata.stop_outcome 已能在作者停止、断线与刷新后说明已保存文件；但普通错误没有这份说明，流式 chunk 或 file_content_end 也不能证明数据库保存成功。正常 done 若留下新建空壳，同样缺少可供作者继续的事实。

## Decision

复用现有回合回执与 RoundEndNote，不增加实体、进度面板、模型循环或自动重发。StreamAdapter 记录真正完成的保存结果，AgentService 在交出错误或最终消息 id 前将其交给 RunOutcome；部分历史的补存也交回实际消息 id。保存失败且从未成功时记录未确认写入，最后一次失败保留之前已经成功保存的正文回执，后续成功则更新字数。

RoundWrittenFiles 用成功的带正文 create_file、实际 edit_file 或流式保存回执确认已写文件。本轮新建、非文件夹、非复用、未删除的空壳，在终态仍没有确认写入时列为「未确认保存」。不改变创建卡片、不对生成中的空壳告警，不把既有空文件推定成这轮未交付。

普通 error 保留原错误码、重试操作与终态，在同一错误说明里附上已保存和未确认保存的文件。刷新后的历史从同一份 stop_outcome 展示相同事实。正常 done 只有仍含新建空壳时才复用简短结尾说明；完整成功不增加提示。保存超时的后台线程可能随后提交，因此剩余项使用「未确认保存」，不把缺少回执说成确定未写入；不额外查询数据库。删除通过真实 tool_call 的调用 ID 与参数关联 data:true 成功结果。停止与断线复用相同文件口径，保留原来的计额、退款、空壳移除、编辑器保护及可继续原因。硬时限仍优先及时交出错误，不把尚在后台保存的正文提前判成未写入。

（2026-10-25 补，审计 F-02/F-03）停止与断线确实用同一份回执（`RoundWrittenFiles.stopped_delivery`）：实时 `done` 和落库的 `stop_outcome` 都保留未确认保存的新建文件。此前一份文件都没写成时会把整个 `unwritten_files` 丢掉，再用流式帧口径的 `write_succeeded` 写 `saved_output=true`，补存失败或超时后作者仍看到「已写入的内容已保存」。现在只少两类空壳：退还时真正移除了的，以及一份都没写成时本轮没往里写过正文（没有流式正文、也没有补存）的空壳。作者可见的 `saved_output` 只由确认写入推出：有确认写入的文件即为真；列不出文件的写入（并行写章、删除）沿用计费口径，但本轮只要有流式正文缺确认回执就为假。计费与退款仍按 `StreamBillingTracker` 的帧口径，不变。退还后移除空白占位前先等残稿补存落定（见 [停止与产出定义](../architecture/2026-10-09-stop-output-definition-and-round-outcome.md)）。

中文用「已保存《文件》字数 · 未确认保存《文件》」，英文用现有 Saved 格式及 Save not confirmed。最多具名三份，其余沿用既有数量缩写。没有机械要求作者补齐框架，作者仍可打开文件、输入或自行继续。

## Alternatives considered

- **只补提示词，让模型自行说明部分完成。** 能沿用自然语言总结；但上游错误可能没有最后一条模型回复，且模型不知道最后的数据库保存结果，因此不能作为此事实来源。
- **把初始空壳标红或提高 framework_ready 门槛。** 能更早提示缺失；但正常生成先建壳后写正文，作者也可手动建立框架，会把有效中间态当作失败。本次只在终态附事实。
- **新增独立进度状态、查询或持久化表。** 能扩展成完整任务进度；但现有保存回执和 stop_outcome 足够承载本轮事实，另建状态会增加实时与历史口径漂移的机会。
- **要求模型自动补齐所有空壳。** 有机会减少不完整产物；但会增加模型调用、费用和取消边界，也会越过作者自行继续的选择，不属于本次准确说明范围。

## Consequences

作者在错误当场和刷新后可以看见已保存与尚未确认保存的文件，正常完整交付保持原界面。代价是现有可选回执增加两个终止原因和未确认保存列表；旧客户端会忽略可选字段，旧历史仍按原格式读取。该说明只陈述本轮有证据的文件写入，不宣称正文质量、所有请求目标完成或并行子任务的逐文件明细。
