# 写作核心前提、成稿事实与局部风格范围

## Problem

wave2 隔离合成数据真实模型验证中，短篇把作者指定的同一物件换成两件，物件流转时间矛盾；连载返修后大纲与正文状态分叉。局部改写还把一次编辑要求写进全局 writing_style；停止后要求保留已存部分的续写回头改了旧段落。工具成功并不证明内容或持久化范围符合要求。关联 [作者交付要求](../feature/2026-10-14-writer-delivery-author-requirements.md)、[核对当前版本](2026-10-12-review-current-version-before-other-chapter-claims.md)。

## Decision

在已有共享交付规则中明确保留核心命题的实体身份和时序，核对最终正文与本轮获准写作的大纲、完成说明；历史章节冲突不扩大改动，也不虚称定稿。planner 按作者要求交付简短分章/分集大纲，不顺带补额外核心文档。writing_style 只持久化持续沿用的偏好，单次局部编辑要求只约束该次编辑。作者要求保留已保存的未完稿时仅末尾追加，新要求冲突先说明，不自行回改旧稿。保持现有模型理解及工具权限，不新增分类器、词表、完成打分或审稿轮次。

## Alternatives considered

- 程序提取人物、物件及时间做硬性校验：可拒绝可结构化的冲突，但开放写作难以可靠识别同一实体，且需要新分类链；不采用。
- 每个短篇强制追加审稿：能增加发现问题的机会，但违反首条快速交付决策且增加付费调用；保留现有送审策略，在 writer 和 reviewer 共享处补通用约束。
- 只记录偶发模型问题：无需增加提示，但局部要求与全局偏好在现有提示中混淆，大纲同步也缺少明确要求，因此做小范围文字修正。

## Consequences

main572 对齐 staging v3 后，真实样本仍出现明确每日发生被写成长期间歇事件、刚发现被写成祖传已知，以及角色获知关键消息前就已据此设饵。共享规则因此补清发生频率、发现时点和先获知再行动；不复制样本人物或情节，不增加自动审稿轮次。

英文样本首个 writer run 使用英文，文件保存后的同角色续跑却输出中文总结。入口语言和原始交付要求均保留，但全中文系统续跑说明被作为最新 user-role item 追加。续跑说明现明确它不是作者新消息，不能改变回复语言，最终说明仍服从作者原话的语言、长度和格式；不另做语言检测或改写已存正文。

减少核心前提被替换、返修后计划过时和局部偏好污染后续创作的风险。这是模型软约束，真实复测只证明具体样本；不能保证今后所有稿件无逻辑错误。不改变文件版本、只读边界、配额或计费。验证产物保存在外部 takeover evidence，Git 不存模型凭据或测试小说。
