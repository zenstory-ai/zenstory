# Agent Note: 普通路由历史摘要保留产物类型

## Problem

[结构化边界批次](../architecture/2026-10-14-typed-authority-and-delivery-evidence.md)引入 `requested_file_types` 并记录了一个未解决的 WATCH：结构化澄清会继承该列表，但普通重新路由的上一轮摘要只处理标量，把合法列表丢掉；反而会转发类型错误的字符串。模型因此看不到完整的前一轮产物范围。

## Decision

- 普通历史摘要保留 `requested_file_types` 列表，包括明确的空列表。词表复用 `ArtifactFileType` 的 Literal 定义，不另列字符串别名。
- 只接受词表内、唯一且长度受词表限制的字符串列表；旧历史没有该字段时保持不输出，字符串、未知值、重复值、嵌套列表等不做猜测或纠正。
- 不改变路由继承条件、权限、配额和模型调用次数。历史信息仍是模型的上下文，不是对新操作的授权。
- 回归通过实际 mock 路由请求检查发送的历史 JSON；先复现合法列表丢失和错误字符串泄漏，再修复。

## Alternatives considered

- **继续保持既有 WATCH**：改动最小，结构化澄清继承正常。但本次合并前复核已能精确复现范围信息丢失，直接补齐现有序列化分支更合适。
- **把任意列表或字符串转成列表**：兼容宽松旧数据，但把损坏或错误类型的历史变成看似有效的结构化范围，因此不采用。
- **构造完整 RouterDecision 验证历史摘要**：可以复用所有模型规则，但需要填入无关的虚拟 agent/workflow 字段，且会让一个字段的错误丢弃整个摘要，因此不采用。

## Consequences

- 普通重新路由与结构化澄清都能获得类型正确的历史产物范围，关闭原批次记录的这一项 WATCH。
- 不补建旧历史缺失字段；拒绝损坏字段不影响摘要中其他有效信息。
