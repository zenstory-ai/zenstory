# Agent Note: 无效文件标识与编辑锚点失败按恢复路径提前熔断

Status: implemented

## Problem

现有工具熔断器只把“工具名、完整参数、等价错误”都相同的失败计为连续失败。模型抄错文件标识中的一个字符后，每次枚举一个相似标识，或在同一文件上不断更换不存在的编辑锚点，都会被当成不同调用，直到一次请求累计十次失败才停止。生产对话因此出现反复读写不存在的标识、把文件不存在误说成权限故障、要求作者手工修改以“唤醒权限”，以及精确编辑连续失败十次才熔断。

## Decision

- 保留现有完整参数连续失败规则，并增加两种基于稳定 `error_type` 和结构化工具参数的恢复失败族：`edit_file` 的 `file_not_found` 跨不同标识累计；`edit_file` 的 `anchor_not_found` 按准确文件标识累计。
- 同一恢复失败族第二次失败时给模型明确恢复步骤；第三次仍失败时沿用请求级熔断终止本轮。文件不存在时禁止猜测、枚举或模糊纠正相似标识，要求从 `query_files` 当前结果逐字复制；不能确认时停止并如实说明未修改，不得归因权限。锚点失败时要求按准确标识重读当前段落、复制短且唯一的逐字锚点，不放宽匹配、不整篇覆盖。
- 成功的 `edit_file` 按目标文件清除该文件的锚点失败族，并清除文件不存在失败族。不同文件的锚点失败互不累计。现有整批原子回滚、陈旧正文、作者编辑保护和精确匹配规则不变。

## Alternatives considered

- **按字符串相似度自动纠正文件标识。** 最强理由是可以省一次查询。被否：相似标识可能属于另一个真实文件，自动纠正会把内容写错位置；文件标识必须来自当前项目的真实查询结果。
- **把所有不同参数的工具失败阈值从十次统一降到三次。** 最强理由是实现最简单。被否：正常的多文件任务可能有彼此无关的零星失败；只对程序已经确认的文件不存在与同文件锚点不存在提前收敛，误伤更小。
- **放宽模糊匹配或失败后整篇覆盖。** 最强理由是更容易让编辑落库。被否：这会绕过歧义、并发和作者手改保护，可能静默改错正文；恢复必须先重读当前内容并重新定位。

## Consequences

- 错误标识枚举与同文件锚点乱试最多三次即停止，不再消耗到请求累计十次上限；第二次失败时模型得到与失败类型对应的恢复步骤。
- 程序不猜正确标识，也不保证模型一定按提示恢复；若模型仍忽略结构化结果，会安全熔断并保留此前已成功写入。
- 同一请求确实要依次处理三个已经删除的文件时，第三个 `edit_file` 会提前停止；这类批量清理应先查询当前文件列表，只对仍存在的文件执行写操作。
- 本批不把恢复失败族扩到 `rename_file` / `delete_file`：相同参数仍按三次规则熔断，连续更换参数仍受请求累计十次上限约束。`parallel_execute` 内嵌编辑失败继续按批次失败计入现有熔断，不在本批猜测或自动修正其子任务标识。
