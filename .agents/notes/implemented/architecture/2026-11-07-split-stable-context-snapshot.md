# 项目快照只保存稳定资料

## Problem

生产快照日志与 MiniMax 写作用量账本按任务 ID 对齐后，复用快照的首轮输入命中率为 43.1%，内容变化触发重建时为 6.8%。工作集全文和章节正文占重建时新增或变化字符的约 85%。它们位于聊天历史之前，换章时会连带打断原可复用的历史前缀。

## Decision

在现有快照与本轮上下文之间重新分配资料。项目简介、写作风格、写作约定和不随焦点变化的设定继续使用快照；正文、焦点和本轮引用等资料随当前消息发送，文件清单和当前阶段独立于稳定资料。工作集使用已有的独立渲染，保留其全文、提示和读版本记录。升级快照格式，沿用现有快照重建条件和统计。

## Alternatives considered

- 提高重建阈值能用一个参数减少重建。实际重建样本里旧快照中未核对或变化的字符占比中位数为 81.4%，延迟重建会反复发送大段旧正文。
- 每轮都只发送新资料能避免过时的副本，也能简化状态管理。代价是稳定资料位于变化的历史之后，较难跨轮复用。

## Consequences

换章或更新工作集时，稳定资料与共同历史能保持字节一致。相同的动态资料在不同请求中可能需要重新按未命中计价；同一请求仍可复用该请求的前缀。旧格式快照在下一轮更新。实际缓存收益以线上首轮未命中 token 为准。
