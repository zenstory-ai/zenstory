# Agent Note: 权限、记忆确认和交付状态不再从展示文字推导

## Problem

本次字符串边界审查复现了：长否定句仍放行删除；引用文件加无关删除词放行整份删除；大纲范围标题被当成正文交付；副标题中的「第一节」覆盖第12章排序；疑问和拒绝被引文包含关系升格为作者确认；模型解释进入去AI味结果；标记占位符碰撞；异常文案触发去掉查询参数后的重试。

这些并不是正则本身的问题，而是自由文本同时充当展示、事实和操作授权。继续枚举动词、否定词、标点或展示文案不能建立可靠边界。

## Decision

- **破坏性操作**：应用内对话不能删除、递归删除或用同名剧集整份覆盖作者保存过的正文。附加、焦点、原话和上一轮提议不再授予这些权限；保护核验失败不放行；复用和递归删除在实际写锁内核验，拒绝前不改类型、排序或时间戳；流式整份落盘携带初始版本时间戳，锁内发现并发变更则拒绝。普通 `edit_file` 的读快照、陈旧写入拒绝、作者净改动提示不变。作者继续使用现有文件菜单删除、编辑器整份修改；不新增确认实体或额外 AI 消息。默认/AI 自动命名的项目仍可自动改名，作者自己的项目名由现有人工改名接口维护，模型的 `author_requested` 不开锁，Agent 与人工改名都锁定同一项目行，并在锁内读取最新名字；人工明确改名会写入 user 来源的事件，之后作者来源永久优先，即使改回旧 AI 名、默认名或台账时间戳相同也不会重新变为 AI 所有，来源读取失败不改名。
- **AI 记忆**：Agent 调用始终保留原有「作者确认」和「未标来源」条目，漏传、改写、`notes=""` 都不能删除这些条目。Agent 新增或改写的内容只进 AI 提议；引文和编号答复不再自动确认。提议区可替换/清空，4000 字总预算不变；作者直接编辑 AI 记忆文本框的 REST 保存仍可维护整个字段；来源合并在锁定并刷新的项目行上执行，与人工 PATCH 共用写入门，预算不符时所有请求字段都不写入。
- **任务证据**：任务可声明 `artifact_file_type`、实际 file ID 的 `artifact_refs`、结构化 `unit_spec`。自动收尾读取本请求确实写过、仍存在且非空、在当前项目中的 typed files；正文每个文件只证明一个编号，大纲范围不证明多章正文。没有明确类型的历史任务保持可读，但不自动完成。新的未声明类型的 done 不写任务板；非文件里程碑须明确 `task_kind=conversation`，已有文件任务不能改成对话任务绕过核验。Agent 传入的 `done_units`、`progress` 和完成引用均丢弃，由后端根据 `completed_artifact_refs` 和当前有效文件重算；自动收尾通过不在模型参数中的可信 `written_artifact_ids` 传递实际写入。阶段与任务名的二元组共同确定身份，同名不同阶段不能继承进度或完成状态。类型不明的原有已完成历史仍保留，但新的文件完成缺证据时不写任务板；失效的已核验文件进度不继续展示为完成。任务板拒绝向外返回失败/部分成功，不自动前推阶段或写成功台账。旧的文件名产物标签仅作完全同名且类型匹配的兼容输入，不作子串匹配。
- **工作流**：Router 明确输出 `requested_file_types`，只接受固定 enum；缺少或错误的类型不能触发补写大纲。需要等待作者时由 `request_clarification` 结构化事件和落库的 `clarification_pending` 控制；普通问号、条件句不能阻止计划交接或使下一轮跳过路由。问题文字仍可用于展示和转告，不作为控制信号。
- **排序**：非零显式/已存 order 优先，其次是类型兼容的 metadata 序号，其次是标题开头的序号。order 与 metadata 冲突时 order 优先；metadata 与标题冲突时 metadata 优先。0 保留为旧数据的未指定值，人工重排采用从1开始的明确排名。不迁移历史数据，不再猜尾随0是笔误，不按副标题改写排序。
- **去AI味协议**：只接受完整且无额外文字的中文/英文原改行对或精确无改动信号；不合法、半组、解释、尾随垃圾和多义原文锚点是协议失败，不降级成整段正文。既有 API 失败路径尝试退款并返回错误，不给编辑器审阅替换载荷。合法编辑的段落、引号、剧本结构和句子保留规则不变。
- **局部兼容清理**：文件标记规范化按原文本 span 拼接，不产生可碰撞的字符串占位符。query_files 只按现有执行器签名调用一次，TypeError 不改变参数或重试。后台测试徽标只保留 example.com 保留域名规则，不由用户名或邮件中的 test/qa/demo/smoke 子串猜测；明确的服务端徽标字段仍优先。

## Alternatives considered

- **增加正则、否定词窗口和异常文案别名**：改动最小且保留聊天便利性。但不能证明语义覆盖，保护和状态仍取决于措辞，因此不采用。
- **让模型自报已授权、已确认、已完成**：更能理解自然语言，但模型判断不能为自己授予破坏性权限，亦不能替代真实产物证据。仅保留模型作为非破坏性意图路由的生产者。
- **新增确认卡、签名授权记录和请求级只读模式**：可以恢复便捷的聊天确认和更明确的权限。但需要独立的交互与 wire 契约；本批已有人工入口足以消除误放，暂不新增实体。后续授权须绑定实际 action/file/version/request，不能复活文字口令。
- **禁止全部字符串解析**：可以消除表面的正则，但会破坏章节导入、格式校验和固定流协议，且用模型替代确定解析更不可靠。因此保留有边界的语法解析，不允许它增加权限或生成事实。

## Consequences

- 收益：约束与身份事实优先；不明确的证据不会静默授权、确认记忆或完成交付；删除大量只为兼容自然语言而存在的猜测代码。
- 成本：聊天不能破坏性操作作者保存的稿件或改作者项目名；对话里的记忆新增仍须作者在原有文本框明确维护确认；类型不明的旧任务不自动关闭；格式不符的模型输出会失败并走退款，而不是勉强展示。
- 本批不修改付费模型、额度、支付、上传、OAuth 或部署。完整 file-delta 事件迁移、请求级只读 UX、聊天确认卡、支付/导出文件名/版本摘要的 wire 升级另行处理，不宣称已完成。
- SQLite 的共享写入门复用既有进程内条带锁，不提供跨进程 SQLite 串行化； hosted PostgreSQL 使用真实行锁。
- 验证以最终代码、离线回归、静态检查和独立复核为准；PG/真实 staging 未执行的范围明确记录。

## Verification

- 先复现权限、记忆确认、任务证据、并发写入和协议错误，再运行相应离线回归；模型和数据库数据均为测试夹具。
- 后端受影响 Agent、API、备注、序号、去AI味及导出测试，Ruff 与 Python 编译检查；前端管理员 API 测试、ESLint、tokens、i18n keys、TypeScript 与 Vite 构建。PR 的 CI 对最终提交另行验证。
- 独立代码复核无未解决阻塞。架构复核为 WATCH：普通重新路由的历史摘要暂不序列化 `requested_file_types` 列表，结构化澄清/续接继承正常；该非阻塞上下文补充留给后续连续性批次，不宣称全架构批准。
- 本机没有独立 Python 类型检查器和获授权的临时 PostgreSQL URL；PostgreSQL 集成回归交由仓库 CI，真实 staging 与付费模型未执行。
