# 订阅页：从销售墙改为清晰的方案与用量界面

Status: rejected — 用户继续否定本稿，并明确选择恢复最初订阅页；本稿只保留探索历史，未用于产品实现。公告保持不动。

当前执行方向：[恢复最初页面](../../implemented/feature/2026-10-17-subscription-original-layout-restored.md)。

## Problem

用户看到[商业化聚焦方案的本地实现](../../implemented/feature/2026-10-17-subscription-conversion-focus.md)后，反馈「有点吃相太难看，而且设计也不好看」。这条新反馈覆盖上一版单 Pro 销售卡的视觉方向，不否定此前已验证的价格、权益、支付与公告实现。

可观察到的旧版结构是：居中双行营销标题、大字号年付总额、连续卖点、全宽含实付金额的购买按钮，免费状态与继续使用退到较弱位置。将其理解为“过度推销感”的成因是设计判断，不是转化数据或用户行为实验结论。不能把改标题和换颜色当成已经解决。

## Proposal

1. 恢复站内产品页面的角色。使用左对齐的正常页标题「订阅与用量」，显示当前方案和真实用量；不再把免费用户先送入一屏销售文案。去掉焦虑式大标题、限时暗示和重复促销词。
2. 只用一个连续的方案权益面板。免费版明确标为当前方案，Pro 是可选升级；用同一张轻量表格对照 AI 消息、项目、素材拆解、技能、历史版本。不是退回两张冗长套餐卡，也不增加档位。
3. 价格清楚但不占据主导。月付 ¥49／30 天、年付 ¥399／365 天示例沿用目录，年付折算价放辅助行；不反复突出省钱数字。保持既有年付默认和明确月付选择，不在本次视觉修订中悄悄改变计费意图。
4. 操作尊重当前方案。「继续创作」正常可见，「升级到 Pro」清晰、适度，不做整屏「支付 ¥399」按钮。升级仍先进入现有结算确认，实际总额和一次性支付宝、不自动续费规则不隐藏。
5. 兑换码继续留在页尾默认折叠的「帮助与支持」，不回到主购买区。通过位置减少干扰，而非降低可读性。用量不再完全收在底部，详细规则可渐进披露。
6. 沿用工作台主题、品牌、侧栏与手机头部。细边线、克制圆角、少量强调色、清晰正文；手机不靠小字号硬塞整张表。已付费账号继续优先有效期、用量和续费，不加入营销教育。

修订原型：`.omx/design/subscription-calm-v3/index.html`。原型数据是示例，不请求接口、不下单、不兑换权益。先用桌面／手机截图验证信息层级与可读性，再决定产品代码的修订基线；不把本轮效果图称为已实现。

## Alternatives considered

- **只缩小旧版字号或换色。** 改动最小，也能减轻部分视觉压力；但页面仍是“营销标题 → 年价 → 卖点 → 支付”，没有改变用户被推着购买的结构，因此不采用。
- **直接恢复最初管理页。** 免费状态和用量足够清楚；但当前卡、四项用量、两张套餐卡层层堆叠，价格与购买位置分离。保留其产品感，不恢复其信息重复。
- **继续单 Pro 卡，把免费入口再提亮。** 仍然容易聚焦升级；但没有直接可见的公平对照，也没有修正主界面的销售墙角色。采用连续表格而非单独促销卡。
- **删除价格或默认改月付。** 能降低第一眼的金额压力；但会把实际支出推迟到结算，或改变此前明确的购买默认。本轮不以减少透明度换取更温和的观感。

## Consequences

预期让订阅页更像可信、易比较的工作台设置，而不是必须离开的促销页面。代价是升级的视觉强度下降，不能承诺转化会上升。公告、订阅规则、真实支付流程及现有本地代码都不在这一轮设计修改中变更。

原型验收：桌面 1440×900、手机 390×844 已截图检查；320／390／768px 无横向溢出；年付默认，切月付同步金额与期限；继续创作与付款规则在手机端保持可见；周期触控区域为 44px；兑换帮助默认关闭；无脚本错误或 HTTP 请求。仅验证独立设计稿，不替代真实产品回归；既有产品文件 SHA-256 与上一轮验证记录完全一致。
