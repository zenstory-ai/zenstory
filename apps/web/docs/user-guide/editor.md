# 编辑器使用

打开项目文件后，可以直接手写、修改标题、引用选区，或审阅 AI 的修改。正文采用纯文本编辑，保存状态显示在编辑器底部。

## 保存当前文件

停止输入约三秒后会自动保存。需要立即保存时，点击“保存”或按 `Command/Ctrl + S`。

- 未保存：当前文字还未确认写入服务端。
- 正在保存：等待本次提交完成。
- 已保存或保存时间：本次标题和正文已保存。

AI 正在改同一文件、或差异审阅尚未完成时，自动保存会暂缓。先处理这一轮，再检查现稿。

正文保存后，短时间内连续的手动修改可能合并到同一历史版本；历史额度用满且无法合并时，仍会保存正文，但不新增版本。详见[版本历史](version-history.md)。

## 引用和局部改稿

选中文字后，点击“添加到对话”，或按 `Command/Ctrl + Shift + Q`。引用携带文件来源，便于 AI 定位。

```text
只检查引用的段落。人物此时还不知道失主身份。
指出越过这一信息边界的句子，并给替换建议。
保留包未交付的结果，不改其他段落。
```

想直接修改文件时，写明目标、替换范围和要保留的事实。只想看建议时，写明“只在对话中回复，不修改文件”。

选区的“去AI味”或 `Command/Ctrl + Shift + R` 会生成候选改写并进入审阅。它用于改善表达，不能保证任何检测器评分。

## 审阅差异

逐项看旧文与新文，再接受、拒绝或重置。完成审阅时，未明确拒绝的待审项会被采用；不想保留的改动要拒绝。

“全部接受”“全部拒绝”适合已确认整批方向的情况。最后完成审阅，检查组合后的正文和保存状态。部分文件操作会直接写入，不能把差异界面当作所有写入之前必经的步骤。

## 草稿恢复和保存冲突

浏览器会尝试在离开或页面更新前保留未保存草稿。重新打开同一账号、项目和文件时：

- 服务端内容未变：草稿会重新出现在编辑器中，确认后保存。
- 服务端已有新内容：页面先显示两份内容，由你选择恢复本地草稿或使用服务端版本。
- 本地存储失败：按提示把重要文字另存，不能假定草稿已保住。

保存时出现冲突，说明文件在你编辑期间更新过。先保留本地文字，再比较服务端新稿并合并。刷新和清空网站数据可能影响本地恢复，别用它们作为第一步。

## 字数

工作台按中文字符和连续英文字母统计，不计数字与标点。投稿平台可能采用不同口径，交稿前按目标平台复核。
