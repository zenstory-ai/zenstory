# 导出稿件：把正文带走，而不是备份整个项目

ZenStory 的“导出正文”把当前项目中已保存、未删除的正文与剧本文件合并为一个 TXT。它适合交稿、离线阅读和保留某一时点的正文副本，但不包含人物设定、素材、聊天与完整版本历史，不能作为整个项目的恢复包。

在 [app.zenstory.ai 工作台](https://app.zenstory.ai/dashboard)打开要导出的项目。下面沿用[第一篇短篇教程](https://zenstory.ai/docs/getting-started/first-project)的《关窗之前》，说明从保存正文到交付副本的步骤；文件名和文字是教学示例，不代表实际导出过用户作品。

## 1. 先确认要带走什么

导出按**文件类型**选择内容，不是只扫描一个叫“正文”的文件夹：

| 项目里的内容 | 当前 TXT 是否包含 |
| --- | --- |
| 未删除的正文 `draft` | 包含，即使它在其他文件夹中 |
| 未删除的剧本 `script` | 包含，适用于短剧项目及混合文件类型的项目 |
| 人物、设定、大纲、素材 | 不包含，即使标题或文件夹名字里有“正文” |
| 已删除的文件 | 不包含 |
| 尚未保存的编辑器文字、只出现在聊天里的候选段落 | 不会因为点击导出就自动变成已保存稿件 |
| 聊天、附件来源、文件历史、项目快照 | 不属于这份合并正文 TXT |

因此，把角色文件改名为“最终正文”并不会改变它的文件类型。反过来，如果你把写作备忘放进了 `draft` 文件，它也可能随正文导出。交稿前打开文件，确认类型与内容都符合用途。

## 2. 保存完成后，从项目页下载

1. 打开正确项目，保存本轮需要交付的修改。若还有 AI 写入或差异审阅，先处理完成，检查目标文件，而不是只看聊天里是否说“完成”。
2. 桌面端点击项目页顶部的下载图标，提示为“导出正文”；移动端从菜单选择“导出正文”。
3. 等浏览器完成下载，再打开文件。网络、项目内容和服务状态会影响耗时，本文不保证固定秒数。
4. 服务端建议文件名为 `{项目名称}_正文.txt`。浏览器若没有读到文件名信息，可能使用“导出.txt”等默认名称；以实际下载记录为准。

导出请求读取服务端已保存内容，不会替你点击编辑器的“保存”。也不要在导出同时继续大批量改写，再把下载文件当成那些后续修改的副本。

## 3. 章节顺序为什么会与拖拽预期不同？

当前排序使用文件排序值、标题与序号信息，并以创建时间等信息兜底。对于正文和剧本中能识别的章节型标题，例如“第1章”“第2集”“第3场”或“Chapter 4”，标题序号可决定有效顺序，**不是拖拽顺序永远优先，也不是只按创建时间**。

- 给同一作品使用一致、明确的编号；不要让两篇正文都叫“第2场”。
- 数字开头标题也可以提供序号线索，但不是任意英文标题都能自动识别；例如不能把“Scene Two”当作已承诺支持的序号格式。
- 顺序有误时先核对标题和文件位置，再重新导出查看；不要为调整导出顺序而删除项目文件。

### 一份便于交稿的例子

假设你已把两场内容分别保存为正文类型，标题是“第1场 认领”和“第2场 核对”。下载文件中的组织形态如下，正文只示意两句，不是完整故事：

```text
第1场 认领

林禾没有把灰色帆布包递过去。

---

第2场 核对

“内袋里放的什么，您再想一想。”
```

每个文件贡献标题、空行和正文，文件之间用 `---` 分隔。正文首尾空白会被清理，内部换行仍是文本的一部分；它不会自动变成带页眉、图片、字体样式的排版稿。

## 4. 只交两场，怎样不影响工作台原稿？

当前导出入口合并所有符合条件的正文和剧本，没有按勾选章节导出的这一步操作。只想发给编辑看前两场时：

1. 先下载完整正文，保留一份不改的副本，例如 `关窗之前_正文_2026-09-12.txt`。
2. 在本地另存一份 `关窗之前_前两场_送审.txt`。
3. **只在送审副本中**移除不需要的场景、创作备忘或不宜分享的信息，打开确认后再自行交付。

这两个名称是你下载后自行起的名字，不是工作台自动生成的日期归档。不要从项目里临时删除后续章节来达到“只导出前两场”，也不要覆盖唯一的完整下载稿。

## 5. 离线修改后，怎样带回工作台？

下载的 TXT 是独立副本，不会与项目双向同步。你可以在本地编辑副本；回到工作台时，先打开当前对应正文，比较它是否在这期间被你或 AI 改过，再把确定采用的段落复制到正确文件并保存。

如果只改了第二场的两句话，就只应用这两句，不要把整本合并 TXT 粘贴进一个场景文件。遇到两个版本都改过的地方，先保留两份，再按段合并；工作台不会因为文件名相同就自动识别你的离线修订。

需要查旧稿或恢复内容，见[版本历史：先比较，再选择恢复范围](https://zenstory.ai/docs/user-guide/version-history)。TXT 副本、单文件版本和项目快照是不同东西。

## 6. 下载失败、乱码或格式不符时

| 现象 | 先做什么 |
| --- | --- |
| 提示没有可导出的正文 | 查看是否存在未删除的 `draft` 或 `script`，而不是仅有大纲或聊天候选文字 |
| 提示权限、登录或套餐格式限制 | 确认账号与目标项目，按当前页面处理；重复点击不会绕过限制 |
| 按钮后没有看到文件 | 查看页面错误与浏览器下载记录；先保留未保存内容，再处理网络问题 |
| 打开后乱码 | 当前服务端输出 UTF-8 并带 BOM；在使用的软件里选择匹配编码，保留原始下载文件再尝试 |
| 需要 Word、PDF 或 EPUB | 当前这个入口输出 TXT；如需其他格式，可在自己信任的本地软件中排版或转换，不把第三方转换器当成 ZenStory 自带功能 |

TXT 不保留富文本样式和图片版式；也不保证与每个投稿平台的字数、章节分隔及上传格式要求一致。发送前至少读一下开头、章节交界与结尾，确认没有缺段、重复段或意外带出的备忘。本文不承诺未来某一版本会提供其他导出格式。
