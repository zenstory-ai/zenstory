# AI 创作助手：给对上下文，分步写作与修订

在 ZenStory 中，AI 不只是返回一段文字，也可以读取和操作项目文件。开始一轮写作前，说清目标文件、依据哪些设定、这次允许改什么，以及写到哪里停止；用文件和引用保留已经做出的创作决定，而不是只靠很长的聊天记录。

本指南适用于 [ZenStory 在线工作台](https://app.zenstory.ai/dashboard)，不是 Oh Story 的命令手册。第一次使用可先看[网页写作快速入门](https://zenstory.ai/docs/getting-started/quick-start)。下方请求沿用[第一篇短篇教程](https://zenstory.ai/docs/getting-started/first-project)的失物招领故事，是原创教学示例，不是实际 AI 运行结果。

## 1. 先选这轮任务，不要一句话包办整部小说

在项目的 AI 对话区输入要求。先区分讨论、起草和改文件：

| 现在需要什么 | 这轮交付物 | 应说明的边界 |
| --- | --- | --- |
| 还没决定情节 | 两个备选方案及各自代价 | 只在对话中讨论，未选方案不写入设定 |
| 准备开始正文 | 指定场景的草稿 | 目标文件、视角、篇幅目标、停止位置 |
| 觉得人物写偏了 | 原句与设定的对照 | 先找依据，再建议修改，不重写整章 |
| 已决定怎么改 | 指定段落的替换 | 保留哪些事实，其他文件是否允许变动 |

一个好用的请求可以包含五项：**目标、依据、确定事实、允许改动、停止点**。不必写很长，但不要把互相冲突的备选方案同时标成“必须遵守”。

## 2. AI 能看到哪些内容？

打开文件后，前端会把焦点文件的身份交给服务端；服务端据此读取该项目中已保存的文件内容，并组装相关资料。因此，它不是只看到文件名；但也不是每次都完整读取整本书、所有素材和全部历史。

文件上下文与聊天历史都有预算，内容可能经过筛选或压缩。刚改过的重要设定应先保存；关键限制也可以简短重申，避免只依赖很早以前的一句聊天。

| 输入 | 怎样提供 | 适合放什么 |
| --- | --- | --- |
| 当前焦点文件 | 在文件区打开本轮要处理的文件 | 当前场景、角色或大纲的已保存内容 |
| 项目素材 | 在素材类型条目上使用“添加到对话”入口 | 自己整理的参考笔记；不是给所有文件都加附件的统一入口 |
| 素材库条目 | 在支持的素材条目上使用“附加到对话”入口 | 与本场直接有关且你有权使用的参考信息 |
| 文本引用 | 打开文件、选中关键文字，再添加到对话 | 要改的原句，或不能违反的那条设定 |
| 其他项目文件 | 在请求里明确文件名，要求先读取；关键段落可再引用 | 角色与大纲的已确认依据，不必复制所有章节 |

当前网页中，项目素材和素材库条目共享 **5 个附件**的位置；文本引用另有 **5 段**上限。满了先移除不相关项，不要用“全部都重要”替代选择。数量上限并不保证每一项全文都进入最终请求。

角色、大纲和正文文件不一定有素材条目的同款附加按钮。找不到时，打开它并引用相关内容，或指明文件名请求读取；不要在别的文件里随意粘贴整份人设来充当附件。引用后若又改了原文，发送前检查引用是否还是你想用的版本。

## 3. 怎样让续写不提前泄露真相？

假设第一场已经写到：沈敏说错了帆布包内袋的物件，包仍未交付。林禾知道“描述不符”，却不知道为什么。先保存相关文件，打开第二场的目标正文，再发送：

```text
继续《关窗之前》的第2场，先读取《三场景提纲》《林禾》《沈敏》和第1场正文。
若有同名文件，先列出候选让我指出目标，不要猜。

已确认：沈敏描述不符；包仍在窗口；林禾不知道她报错的原因。
只写林禾提出进一步核对、沈敏回应这一段。用林禾有限视角，
通过动作和问答推进，不把“怀疑”写成“已证实撒谎”。
先在对话中给出约600个中文字的候选段落，不改文件。
写到需要做出下一步选择时停止；关键设定不足就提问，不自定真相。
```

这不是让模型保证不犯错，而是把“本轮可以决定什么”说明白。阅读结果时，先看它有没有让人物知道尚未获知的信息，再看语言是否合适。长度只是创作目标。

若满意，再明确要求把采用的段落放入哪个正文文件、替换还是追加；不要让“继续”同时承担“续写内容”和“把所有文件都保存好”两种含义。

## 4. 已经写偏了，怎样查出需要改的地方？

不要先要求“把人物写得更符合人设”。给出可核对的矛盾与材料：

```text
请对照我引用的角色设定，检查当前第2场。
只在对话中列出：问题原句、与哪条设定冲突、最小修改建议。
已确认事实：林禾只知道沈敏的物件描述不符，不知道她报错的原因。
不要新增背景，不修改文件；找不到依据的地方标“待作者决定”。
```

“给建议、不改文件”是任务要求，不是强制只读模式。Agent 的可用工具包括创建、编辑和删除文件，不能假定每次写入都会先弹确认框。发送前保存重要原稿，发送后查看实际文件与操作结果；若出现差异审阅，再逐项决定接受什么。

具体的选区引用、局部修改前后对照和差异操作，见[编辑器：只改需要改的文字](https://zenstory.ai/docs/user-guide/editor)。正文改动若真正改变了人物动机或事件结果，应另行更新相关角色与提纲，不能假定自动同步全部设定。

## 5. 长对话中，怎样接着写而不反复解释？

把已确认决定放进对应项目文件，把本轮任务留在简短的接续卡里。下面是可放入对话的交接格式，不是会自动执行的工作流文件：

```text
本轮目标：继续第2场，不写结局。
已完成：第1场已保存；包未交付。
依据：当前版《三场景提纲》《林禾》《沈敏》及第1场正文。
本轮不能改变：林禾不知道报错原因。
待决定：沈敏接下来提供什么证据，包最终归属是谁。
先做什么：读取上述文件，列出需要作者确认的一项选择；暂不写正文。
```

对话区顶部的加号“新建会话”会切换到新的活动会话并清空当前消息展示，**不会删除项目文件**，也不等于清除所有项目状态。开始前留好决定和未完成事项，开始后检查焦点文件、附件与引用列表。

旧会话不再作为当前活动会话；不要把新建会话当作撤销文件修改，也不要把旧聊天的完整检索与恢复当作写作计划的前提。换了对话，已经保存的错误设定仍应在文件里修正。

## 6. 回复中断或按了停止，下一步怎么办？

**停止生成不等于撤销。** 中断可能留下部分回复、操作记录和已经发生的文件变更；“没有看到最后一句完成提示”也不等于什么都没发生。

1. 先保留编辑器里尚未保存的重要文字，不要立即清缓存或盲目刷新。
2. 查看这轮回复、操作结果和目标文件，区分“只提出了建议”“已经写入一部分”“仍未完成”。
3. 指定恢复范围，例如：“先读当前第2场，只列出已完成与缺失部分，暂不改文件。”确认后再续写缺失段落，避免重复追加整场。
4. 如果页面提示配额或权限问题，按提示处理；反复点“继续”不能替代解决这些限制。

界面中的状态与工具结果帮助定位工作进度，不代表展示了模型的全部内部推理，也不证明文字已经达到发表标准。
