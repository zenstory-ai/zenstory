# 写作工作流

每轮结束时，保存采用的文字与决定，并记下下一轮从哪里继续。你可以按场景、整章或完整短篇推进，明确本轮目标和依据即可。

## 先决定这轮要交付什么

| 阶段 | 请求 | 结束时留下 |
| --- | --- | --- |
| 探索 | 比较少量故事方向 | 已选方案与待定问题 |
| 规划 | 整理人物目标、阻力与场景变化 | 保存的提纲和必要设定 |
| 起草 | 写指定场景或章节 | 可阅读的正文与停止位置 |
| 修订 | 对照依据修改具体问题 | 采用的改动及相关设定更新 |

人物动机尚未决定时，先解决动机；已经明确整章方向时，也不必强行拆为固定字数的小段。

## 用文件保留决定

人物、设定、大纲和正文各有位置。参考笔记与正式设定分开，待定方案标明待定。AI 记忆只留简短背景和实际进度。

发送前保存重要修改，打开目标文件，点名本轮需要读取的资料；局部问题用引用定位。不要靠一长串旧聊天保存唯一的创作决定。

## 从第1场继续第2场

《关窗之前》第1场已经写到描述不符。下一场可以继续追问物件，也可以转向认领依据。先选本场解决哪个问题，再要求正文：

```text
先读当前人物文件、三场景提纲和第1场。
第2场只推进认领依据，不揭露报错原因。
沈敏先说出包底补丁特征，林禾再核对，最后她说“包不是我的”。
用林禾有限视角，包仍留在窗口。写入《第2场 核对》，不继续第3场。
```

补丁和对白是本例新增的写作决定，需要先确认并加入提纲。描述对得上，不等于认领资格已获证实。

## 修改时先看事实，再看表达

如果一句话从“怀疑”变成“已知”，先修正信息边界，再调整节奏。只改问题段落，保留已经采用的行动和结果。

剧情方向确实改变时，再检查受影响的人物、提纲与正文；语言润色不应顺便重选结局。

## 结束时记录进度

```text
已完成：第2场已保存，补丁已核对，包未交付。
待决定：沈敏与失主的关系、报错原因、最终归属。
下一轮：先讨论第3场的选择，不写正文。
依据：人物文件、当前三场景提纲和前两场。
```

只有实际入稿并保存后才写“完成”。中断时记录停止处，先读现稿再补缺口。重要节点可以检查历史，完成后导出一份正文副本。
