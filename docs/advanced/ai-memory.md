# AI 记忆与上下文：分清设定、进度和待定想法

> 仓库文档快照（2026-09-13）。[当前官网指南](https://zenstory.ai/docs/advanced/ai-memory)以网页工作台文档为准；本页正文复用[此版本的官网内容源](https://github.com/zenstory-ai/zenstory/blob/1773af4781996363496f47268cce0e7c640108c8/apps/web/docs/advanced/ai-memory.md)，保留可在仓库中直接阅读的说明与示例。此日期只说明本页所用版本，不表示其他仓库文档已同步。

ZenStory 的 **AI 记忆是一份可编辑的项目摘要**，不是已经读完整本书的证明，也不保证人物永远不写偏。它保存项目简介、写作风格、当前阶段和备注四项，供聊天上下文组装使用；具体人物、提纲和正文仍应保存在相应文件中，本轮需要什么就明确指出。

本指南适用于 [ZenStory 在线工作台](https://app.zenstory.ai/dashboard)，不是 Oh Story 的状态追踪文件或 DSH 插件说明。第一次使用可先读[网页快速入门](https://zenstory.ai/docs/getting-started/quick-start)。

## 1. 哪些内容放记忆，哪些留在文件里？

| 内容 | 适合放哪里 | 不要混成什么 |
| --- | --- | --- |
| 稳定的题材、视角和重要限制 | AI 记忆里的简短摘要；详细依据留在设定文件 | “写过一遍，AI 就一定永远记得” |
| 人物背景、能力边界、完整提纲 | 对应人物、设定和大纲文件 | 四个记忆字段已自动收齐所有文件 |
| 正文中已经发生的事 | 正文文件；当前阶段简要记录已写到哪里 | 下一场打算发生的事已经完成 |
| 还没选的动机、身份或结局 | 构思文件或带“待定”标记的备注 | 已确认设定，或人物已经知道的事实 |
| 只针对这一轮的修改要求 | 当前消息、引用与目标文件 | 长期改变整个项目的写作风格 |
| 对话中讨论过的内容 | 聊天记录；采用后再归入对应文件或摘要 | 每条建议都已进入永久记忆 |

新建会话与修改项目记忆是不同操作。不要用换会话来“清掉”保存错误的设定，也不要依赖旧聊天的完整恢复来继续写作。焦点文件、附件、引用和会话交接的具体区别，见 [AI 创作助手](https://zenstory.ai/docs/user-guide/ai-assistant)。

## 2. 打开、修改并保存

1. 在项目编辑页的聊天标题栏，点击提示为“AI 记忆”的数据库图标。
2. 查看四个字段，修改本次需要更新的部分。
3. 点击“保存”。保存成功后对话框关闭；若提示失败，先保留输入并处理提示，不把关闭面板当成已保存的证据。
4. 重要更正后可重新打开，确认实际保存的内容。点“取消”不是提交修改，也不要依赖未保存退出时一定有额外警告。

这里只需要用“保存”。如果看到分享灵感等其他入口，它们不是保存记忆的必要步骤。

| 字段 | 建议内容 | 当前源码的保存上限 |
| --- | --- | --- |
| 项目简介 `summary` | 类型、核心处境、主视角和少量已确认限制 | 4000 字符 |
| 写作风格 `writing_style` | 希望保持的表达特征与不想要的写法 | 1000 字符 |
| 当前阶段 `current_phase` | 已保存到哪里、本轮目标、尚未完成什么 | 1000 字符 |
| 备注 `notes` | 易混淆事实、必要文件名、明确标记的待定问题 | 4000 字符 |

这些是保存上限，不是推荐写满的长度，也不是 token 数或“全文都会被模型读到”的承诺。上下文有预算，项目简介与备注的长文本可能被裁剪。先放最关键的限制，长人物卡和章节记录留在文件里；本轮关键段落可以再引用。

手动输入需要保存，但 **Agent 也有更新项目记忆的工具**。不能把“我没有按这个面板的保存键”理解成 AI 不可能更新过记忆，也不要假定每次工具更新都会先弹出逐项批准框。要求先给建议，是任务边界，不是强制只读权限。

## 3. 原创例子：第1场写完，不等于结局已经发生

下面沿用[第一篇短篇教程](https://zenstory.ai/docs/getting-started/first-project)的《关窗之前》，是假设作者已保存第1场后的填写练习，**不是实际账号、模型输出或系统自动生成的记忆**。

已知条件：林禾负责车站失物招领窗口，沈敏来认领灰色帆布包。她说对外观，却说错内袋物件。第1场已写到这个分歧；包尚未交付，林禾不知道报错原因。作者也还没决定原因、沈敏与失主的关系和最终归属。故事采用林禾有限视角，不能仅凭口头认领交包。

**不应保存的进度摘要：**

> 林禾识破沈敏是骗子，已经把包交给真正失主。接下来写沈敏后悔。

它把待定身份说成事实，把尚未发生的交付写成完成，还替另一个人物决定了内心。把这段错误摘要反复喂给 AI，不会让续写更可靠。

**更合适的四字段草稿：**

```text
项目简介：现实题材短篇《关窗之前》，采用林禾有限视角。
车站失物招领窗口六点关闭，开场五点四十分。
林禾不能仅凭口头认领交付灰色帆布包。

写作风格：通过问答与可见动作推进；允许必要的心理描写，
但不越过林禾当前能知道的信息，不替其他人物解释内心。

当前阶段：第1场已保存到“内袋物件描述不符”；包尚未交付。
本轮只讨论第2场的进一步核对，不写结局；第2场尚未完成。

备注：[待作者决定] 报错原因、沈敏与失主的关系、包的最终归属。
[续写边界] 描述不符不等于已经证实撒谎。
[依据文件] 《林禾》《沈敏》《三场景提纲》与第1场正文。
```

方括号只是作者自己选的文字标记，不是系统识别的特殊字段。文件名也不是“填进去就自动读取”的指令；写第2场时仍应明确要求先读这些文件，必要时引用关键内容。

这个摘要保留了有用的短期入口，却不试图装下全篇。以后作者若确定新动机，应先记录为作者决定，再安排人物何时得知；“作者已经决定”仍不等于“林禾已经知道”。

## 4. 已经记错了，怎样更正而不重写故事？

先找依据，再决定改哪一层。记忆摘要错了，不代表正文也错；正文改了，也不能假定所有人设、提纲和摘要已经同步更新。

可先提出这样一轮请求：

```text
先读取《林禾》《沈敏》《三场景提纲》和第1场已保存正文。
若同名文件不止一个，先列出候选，不猜目标。
对照当前 AI 记忆，只列：不一致的原句、文件依据、建议替换文字。

已确认：第1场止于描述不符，包未交付；林禾不知道报错原因。
先在对话中给出四字段修改草稿，不更新记忆、不修改文件。
未决身份与动机保留待定，不替我选择结局，也不顺便写第2场。
```

读过建议后，你可以自己在面板中改并保存；如果明确让 Agent 写入，只点名要改的字段和采用的文字。发送后查看实际记忆与相关文件，不能只凭“已记住”三个字判断完成。

若作者同时改变了情节方向，分别决定哪些人物设定、提纲和正文需要改，另开有范围的修订任务。别把一次摘要更正变成整本书的静默重写。

## 5. 怎样更新而不越积越乱？

- **确定设定后**：保留简短结论及相关文件名，移除已放弃的备选，别把“可能”悄悄改成“已经”。
- **保存一场正文后**：更新实际进度和出口状态；“打算下一场交包”仍是计划，不是当前持物状态。
- **换会话前**：留下已完成、待决定和下一项任务；新会话再确认目标文件与引用。
- **发现写偏后**：查是哪份依据过时，修正确实错误的那一处，不盲目让所有文件互相覆盖。

不必按固定几章或每周填满一次。真正有决定、进度或依据变化时再维护，比把所有聊天复制进备注更有用。填进记忆的内容可能进入 AI 上下文；它不是用来对模型隐藏信息的私密便笺。

## 常见问题

### 有记忆，为什么还会写错人设？

摘要可能过时、遗漏或与文件冲突；上下文可能受预算影响，模型也可能理解错。先检查本轮使用的已保存依据和关键句，不要把“再强调一次永远不能错”当作一致性机制。[长篇连续性指南](https://zenstory.ai/oh-story/long-novel-continuity)中的作者真相、人物已知和读者已知区分可以借鉴，但 Oh Story 的追踪文件不等于网页工作台自动具备的功能。

### 让 AI “记住”一句话，就保存成功了吗？

不一定。可能只是聊天回复，也可能发生了项目状态更新。看工具结果并打开记忆确认；重要的正式设定同时应有清楚的项目文件依据。

### 导出 TXT，会一起备份记忆吗？

不能这样理解。当前稿件导出面向正文与剧本，不是包含四字段、素材、聊天和历史的完整项目备份。需要独立保留这份摘要时，复制四字段到自己的文档；恢复方式另看[版本历史](https://zenstory.ai/docs/user-guide/version-history)与[稿件导出](https://zenstory.ai/docs/user-guide/export)，不要承诺它们能恢复任意一轮记忆修改。
