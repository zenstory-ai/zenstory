## A: architecture decisions and established KEEP

KEEP direct local state until a demonstrated shared contract needs extraction. A 1,577-line SkillsPage includes local cards/forms, but splitting pure rendering is optional clarity work; replacing fetch/state with a framework is not justified by this map. Existing request counters already solve public list and resource A→B selection; reuse them for a proven boundary rather than invent global generations.

KEEP owner checks, approved visibility, added-link aliases/uniqueness, atomic quota reservation, locked resource accounting, share resource copy + source link transaction, parser bounds/safe YAML/NFC, raw review disclosure and atomic decision/reward/audit. Relevant anchors: `services/quota_service.py:141,161`; `skill_package_service.py:363,443`; `api/skills.py:605,614`; `api/admin/skills.py:149`; `services/features/points_service.py:650`. Existing approvals are not rediscovered as old defects.

Package parser (`agent/skills/package.py`) accepts standard/legacy Markdown without losing fenced content; limits zip/upload entries/decompressed bytes/frontmatter depth/nodes/resources; rejects traversal/symlinks/duplicate normalized paths/non-UTF8 resource content/YAML aliases/unsupported types. Resources stay textual DB values. There is no source-grounded need for another parser/sanitizer or new abstraction.

Small optional simplification: correct wrapper documentation describing legacy prompt_template/variables and public-add “copy” (`lib/api.ts:1387,1707`) to actual instructions/links. This is clarity, not a runtime defect or authorized edit.
