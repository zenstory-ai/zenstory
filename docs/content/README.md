# 创作指南编辑规则

目标是 2000 篇独立、可用的创作文章。`guides.json` 和 `articles.json` 中的一条内容算一篇；中英文版本不重复计数。当前修订完成后为 170 篇，后续逐批补充，每批通过检查后 PR 并合并。

文章面向作者与内容创作者。题目用他们实际会问的话：怎么写开头、怎么做大纲、对白为什么生硬、AI 视频角色怎么保持一致。优先解决常见任务和明确问题，不为数量扩展到 skill 没有方法的领域，不把内部字段、流程标签和新造的词当选题。

一篇合格文章要能让读者开始做：开头直接回答问题；正文提供有取舍的具体方法；有按本题填写的模板、原创场景或改前改后对照；写清常见失败怎样修；链接到确实存在的 skill 与相关方法文件。案例不冒充真实用户成绩，方法的数字默认值不写成所有题材的硬规则。

补充前检查已有目录和 [逐篇修订记录](2026-09-29-guide-review.csv)。同一问题的不同说法合并到主文章；新文章必须有新的读者问题和实际方法。不要用“题材 × 技法”排列组合批量扩写，也不要把三个通用段落当完整教程。站内来源与方法不能用泛用项目说明替代。

`skill.url` 指向固定提交的真实 `SKILL.md` 文件。不同仓库的目录结构不同，DSH 的打包技能在 `packages/knowledge/.../skills/`。`sources[]` 提供正文所用的具体方法文件。提交前对所引用提交运行 `git cat-file -e COMMIT:PATH`；链接校验是来源存在性检查，文章的方法是否对应来源仍需编辑判断。

文章在九个常用任务分类中只选一个主类，使用 `topic` 字段。首页展示精选，`/guides` 提供学习路径与搜索，分类页每页 24 篇。文章量增长时增加分页，不增加首页列表长度。更新目录运行 `node apps/web/scripts/update-guide-directory.mjs`。

同题合并记录在 `guide-redirects.json`，生成中英文永久重定向；撤下的非同题文章不跳到无关页面。修改映射后运行 `node apps/web/scripts/build-site-layout.mjs --write-config`。

验证运行 `cd apps/web && npm run test:site && npm run build:vercel`。涉及布局或搜索时，检查 390px 溢出、键盘搜索、无脚本分类分页和 axe。测试与可访问来源不替代作者视角的内容审读。
